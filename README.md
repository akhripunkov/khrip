# Khrip

> **K**eep **H**ardware **R**unning **I**n **P**arallel

Компилируемый язык для HTTP API под Linux x86-64. Цели, сравнение с Go и C#:

1. **ИИ пишет код на Khrip быстрее и дешевле** — меньше токенов при сравнимом
   результате на основных задачах, на любой доступной модели. Это главная цель.
2. **Многопоточность и веб-серверы** лучше.
3. **Скорость вычислений** выше.
4. **Память** — лучшая или близкая к лучшей.
5. **Быстрый запуск.**
6. **Небольшой размер приложения.**

Каждая цель проверяется замером, а не заявлением ([docs/DESIGN.md](docs/DESIGN.md)).

| | |
|---|---|
| Компилятор | `khc` |
| Исходники | `.kh` |
| Платформа | Linux x86-64, статический ELF без libc |
| Статус | **v0.2**: компилятор собирает сам себя, первый HTTP-сервер на Khrip |

## Сборка из исходников

Нужны только `nasm` и `ld`: никаких Go, C или других компиляторов.

```
./build.sh       # зерно на ассемблере → khc → khc собирает сам себя
tests/run.sh     # тесты
```

Компилятор `khc` написан на Khrip ([src/khc.kh](src/khc.kh), ~1600 строк). Первый раз его
собирает зерно на ассемблере x86-64 ([bootstrap/khc0.asm](bootstrap/khc0.asm)), дальше он
собирает себя сам. Два последних поколения совпадают побайтно. Самокомпиляция занимает
около 4 мс, компилятор весит 38 КБ.

```khrip
fn main() -> i64 {
    println("Hello, Khrip!")
    return 0
}
```

```
build/khc -o hello lib/std.kh hello.kh && ./hello
```

Сейчас язык — минимальное подмножество [Khrip-0](docs/KHRIP0.md): целые числа, функции,
циклы, строки, системные вызовы Linux.

## Каким будет API

```khrip
type User {
    id: int
    name: str
}

store users: map[int, User]

route GET "/users/{id}" (id: int) -> User | 404 {
    return users[id] ?? 404
}
```

Маршрутизацию, проверку входных данных, JSON и описание OpenAPI компилятор генерирует
сам из объявления `route` и типов. Почему синтаксис именно такой — критерии языка для ИИ
с замерами в [docs/CRITERIA.md](docs/CRITERIA.md). Дизайн — [docs/DESIGN.md](docs/DESIGN.md),
план — [docs/ROADMAP.md](docs/ROADMAP.md).

## Где мы сейчас (v0.2)

Сервер на 2 ядрах, нагрузка `wrk` с двух других ядер, 128 соединений
([полный отчёт](bench/results/2026-10-19-v0.2.md)):

| | plaintext RPS | json RPS | p99, мс | Память | Размер | Старт |
|---|---:|---:|---:|---:|---:|---:|
| **Khrip v0.2 (1 поток)** | **114 368** | **117 815** | 6.5 / 10.6 | **1,1 МБ** | **25 КБ** | **10 мс** |
| Go 1.24 net/http | 79 584 | 76 781 | 6.6 / 6.4 | 14,7 МБ | 8 МБ | 16 мс |
| C# .NET 10 (JIT) | 116 176 | 114 888 | **3.6 / 3.4** | 96,5 МБ | +среда .NET | 418 мс |
| C# .NET 10 (Native AOT) | 110 158 | 108 080 | 4.8 / 4.3 | 43,3 МБ | 9 МБ | 38 мс |

Один поток Khrip держит столько же, сколько C# на двух ядрах, и в 1,5 раза больше Go,
занимая в 13 раз меньше памяти, чем Go. Где проигрываем:

- **p99** выше, чем у C#: один поток иногда задерживает очередь. Лечится многопоточностью (v0.5).
- **Вычисления** в 1,65–1,7 раза медленнее Go (fib 321 мс против 194, решето 217 против 126):
  генератор кода пока гоняет каждое значение через стек. Лечится на шаге v0.7.
- **Токены:** код сервера — 169 токенов против 191 у Go и 133 у C# (o200k). Лечится
  объявлениями `route` (v0.4).

(нужны Go, .NET SDK 10, `wrk`, Node.js). Эталонный замер v0.0 —
[bench/results/2026-10-19.md](bench/results/2026-10-19.md).
