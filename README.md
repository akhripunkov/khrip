# Khrip

> **K**eep **H**ardware **R**unning **I**n **P**arallel

Компилируемый язык для HTTP API под Linux x86-64. Цели, сравнение с Go и C#:

1. **ИИ пишет код на Khrip быстрее и дешевле** — меньше токенов при сравнимом
   результате на основных задачах, на любой доступной модели. Это главная цель.
2. **Многопоточность и веб-серверы** лучше.
3. **Скорость вычислений** выше.
4. **Память** — лучшая или близкая к лучшей.
5. **Быстрый запуск.**
6. **Небольшой размер приложения.**

Каждая цель проверяется замером, а не заявлением ([docs/DESIGN.md](docs/DESIGN.md)).

| | |
|---|---|
| Компилятор | `khc`, написан на Khrip и собирает сам себя |
| Исходники | `.kh` |
| Платформа | Linux x86-64, статический ELF без libc |
| Статус | **v0.13**: сборка мусора в `store`, строки UTF-8, ClickHouse в языке (`ch "..."`, `table`) и драйвер MongoDB, анонимные типы, скилл для агентов; PostgreSQL (`sql` с проверкой при компиляции, `tx`, миграции, свой клиент протокола), строгие типы, `float`, варианты и `match`, лямбды, `route`/`store`/`test`, `fetch` со своим TLS 1.3, `every`, заголовки и `fail`, пароли, время, регулярные выражения, многопоточный сервер на сопрограммах, SIMD |
| Описание языка | [skill/khrip/](skill/khrip/SKILL.md) — скилл для агентов: ядро до 3000 токенов o200k и главы по задаче до 900; [docs/KHRIP.md](docs/KHRIP.md) — полный справочник |

Кроме PostgreSQL — **ClickHouse и MongoDB**. ClickHouse встроен в язык, как
`sql`: `ch "..."`, таблицы `table`, вставка по типам столбцов, миграции,
проверка каждого запроса при запуске. MongoDB — библиотечный драйвер: BSON,
типизированные `to_bson`/`from_bson`, пакетные операции, курсоры,
переиспользование соединений и тайм-ауты. Оба — без libc и внешних библиотек,
свой протокол и TLS. Возможности, ограничения и запускаемые примеры —
[docs/DATABASES.md](docs/DATABASES.md); проверки идут на настоящих серверах, есть
сценарий изолированного запуска в Docker.

## Как выглядит API

```khrip
type Role = Admin | Member

type NewUser { name: str, email: str, age: int, role: Role = Member }

type User { id: int, ...NewUser }

store users: map[int, User]
store last_id: int

route POST "/users" (body: NewUser) -> 201 User | 400 str {
    if !body.email.matches(`[^@\s]+@[^@\s]+`) {
        return 400 "email is invalid"
    }
    last_id += 1
    let user = User { id: last_id, ...body }
    users[user.id] = user
    return 201 user
}

route GET "/users/{id}" (id: int) -> User | 404 {
    return users[id] ?? 404
}

route GET "/users" (role: Role?, min_age: int?, page: int = 1) -> [User] {
    let found = users.values()
        .filter(u => role == none || u.role == role)
        .filter(u => min_age == none || u.age >= min_age)
        .sort_by(u => u.name)
    return found[(page - 1) * 20..page * 20]
}

test "create and read" {
    let r = call POST "/users" NewUser { name: "Ann", email: "ann@x.io", age: 30 }
    expect r.status == 201
    expect (call GET "/users/1").status == 200
}
```

```
build/khc run users.kh       # сервер на :8080 (PORT, THREADS)
build/khc test users.kh      # блоки test
build/khc check users.kh     # все ошибки сразу, с подсказками (--json для агентов)
build/khc -o users users.kh  # статический бинарник ~210 КБ
```

Разбор параметров пути, строки запроса и JSON-тела, проверку ввода (400 с понятным
текстом), коды ответов и JSON компилятор выводит из объявления `route` и типов.
Заголовки — `header("X-API-Key")`, `set_header(...)`; прервать запрос из любой
функции — `fail(401)`; пароли — `hash_password`/`check_password`, время —
`time_iso`/`parse_time`, проверка формата — `` s.matches(`[A-Z0-9-]{3,20}`) ``.
Внешние сервисы — `fetch GET url`, фоновые задачи — `every 10 min { ... }`,
сохранение данных между перезапусками — `KHRIP_DATA=файл`. Пример целиком —
[погодный бэкенд с уведомлениями](examples/weather/weather.kh): погода по городу,
подписки с порогами, проверка каждые 10 минут, вебхук (подходит и Telegram).
Каждый запрос выполняется в своей арене памяти; данные `store` переживают запрос и
доступны обработчикам так, будто запросы идут по одному; заменённые и удалённые
значения `store` освобождает сборщик мусора, который не останавливает читающие
запросы. Паника в обработчике — 500, сервер работает дальше.

| Переменная | Что задаёт |
|---|---|
| `PORT` | порт сервера (8080) |
| `THREADS` | рабочих потоков (по числу ядер, не больше 4000) |
| `KHRIP_DATA` | файл JSON, в котором `store` переживает перезапуск: загружается при старте, сохраняется раз в секунду, если `store` менялся, и при SIGTERM/SIGINT |
| `KHRIP_COROUTINES` | ждущих запросов на поток (4096), дальше — очередь |
| `KHRIP_GC` | запас кучи `store` над живыми данными, % (50); `off` — без сборки |
| `KHRIP_GC_MIN_MB` | наименьшая цель сборки, МБ (4) |
| `KHRIP_GC_LIMIT_MB` | мягкий предел кучи `store`, МБ (нет): цель не выше него, но не ниже 1,1 живого |
| `KHRIP_GC_LOG` | `1` — строка о каждой сборке в stderr; программу тоже нужно собрать с `KHRIP_GC_LOG=1` |
| `SSL_CERT_FILE` | корневые сертификаты для https (иначе — системные) |
| `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` | прокси для `fetch` |

Переменные PostgreSQL — ниже, ClickHouse — в [docs/DATABASES.md](docs/DATABASES.md);
настройки разработчика (проверки и частая сборка) — в
[docs/DESIGN.md](docs/DESIGN.md).

## Скилл для агентов

[skill/khrip/](skill/khrip/SKILL.md) учит языку нейросеть, которая пишет код: ядро
`SKILL.md` (типы, операторы, значения, маршруты, тесты, ловушки привычек Python,
TypeScript и Go) и главы, которые агент читает сам, когда они нужны задаче:
`postgresql.md`, `mongodb.md`, `clickhouse.md`, `production.md`. Это сжатая
форма [docs/KHRIP.md](docs/KHRIP.md); ключевые правила скилла и все его примеры
набор тестов сверяет с компилятором, а бюджеты токенов — с токенизатором.

Папка в формате agent skills (`SKILL.md` с полями `name` и `description`):
положите её в каталог скиллов агента — например, в `.claude/skills/khrip` проекта
или в `~/.claude/skills/khrip` — и агент возьмёт ядро, как только
займётся кодом на Khrip. Агенту без скиллов дайте `SKILL.md` системным промптом,
а главы — по его просьбе; так работает слепая проверка
([eval/PROMPT.md](eval/PROMPT.md)). Ошибки компилятора агенту удобнее читать в
`khc check --json`.

## PostgreSQL

```khrip
migration 1 `
CREATE TABLE accounts (id bigserial PRIMARY KEY, owner text NOT NULL,
    balance bigint NOT NULL DEFAULT 0 CHECK (balance >= 0));
`
type Account { id: int, owner: str, balance: int }
type Transfer { from: int, to: int, amount: int }

route GET "/accounts/{id}" (id: int) -> Account | 404 {
    return sql "SELECT * FROM accounts WHERE id = {id}"      // нет строки — 404
}

route POST "/transfers" (body: Transfer) -> 204 | 404 | 409 str {
    tx {                                                      // SERIALIZABLE, повтор при конфликте
        let from: Account = sql `SELECT * FROM accounts WHERE id = {body.from}`
        if from.balance < body.amount {
            return 409 "insufficient funds"                   // откат
        }
        sql "UPDATE accounts SET balance = balance - {body.amount} WHERE id = {body.from}"
        sql "UPDATE accounts SET balance = balance + {body.amount} WHERE id = {body.to}"
    }
    return 204
}
```

SQL пишется как есть, `{x}` уходит параметром (собрать текст запроса из строки
времени выполнения нельзя — инъекции нет по построению), тип результата задаёт
ожидаемый тип: `T` — одна строка или 404, `T?` — одна или ни одной, `[T]` — все.
Компилятор ловит привычки других драйверов и диалектов (`$1`, `BEGIN`,
`INSERT IGNORE`, `IFNULL`...; `?` — только на месте значения перед `)`, `,` или
в конце, как в `id = ?` и `IN (?, ?)`: в PostgreSQL `?`, `?|` и `?&` — ещё и
операторы jsonb), запись после чтения вне `tx`, неизвестные таблицы и столбцы по
миграциям; сервер при запуске готовит каждый запрос на настоящей базе и сверяет
типы — и не запускается, если что-то не сходится (так отвергается и
`id = ? AND ...`). Свой клиент протокола: без libpq, SCRAM, TLS через свой
TLS 1.3, пул соединений на сопрограммах.

| Переменная | Что задаёт |
|---|---|
| `DATABASE_URL` | `postgres://user:password@host:5432/db?sslmode=…` (`disable`, `prefer` — по умолчанию, `require`, `verify-ca`, `verify-full`; `sslrootcert=system` — корни системы) |
| `DATABASE_POOL` | соединений на процесс; по умолчанию 4 на поток, не больше 32 |
| `DATABASE_TIMEOUT` | мс на запрос или блок `tx` вместе с ожиданием соединения и повторами (10000); дальше — CancelRequest и 503 |
| `DATABASE_MIGRATE` | `apply` — миграции при запуске (по умолчанию); `check` — только проверить, применяет отдельный шаг `./app migrate` |
| `KHRIP_TEST_DATABASE_URL` | база для `khc test` (иначе `DATABASE_URL`); тесты работают во временной схеме и удаляют её |

| Ошибка базы | Ответ |
|---|---|
| дубликат (23505), нарушение CHECK | 409 |
| нет строки, на которую ссылается внешний ключ | 404; на строку ещё ссылаются — 409 |
| NOT NULL, неверное значение (22xxx) | 400 |
| база недоступна, перегружена, тайм-аут | 503 и `Retry-After` |
| связь пропала во время COMMIT | 500 «transaction outcome unknown» |
| остальное | 500; текст запроса — в журнал, не клиенту |

| PostgreSQL | Khrip |
|---|---|
| `smallint`, `integer`, `bigint`, `numeric` без дробной части | `int` |
| `real`, `double precision`, `numeric` | `float` |
| `text`, `varchar`, `uuid`, `citext` и другие | `str` |
| `boolean` | `bool` |
| `timestamptz`, `timestamp`, `date` | `str` (как `time_iso`) или `int` (секунды Unix) |
| `json`, `jsonb` | любой тип |
| массивы | `[T]` |
| свой `ENUM` | вариант `type Role = Admin \| Member` или `str` |
| столбец без NOT NULL | `T?` |

## Где мы сейчас (v0.13)

**Память** (этап памяти v0.13: одна и та же постоянная частота запросов для всех
языков, `wrk2 -R`; [точка отсчёта](bench/results/2026-10-26-memory-baseline.md),
[часть 3](bench/results/2026-10-28-memory-part3.md)). Заменённые и удалённые
значения `store` теперь освобождает сборщик мусора:

| | Khrip | Go |
|---|---:|---:|
| patch (постоянные обновления, 26 000 запросов в секунду), пик RSS, МБ | **4,4** | 14,6 |
| пиковая память в 13 сценариях eval, доля от Go | **0,14–0,82** | 1 |
| 10 минут при одинаковой частоте (bank, inventory, shortener, notes, polls), пик от Go | **0,26–0,46** | 1 |
| смена фазы (2 млн записей, затем замены), пик от Go | **0,62** | 1 |
| живые данные на запись, от Go | 0,76–1,26 | 1 |
| молчащее соединение, КБ | **0,2** | 22 |

В замкнутом цикле (`eval/perf.sh`, без постоянной частоты) patch у v0.12 доходил
до 232 МБ ([промежуточный замер](bench/results/2026-10-25-v0.13-interim.md)), у
v0.13 — 4,3–4,4 МБ.

Паузы сборщика короткие: при 134 МБ живого начало сборки — 4–6 мкс, разметка
идёт кусками примерно по 0,2 мс под мьютексом писателей (самый долгий кусок в
замере — 229–253 мкс процессора), а читающие запросы её не ждут.

**Скорость** ([отчёт этапа](bench/results/2026-10-28-speed-part2.md)): поиск по

| | Khrip | Python FastAPI | C# | Go |
|---|---:|---:|---:|---:|
| 5 задач, на которых язык дорабатывался | **2645** | 3168 | 3270 | 5079 |
| 3 отложенные задачи, язык заморожен | 2431 | **2186** | 2427 | 3425 |
| те же 3 после добавления `parse_time` | **1944** | 2186 | 2427 | 3425 |

Честно: на задачах, которых язык «не видел», Khrip оказался вровень с C# и
хуже Python — не хватило разбора дат. Преимущество над Go устойчивое (×1,4–1,9),
над Python и C# — 10–25% и только там, где нужное есть в языке. Все решения
написал тот же ИИ, что и язык, поэтому это не независимая оценка; протокол
слепой проверки на других моделях — [eval/README.md](eval/README.md#протокол-слепой-проверки).

**Вычисления** (`bench/compute`, одно ядро): решето Эратосфена — 150 мс против 142
у Go и 144 у C# AOT; fib(38) — 286 мс против 207 у Go и 203 у C# AOT: вызов функции
пока дороже.

**SIMD** (`bench/simd`): разбор заголовков браузерного запроса — 134 нс против 816
побайтно, запись JSON — в 5,9 раза быстрее, чтение — в 3,5 раза.

## Сборка из исходников

Нужны только `nasm` и `ld`: никаких Go, C или других компиляторов.

```
./build.sh       # зерно на ассемблере → загрузчик → khc → khc собирает сам себя
tests/run.sh     # 708 тестов: программы, ошибки, блоки test, сборщик store, HTTP, сопрограммы, TLS, PostgreSQL, MongoDB, ClickHouse, погода, задачи eval, скилл
eval/perf.sh     # нагрузочный замер решений на Khrip, Go, C# и Python (нужны wrk, Go, .NET, FastAPI; для задач на базе — PostgreSQL)
```

Цепочка раскрутки: зерно на ассемблере [bootstrap/khc0.asm](bootstrap/khc0.asm)
понимает начальное подмножество [Khrip-0](docs/KHRIP0.md); на нём написан загрузчик
[bootstrap/boot.kh](bootstrap/boot.kh), который понимает часть Khrip-1 и собирает
настоящий компилятор [src/](src) (~24 000 строк на Khrip). Дальше `khc` собирает себя
сам; два последних поколения совпадают побайтно. Самокомпиляция — ~0,1 с.

С `KHRIP_GC_VERIFY=1` набор идёт с проверками сборщика `store` во всех
программах (граф `store` и куча после каждого пишущего запроса и каждой сборки),
с `KHRIP_GC_STRESS=1` — ещё и с очень частой сборкой (каждые 64 КБ выделений в
`store`);
тесты MongoDB и ClickHouse ходят на настоящие серверы, если заданы `MONGODB_URI`
и `CLICKHOUSE_URL` (иначе — строки SKIP).
