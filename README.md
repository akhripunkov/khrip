# Khrip

> **K**eep **H**ardware **R**unning **I**n **P**arallel

Компилируемый язык для HTTP API под Linux x86-64. Цели, сравнение с Go и C#:

1. **ИИ пишет код на Khrip быстрее и дешевле** — меньше токенов при сравнимом
   результате на основных задачах, на любой доступной модели. Это главная цель.
2. **Многопоточность и веб-серверы** лучше.
3. **Скорость вычислений** выше.
4. **Память** — лучшая или близкая к лучшей.
5. **Быстрый запуск.**
6. **Небольшой размер приложения.**

Каждая цель проверяется замером, а не заявлением ([docs/DESIGN.md](docs/DESIGN.md)).

| | |
|---|---|
| Компилятор | `khc`, написан на Khrip и собирает сам себя |
| Исходники | `.kh` |
| Платформа | Linux x86-64, статический ELF без libc |
| Статус | **v0.9**: строгие типы, `float`, варианты и `match`, лямбды, `route`/`store`/`test`, `fetch`, `every`, заголовки и `fail`, пароли, время, регулярные выражения, многопоточный сервер, SIMD |
| Спецификация для нейросетей | [docs/KHRIP.md](docs/KHRIP.md) — ~2900 токенов |

## Как выглядит API

```khrip
type Role = Admin | Member

type NewUser { name: str, email: str, age: int, role: Role = Member }

type User { id: int, ...NewUser }

store users: map[int, User]
store last_id: int

route POST "/users" (body: NewUser) -> 201 User | 400 str {
    if !body.email.matches(`[^@\s]+@[^@\s]+`) {
        return 400 "email is invalid"
    }
    last_id += 1
    let user = User { id: last_id, ...body }
    users[user.id] = user
    return 201 user
}

route GET "/users/{id}" (id: int) -> User | 404 {
    return users[id] ?? 404
}

route GET "/users" (role: Role?, min_age: int?, page: int = 1) -> [User] {
    let found = users.values()
        .filter(u => role == none || u.role == role)
        .filter(u => min_age == none || u.age >= min_age)
        .sort_by(u => u.name)
    return found[(page - 1) * 20..page * 20]
}

test "create and read" {
    let r = call POST "/users" NewUser { name: "Ann", email: "ann@x.io", age: 30 }
    expect r.status == 201
    expect (call GET "/users/1").status == 200
}
```

```
build/khc run users.kh       # сервер на :8080 (PORT, THREADS)
build/khc test users.kh      # блоки test
build/khc check users.kh     # все ошибки сразу, с подсказками (--json для агентов)
build/khc -o users users.kh  # статический бинарник ~140 КБ
```

Разбор параметров пути, строки запроса и JSON-тела, проверку ввода (400 с понятным
текстом), коды ответов и JSON компилятор выводит из объявления `route` и типов.
Заголовки — `header("X-API-Key")`, `set_header(...)`; прервать запрос из любой
функции — `fail(401)`; пароли — `hash_password`/`check_password`, время —
`time_iso`/`parse_time`, проверка формата — `` s.matches(`[A-Z0-9-]{3,20}`) ``.
Внешние сервисы — `fetch GET url`, фоновые задачи — `every 10 min { ... }`,
сохранение данных между перезапусками — `KHRIP_DATA=файл`. Пример целиком —
[погодный бэкенд с уведомлениями](examples/weather/weather.kh): погода по городу,
подписки с порогами, проверка каждые 10 минут, вебхук (подходит и Telegram).
Каждый запрос выполняется в своей арене памяти; данные `store` переживают запрос и
доступны обработчикам так, будто запросы идут по одному. Паника в обработчике — 500,
сервер работает дальше.

## Где мы сейчас (v0.9)

**Веб-сервер**, 2 ядра, `wrk` с двух других ядер, 128 соединений
([отчёт](bench/results/2026-10-19-v0.5.md)):

| | plaintext RPS | json RPS | p99 json, мс | Память | Размер | Старт |
|---|---:|---:|---:|---:|---:|---:|
| **Khrip** | **250 502** | **245 216** | **3,7** | **2,1 МБ** | **61 КБ** | **14 мс** |
| Go 1.24 net/http | 77 798 | 69 881 | 13,8 | 14,8 МБ | 8 МБ | 31 мс |
| C# .NET 10 (JIT) | 120 212 | 113 191 | 5,5 | 95,3 МБ | +среда .NET | 549 мс |
| C# .NET 10 (Native AOT) | 110 221 | 101 140 | 6,3 | 40,9 МБ | 9 МБ | 40 мс |

В 2,1 раза больше запросов, чем у C#, и в 3,2 раза больше, чем у Go, при 2 МБ памяти.
p99 на plaintext шумит от прогона к прогону (1,4–8,6 мс); у C# стабильнее — 3,8 мс.

**Токены на типичных задачах бэкенда** ([eval/](eval/README.md)): восемь задач
— сокращатель ссылок, банк с переводами, заметки с паролями и токенами,
ограничение частоты, каталог с фильтрами и страницами, склад с заказами, опросы,
бронирование переговорных. Каждая решена на Khrip, Python, C# и Go, все решения
проходят один и тот же сценарий запросов (`eval/run.sh`). Размер решения, o200k:

| | Khrip | Python FastAPI | C# | Go |
|---|---:|---:|---:|---:|
| 5 задач, на которых язык дорабатывался | **2661** | 3168 | 3270 | 5079 |
| 3 отложенные задачи, язык заморожен | 2431 | **2186** | 2427 | 3425 |
| те же 3 после добавления `parse_time` | **1958** | 2186 | 2427 | 3425 |

Честно: на задачах, которых язык «не видел», Khrip оказался вровень с C# и
хуже Python — не хватило разбора дат. Преимущество над Go устойчивое (×1,4–1,9),
над Python и C# — 10–25% и только там, где нужное есть в языке. Все решения
написал тот же ИИ, что и язык, поэтому это не независимая оценка; протокол
слепой проверки на других моделях — [eval/README.md](eval/README.md#протокол-слепой-проверки).

**Вычисления** (`bench/compute`, одно ядро): решето Эратосфена — 150 мс против 142
у Go и 144 у C# AOT; fib(38) — 286 мс против 207 у Go и 203 у C# AOT: вызов функции
пока дороже.

**SIMD** (`bench/simd`): разбор заголовков браузерного запроса — 134 нс против 816
побайтно, запись JSON — в 5,9 раза быстрее, чтение — в 3,5 раза.

## Сборка из исходников

Нужны только `nasm` и `ld`: никаких Go, C или других компиляторов.

```
./build.sh       # зерно на ассемблере → загрузчик → khc → khc собирает сам себя
tests/run.sh     # 110 тестов: программы, ошибки, блоки test, HTTP, погода, задачи eval
```

Цепочка раскрутки: зерно на ассемблере [bootstrap/khc0.asm](bootstrap/khc0.asm)
понимает начальное подмножество [Khrip-0](docs/KHRIP0.md); на нём написан загрузчик
[bootstrap/boot.kh](bootstrap/boot.kh), который понимает часть Khrip-1 и собирает
настоящий компилятор [src/](src) (~9500 строк на Khrip). Дальше `khc` собирает себя
сам; два последних поколения совпадают побайтно. Самокомпиляция — ~40 мс.
