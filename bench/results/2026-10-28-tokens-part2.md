## 0. Исправления по независимой проверке (ревью 0954735)

Решения ведущего — обязательные. Всё в компиляторе — с тестами и мутациями
(tests/run.sh, «оптимизации компилятора»: 20 новых подложенных ошибок, каждую
ловит свой тест).

**HIGH**

- **H1, `Product { ...old, ...patch }` стирал необязательные поля.** Теперь
  (src/atom.kh, parse_struct_lit): распаковка значения того же типа копирует все
  поля как есть; значения другого типа (заплатка) — поле `T?` берётся, только
  если оно не none, и в поле `T`, и в поле `T?` (как `SET {patch}` и `to_bson`).
  Поле со значением по умолчанию без значения из прежних распаковок сначала
  получает умолчание, потом заплатку. То же у анонимных литералов (A2 —
  ожидаемый тип; A3 — поле `T?` из нескольких распаковок: последняя не none).
  Стереть поле — явно: `note: patch.note`. Скилл и KHRIP.md говорят это. Тест
  tests/run/spread_patch.kh (+ правило skill spread_patch.kh), мутации
  spreadsame, spreadoptopt, spreaddefault, anonspreadopt. Решения eval и тесты:
  поведение не изменилось ни у одного (набор проходит без правок ожиданий).
- **H2, `clickhouse metrics = env(...)` в сервере.** Скрытая глобальная
  соединения `__ch_conn_*` больше не «глобальная, которую делят запросы».
  Тесты: tests/chcheck/ch_named_route.kh и ch_named_every.kh (`khc check`),
  tests/chdb/named_server.kh (маршрут и `every` на настоящем ClickHouse),
  правило ch_inline.kh.

**MEDIUM: скилл и компилятор**

- **M1.** `postgresql.md`: «`{rows}` with a list inserts them all». `INSERT
  INTO t {[body]}` и `INSERT INTO t {name}` (не строка) — ошибки `khc check`
  с подсказкой (для списка списков — «drop the brackets»), а не синтаксическая
  ошибка базы при запуске. tests/errors/sql_insert_rows.kh, мутация
  sqlinsertrows.
- **M2.** `return 409 "msg"` при `| 409` без типа — ошибка «status 409 has no
  body here», подсказка «declare | 409 str to send a message». Ядро: «a bare
  `| 409` has no body». tests/errors/route_status_body.kh, правило
  status_body.kh, мутация routestatusbody.
- **M3.** Ядро: сужение — у `let` и параметра, «not a `var` or a field: `if let
  t = body.title { }`». Правила var_narrow (поле тоже) и var_narrow_ok.
- **M4.** Строка «any f(x, y) can be written x.f(y)» заменена: встроенные — методы
  (кроме `len(xs)`), своя функция — ещё и метод первого аргумента, `print`,
  `to_json`, `url_encode` — только функции. Подсказки: `sum(xs)` → «sum is a
  method: write xs.sum()», `max(n, 2)` → `n.max(2)`, `trim(" a ")` → `" a
  ".trim()`, `xs.to_json()` → «to_json is a function». Правила methods и
  methods_ok, мутация methodform.
- **M5.** Ловушки в ядре и подсказки компилятора вместо голых или каскадных
  ошибок: `x in xs`/`not in` → «Khrip has no 'in' operator» с `xs.contains(x)`,
  `m.has(k)`, `s.contains(part)` по типу правой части (и в условии `if`);
  `m.get(k, 0)` → «.get() takes only the key», `m["b"] ?? 0`; `"{x:.2f}"` →
  «format specs ... are not supported», `{x.round_to(2)}` (ширина `{x:>4}` —
  «write {x}»); `.sort(comparator)` → `sort_by`. tests/errors/habit_hints.kh,
  правила traps_in и traps_in_ok, мутации inoperator, formatspec, mapgetdefault.
- **M6.** Ядро: «Beside a struct or error variant, a literal 200 is `return 200
  { ... }`». `return todos[id] ?? 404 { error: "..." }` и `?? 404 "текст"`
  теперь работают (и после статуса: `return 200 x ?? 404 {...}`); попутно
  исправлено: `return n ?? 0` в маршруте, который возвращает int, был статусом
  0. `let t = m[k] ?? 404` (не в return) — подсказка «?? 404 answers 404 only
  in return; here write x ?? fail(404) or let v = x else { return 404 }».
  tests/api/route_qq_value.kh, правила return_200 и return_200_ok, мутации
  routeqqvalue, routeqqint, qqstatuslet.
- **Ключевые слова — имена полей.** `type`, `in`, `match`, `test`, `call` —
  имена полей в объявлении типа, литерале и после точки (лексер: перед `:`,
  когда ближайшая открытая скобка — `{`, и после `.`). Неоднозначности нет:
  ни одно из них не бывает перед `:` внутри `{` и после `.`. Сверх решения
  (было нужно для задачи todos): `type` и `test` — ключевые слова только в начале
  своих объявлений (`type Имя`, `test "..."`), иначе это имена: параметр
  запроса `?type=note`, локальная, сокращение `{ type }`. Объявления верхнего
  уровня не изменились. `in`, `match`, `call` параметрами и локальными не
  стали: в выражении они — оператор и выражения. Поле `type` у варианта —
  ошибка (JSON варианта называет себя в `"type"`). Тесты:
  tests/run/keyword_fields.kh, tests/api/keyword_names.kh,
  tests/errors/variant_type_field.kh; мутации kwfield, kwfielddot, kwtypename,
  kwtestname, kwvariant.
- **Тело `call` с типом.** Причина: `call PATCH ... { qty: 8 }` получает тип
  тела маршрута, его поля none писались как `null`, а сервер считает явный
  `null` присланным — `SET {body}` записывал NULL в `NOT NULL` → 400 «missing
  value». Теперь тело `call` с типом не пишет поля none (lib/api.kh,
  `__json_encode_sent`, слово ctx CTX_JOMIT): обе формы ведут себя одинаково,
  явный `null` — телом-строкой. tests/pg/api.kh («merge patch»: `PersonPatch {
  nick }` и `{ nick }` не трогают `name`).

## 2. Тесты (tests/run.sh, tests/skill/)

## 3. Способ замера

eval/PROMPT.md: system prompt — правила языка; у Khrip — строка о главах и весь
`SKILL.md`; первое сообщение — задача. Ответ из строк `READ <глава>` (можно
несколько, можно в блоке кода) — не попытка, главы приходят следующим
сообщением. eval/README.md («Токены»): стоимость одного правильного ответа =

спецификации нет. Слепая проверка («Протокол слепой проверки») считает иначе и
точнее: счёт поставщика (usage) за каждый вызов × его цены, итог — по задачам,

**Находки прогона 1 и что исправлено:**

1. **Сужение `T?` и `if let` в `if`, который даёт значение** (ledger, попытки
   1–3). Модель сделала последнюю строку `tx { ... }` выражением
   `if prev != none { prev.body ... } else { ... }`: сужение там не действует
   (`the value may be none`); после подсказки — `if let p = prev { ... } else
   { ... }`: `if let cannot be used as a value` с подсказкой «use x ?? default or
   match», которая не помогает; затем снова первая форма. Ядро говорило «checks
   against none narrow a let», не оговаривая это. **Исправлено:** «Narrowing and
   `if let` work in `if` statements, not in an `if` used as a value: unwrap
   before it» (+18 токенов, правило tests/skill/rules/narrow_if_value.kh). Повтор
   со свежим агентом написал `if let` оператором и `return 201 old` внутри `tx`.
2. **`{before}::bigint IS NULL`** (повтор ledger, попытка 1): привычка pgx/asyncpg
   приводить тип параметра; компилятор узнаёт только `({x} IS NULL OR ...)`.
   **Исправлено в главе:** «`{expr}` is a typed parameter (no `::cast`) ...
   compare an optional exactly as `({x} IS NULL OR col = {x})`»; правила
   pg_optional.kh и pg_optional_ok.kh. Повтор ledger был одним, как в задании, —
   эту правку прогон ещё не видел.
3. Не скилл, а модель: `WHERE key = {key}` с `key: str?` (ledger, попытка 1) —
   правило было в главе, компилятор объяснил, модель исправила.
4. Ловушки ядра сработали: notes перечитал `accounts.has` после
   `hash_password` («store may change ... read it again after»), никто не написал
   `null`, `++`, тернарный оператор, компаратор сортировки или литерал без имени
   в лямбде (часть 1 оставила это кандидатом — не понадобилось).
5. Транспорт прогона, не скилл: сообщения между сеансами экранируют HTML —
   глава пришла с `&gt;=` и `-&gt;` вместо `>=` и `->`; ответ от этого не

   строки на 4 пробела меньше, чем у `blind.py`; токены считаны по файлу
   `blind.py`.
