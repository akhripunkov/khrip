**Выброшено** (в скилле нет):

- «Keep money in int cents» — совет, а не правило; задачи говорят это сами, а
  `int` и запрет смешивать с `float` — в ядре.
- Из «Habits from other languages» — пары, на которые компилятор отвечает той же
  подсказкой: `and or not`, `x++` (в ядре «no `++`»), `elif`, `func def
  function`, `String`, `.length .size() .Count`, `let mut`, `import`, `$1`/`?` в
  SQL, `BEGIN`/`COMMIT`. Оставлены и дополнены ловушки без подсказки
  компилятора: тернарный `?:`, `switch`, `enum E { A, B }`, `range(n)`, `if xs`,
  `str(n)`, `int(s)`/`parseInt`, `f"{x}"`/`${x}` (в сырой строке `${x}` молча
  остаётся текстом), `try/catch/throw/raise`, `return 400, "msg"`, лямбды с
  телом и компаратором сортировки, печать списка.
- «`{2,5}` stays text» осталось, а пример `const`, `if`, `match` у `ORDER BY`
  сжат до «локальная из строковых литералов (`if`, `match`)».

## 2. Тесты (tests/run.sh, tests/skill/)

- **Формат:** `SKILL.md` начинается с frontmatter `name` (имя папки, строчные
  буквы, цифры, дефис) и `description` (до 1024 знаков).
- **Бюджеты:** `eval/tokens/count.mjs --raw` (новый режим: весь текст) считает
  каждый файл скилла; ядро ≤ 3000, глава ≤ 900. Нет node — строка `SKIP`; нет
  gpt-tokenizer — `npm install` (версия закреплена, 2.9.0), не вышло — `SKIP`;
  счётчик упал — `FAIL`.
- **Каждый блок кода компилируется** (tests/skill/check.py): у всех блоков
  метка — «```khrip» (целая программа: `khc check`, с тестами и без баз — ещё
  `khc test`), «```khrip top» (объявления, обёртка tests/skill/wrap/top.kh),
  «```khrip body» (операторы в теле маршрута, wrap/body.kh). Блок без метки
  `khrip` или с неизвестной меткой — `FAIL`: пример не может уйти из проверки.
- **Примеры глав работают:** tests/skill/run/<глава>.kh дописывается к первой
  программе главы и идёт через `khc test` на настоящей базе: перевод, 409,
  404, `created_at`; 120 событий MongoDB, `limit`, курсор, дубликат 11000,
  `$set` только присланных полей; вставка ClickHouse, статистика, Nullable,
  400 на UInt64. Без базы — `SKIP` (PostgreSQL проверяется `psql`).
- **Ключевые правила** (tests/skill/rules/, 17 программ): в каждой — `// in:`
  файл скилла и `// rule:` фраза, которая должна в нём стоять, и
  `// expect:` (ошибка), `.out` (вывод), `// compiles` или блок `test`. Литерал
  без ожидаемого типа — тип своих полей; `{k: v}` с переменной — ошибка; `{` в
  начале оператора и в ветке `match`; `7 / 2`, литерал int как float; int и
  float не смешиваются; `var` не сужается; сужение и `if let` не работают в `if`
  со значением (находка прогона); поле, изменённое через `let`, меняет store;
  подстановка, `{2,5}`, сырые строки, `${x}`; JSON в обычной строке —
  ошибка; каждый статус объявлен; тело запроса — значения по умолчанию, `null`,
  перечисления, 400; сортировка без компаратора; запись вне `tx` после другого
  оператора; `{x}::bigint IS NULL` — не проверка (находка прогона) и
  `({x} IS NULL OR ...)` — проверка; `T?` в `ch` без `IS NULL`.
- Проверено, что проверка падает: на испорченном ожидании в примере MongoDB и
  PostgreSQL, на блоке без метки.

Полный набор: см. «Проверка» ниже.

## 4. Пробный прогон

Не слепая проверка: агенты — того же поставщика, что писал Khrip. Каждый — новый
облачный сеанс без репозитория; первое сообщение — оговорка «без инструментов,
только этот текст» (dry-run/wrapper.txt), system prompt и задача по
eval/PROMPT.md. Ответы я переносил в `eval/blind.py reply`, его сообщения
(глава, вывод проверки) — обратно в сеанс. Проверки — eval/run.sh на настоящем
PostgreSQL. Токены — o200k по сообщениям разговора.

| Задача | Итог | Попытки | Вызовы | Главы | Ответы | Стоимость, w = 0,02 | w = 0,2 | Эталон: программа |
|---|---|---:|---:|---|---:|---:|---:|---:|
| notes | прошла (35/35) | 1 | 1 | — | 766 | 827 | 1372 | 598 |
| inventory | прошла (41/41, свои тесты тоже) | 1 | 1 | — | 1208 | 1269 | 1814 | 695 |

«Стоимость» — `вызовы × w × system + главы + ответы + сообщения о неудаче`
(system 3029 и 3042 токена: ядро и строка о главах). Программы длиннее эталонных
решений: notes 759 против 598 токенов кода (+27 %), ledger 1350–1384 против 995
(+36–39 %), inventory 1202 против 695 (+73 %, с блоком тестов); эталоны писал тот,
кто делал язык.

**Находки и что исправлено:**

1. **Сужение `T?` и `if let` в `if`, который даёт значение** (ledger, попытки
   1–3). Модель сделала последнюю строку `tx { ... }` выражением
   `if prev != none { prev.body ... } else { ... }`: сужение там не действует
   (`the value may be none`); после подсказки — `if let p = prev { ... } else
   { ... }`: `if let cannot be used as a value` с подсказкой «use x ?? default or
   match», которая не помогает; затем снова первая форма. Ядро говорило «checks
   against none narrow a let», не оговаривая это. **Исправлено:** «Narrowing and
   `if let` work in `if` statements, not in an `if` used as a value: unwrap
   before it» (+18 токенов, правило tests/skill/rules/narrow_if_value.kh). Повтор
   со свежим агентом написал `if let` оператором и `return 201 old` внутри `tx`.
2. **`{before}::bigint IS NULL`** (повтор ledger, попытка 1): привычка pgx/asyncpg
   приводить тип параметра; компилятор узнаёт только `({x} IS NULL OR ...)`.
   **Исправлено в главе:** «`{expr}` is a typed parameter (no `::cast`) ...
   compare an optional exactly as `({x} IS NULL OR col = {x})`»; правила
   pg_optional.kh и pg_optional_ok.kh. Повтор ledger был одним, как в задании, —
   эту правку прогон ещё не видел.
3. Не скилл, а модель: `WHERE key = {key}` с `key: str?` (ledger, попытка 1) —
   правило было в главе, компилятор объяснил, модель исправила.
4. Ловушки ядра сработали: notes перечитал `accounts.has` после
   `hash_password` («store may change ... read it again after»), никто не написал
   `null`, `++`, тернарный оператор, компаратор сортировки или литерал без имени
   в лямбде (часть 1 оставила это кандидатом — не понадобилось).
5. Транспорт прогона, не скилл: сообщения между сеансами экранируют HTML —
   глава пришла с `&gt;=` и `-&gt;` вместо `>=` и `->`; ответ от этого не
   пострадал. Одно сообщение о неудаче (ledger, 09) ушло с отступом исходной
   строки на 4 пробела меньше, чем у `blind.py`; токены считаны по файлу
   `blind.py`.

## 6. Найдено по пути (вне задачи, в компилятор)

- Восстановление после синтаксической ошибки внутри функции уходит в
  lib/nostore.kh: `xs.sort((a, b) => a - b)` или `print(x ? "a" : "b")` дают
  поток ложных ошибок библиотеки (`unknown name 'n'`, `expected '}', found end of
  file` в lib/nostore.kh). Ошибка «the program has no fn main» указывает на
  lib/nostore.kh:1:1.
- Сужение после проверки на `none` и `if let` не работают в `if`-значении — в
  скилле теперь оговорено, но это кандидат в язык; подсказка к «if let cannot be
  used as a value» (`use x ?? default or match`) не ведёт к рабочему коду.
- `({x}::тип IS NULL OR ...)` не считается проверкой на NULL.
- `-> T | 404` и `return 404 "сообщение"` компилируется, а сообщение молча
  заменяется на «Not Found» (нужен `404 str`).
- Подсказка к `int * float` предлагает `x.to_int()` у float, а не
  `n.to_float()` у int.
