# v0.11: свой TLS 1.3

`fetch` по https больше не запускает `curl`: TLS 1.3, проверка сертификатов и
вся криптография — в библиотеке Khrip, горячие места — машинный код компилятора
(AES-NI, PCLMULQDQ, SSE2, 64-битное умножение Монтгомери). Intel Xeon 2,8 ГГц
(AVX2, AES-NI, без SHA-NI).

## Шлюз по HTTPS

Стенд [bench/gateway](../gateway/run.sh), сценарии `tls` и `tls-new`: `GET
/quote?id=N` — запрос в сервис по HTTPS (Go, сертификат ECDSA P-256 от
промежуточного P-384 и корня RSA), разбор JSON, ответ. Шлюз на ядрах 0 и 1,
сервис на ядре 2, `wrk` (64 соединения) на ядре 3.

Keep-alive — соединения с сервисом переиспользуются:

| | запросов/с | p50, мс | p99, мс | мкс процессора на запрос | пик памяти, МБ |
|---|---:|---:|---:|---:|---:|
| **Khrip** | **29 354** | **2,1** | **6,6** | **52** | **8,8** |
| Go | 12 419 | 4,8 | 12,7 | 119 | 16,1 |
| C# | 10 249 | 5,5 | 22,0 | 186 | 113 |
| Python | 356 | 157 | 755 | 2 774 | 53 |
| Khrip v0.10 (https через `curl`) | 106 | 577 | 960 | 1 086 и процессы `curl` | — |

Сервис закрывает соединение после каждого ответа — каждый запрос шлюза
начинается с полного рукопожатия:

| | запросов/с | p50, мс | p99, мс | мс процессора на запрос |
|---|---:|---:|---:|---:|
| **Khrip** | **1 346** | 44,8 | 79,8 | **1,45** |
| Go | 978 | 16,6 | 6 100 | 1,83 |
| C# | 383 | 159 | 343 | 5,14 |
| Python | 186 | 329 | 739 | 5,35 |

Здесь потолок задаёт и сервис: на одном ядре он сам делает рукопожатия.
Khrip запоминает проверенную цепочку сертификатов (как браузеры), поэтому
повторное рукопожатие с тем же сервером проверяет только подпись
CertificateVerify; Go и C# проверяют цепочку каждый раз. p99 у Go в этом режиме —
единичные запросы, ждавшие секунды.

## Криптография, одно ядро

| | Khrip |
|---|---:|
| проверка ECDSA P-256 | 0,48 мс |
| проверка ECDSA P-384 | 1,2 мс |
| проверка RSA-2048 (PSS) | 0,12 мс |
| X25519 | 0,24 мс |
| ключ P-256 (для HelloRetryRequest) | 0,38 мс |
| AES-128-GCM | 537 МБ/с |
| ChaCha20-Poly1305 | 221 МБ/с |
| полное первое рукопожатие (P-256 + P-384 + RSA в цепочке) | ~2,3 мс |

Для сравнения: в OpenSSL на ассемблере проверка P-256 — около 0,06 мс, AES-GCM
— несколько ГБ/с. Разницу с Go и C# на шлюзе это не меняет — запрос стоит
дороже, чем шифрование, — но место для ускорения есть.

## Чего пока нет

- TLS 1.2: сервер без TLS 1.3 получает отказ «protocol version».
- Сертификат клиента (mTLS), возобновление сессий (PSK), ключи P-521 и Ed25519 в
  сертификатах, проверка отзыва (OCSP, CRL — как и в Go по умолчанию).
- TLS на стороне сервера: Khrip-сервер за обратным прокси или ingress.
