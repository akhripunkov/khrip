## 1. Правила языка (что пришлось решить)

**A1, анонимный тип.** `'{' поле ':' тип ['=' литерал] (',' ...)* '}'` — в
полях, списках, словарях, `T?`, параметрах, результатах функций и маршрутов,
`let`/`var`, `store`. Запятые между полями, как у именованных типов,
необязательны; `...Другой` внутри анонимного типа — ошибка с подсказкой
назвать тип; пустой `{}` как тип — ошибка.

- **Тождество.** Те же имена полей с теми же типами **и значениями по
  умолчанию в том же порядке** — один тип (решение ведущего после ревью; в
  приложении было «в любом порядке», текст приложения исправлен). Порядок —
  часть типа, потому что в нём поля уходят в JSON и BSON: сортировка MongoDB
  `{ score: -1, name: 1 }` — не `{ name: 1, score: -1 }`. Литерал с ожидаемым
  типом берёт его порядок (как `T { ... }`), литерал без него (A3) — свой.
  Значение по умолчанию — часть типа: иначе непонятно, чьё значение берёт
  `from_json` у `{ limit: int = 20 }` и `{ limit: int }`. Значения
  сравниваются как записаны (`20` и `0x14` — разные), это редкость. Типы,
  которые отличаются только порядком или значением по умолчанию, не
  смешиваются, и ошибка называет отличие.
- **Имя** в сообщениях — запись типа: `{ token: str }`, со значениями по
  умолчанию (`{ limit: int = 20 }`); в сгенерированном коде (маршрутизатор,
  снимок store) — `__anon<номер>`, которое понимают только библиотека и
  сгенерированный текст.
- **Именованные типы номинальны:** значение анонимного типа становится
  именованным только литералом или распаковкой (`User { ...x }`), и наоборот
  (`{ ...user }` с ожидаемым анонимным типом). Неявное преобразование — ошибка
  с подсказкой.

**A2, решение у `{`.** В позиции значения `{`, за которой `...` или имя и
`:`, `,`, `}`, — литерал структуры; ключ-строка — словарь, как раньше.

- Если ждут **словарь**, это словарь, но голое имя ключом — ошибка (после
  ревью): `{"k": v}` — ключ "k", `{(k): v}` — ключ из переменной. Без
  ожидаемого словаря `{k: 1}` — структура (так в приложении A), а если такой
  литерал раньше был бы словарём с ключами — значениями переменных (§9), —
  ошибка с той же подсказкой. В репозитории было одно такое место
  (tests/api/gc_maps.kh).
- `{ имя }` после `=>` — всегда E-A1 (после ревью): значение имени пишется
  `=> имя`.
- `{}` — структура (со значениями по умолчанию; без них — ошибка со списком
  недостающих полей), только если ждут структуру; иначе словарь.
- Ожидаемый тип (`want` парсера): `let`/`var` с типом, присваивание локальной,
  глобальной, store, полю и элементу, параметр (и обобщённый у методов списка:
  `xs.push({ ... })`), `return`, элемент списка, поле литерала, значение
  словаря, правая часть `??`, ветки `if`/`match` со значением (в скобках).
  `T?` даёт `T`. Тип-вариант (`Shape`) — ошибка «нужно имя варианта». Лямбды
  своего ожидаемого типа не получают: `xs.map(x => { a: x })` — A3.
- **return маршрута:** со статусом — тип варианта со статусом; без статуса —
  единственный тип-структура среди вариантов (`-> 201 Product | 400 str`);
  две разные структуры — ошибка с подсказкой «имя типа или статус».
- В **начале оператора и в ветке `match`** `{` — блок: `{ имя:`, `{ имя,`,
  `{ ...` там — ошибка (E-A1 у ветки `match`, такая же в начале оператора и в
  конце блока со значением), подсказка — `({ ... })` или имя типа; в ветке
  `match` и `{ имя }` (после ревью — всегда). Тело лямбды — выражение:
  `xs.map(x => { x })` — структура. Оператор `имя:` (`if c { x: 1 }`) — своя
  ошибка.
- В **условии, у значения `match` и в заголовке `for`** `{` начинает блок:
  литерал там — ошибка «нужны скобки».
- Тело `fetch` и `call` теперь может начинаться с `{` (литерал структуры или
  словаря) на той же строке, кроме условия. Тело `call`, у которого путь —
  один литерал и попадает ровно в один маршрут с телом, получает тип тела
  этого маршрута (после ревью).

**A3.** Литерал без ожидаемого структурного типа получает закрытый анонимный
тип своих полей; значения вычисляются по порядку записи. Распаковка работает:
поля структуры, кроме заданных явно, из нескольких распаковок — последняя
(разные типы одного поля — ошибка). `none`, значение без типа и повтор поля —
ошибки; поле без `:` (кроме сокращения `{ имя }`) — ошибка. Где принимается:

- тело `fetch` и `call` — JSON по описанию типа;
- `to_json`, поля и методы-функции (`req.model`, `x.f()`) — проверяются по
  типу;
- **тело ответа маршрута — только если тип маршрута тот же анонимный тип**
  (`-> { token: str }`, `let r = { token: t }; return r`). В именованный тип
  маршрута значение A3 не превращается: это было бы неявное преобразование;
  подсказка — имя типа или `Name { ...value }`.

**W-A2.** Анонимный тип, записанный как тип в трёх и более местах программы
(не литералами), — предупреждение у третьего места по тексту с подсказкой
дать ему имя. Места считаются по позиции `{`, поэтому повторный разбор
встраиваемой функции не считается; считаются только места в программе (не в
библиотеке и не в сгенерированном коде).
Порог — 3, как в приложении. Стоимость — список пар (тип, место) и один проход
в конце сборки.

## 2. Реализация

- **Типы** (src/decl.kh, src/types.kh): анонимная структура — обычная запись
  в таблице структур с именем `{ ... }`; `anon_struct` ищет существующую с тем
  же набором (имя, тип, ключ значения по умолчанию). Поэтому описания типов
  (`type_desc`), маски ссылок, JSON, копирование в store, проверка графа,
  снимок KHRIP_DATA и `khc test` работают тем же кодом, без изменений в
  библиотеке.
- **Предварительный проход:** после заголовка `fn`/`route`/`test` сканер
  объявлений сразу переходит к телу, после `store`/`var` — к начальному
  значению (иначе `}` типа результата перед `{` тела выглядел как начало
  объявления). Тип результата маршрута `{ имя: ...` отличается от тела по
  трём лексемам.
- **Литералы** (src/atom.kh): `brace_struct_ahead` решает у `{`;
  `parse_brace_struct` — A2 через `parse_struct_lit` (те же проверки и
  сообщения, что у `T { ... }`) или A3 (`parse_anon_lit`: значения в стек,
  затем структура в раскладке типа). E-A1 и ошибки начала оператора —
  src/stmt.kh, src/variant.kh; выбор варианта `return` — src/api.kh.
- **Предупреждения** (src/diag.kh): `warn_tok`, счётчик ошибок `nerrors`;
  предупреждение не прячет ошибку той же строки; встраивание выключается
  только ошибками.
- **Анализ чтения** (src/rw.kh): `rw_type_end` разбирает `{ ... }`, объявление
  `let x: { ... } =` узнаётся, а `=` значения по умолчанию в таком типе не
  считается присваиванием. Литералы `{ ... }` были свежими и раньше (как
  словари).
- Найдено и исправлено по пути: незакрытая `{` объявления `type` роняла
  компилятор (было и в e1203ad).

## 8. Риски и места для тихой ошибки

Новые места, где ошибка проходит молча:

1. **Опечатка в поле литерала A3** (`{ modle: m }` уходит телом `fetch` или в
   `to_json`) — молча, как у словаря и объекта TypeScript (приложение A).
   Чтение поля `req.model` у такого литерала — ошибка компиляции.
2. **Тело `call` в тестах** — A3, только если путь не литерал (`call POST
   path { ... }`, путь с подстановкой) или маршрутов с таким путём не один:
   там опечатка в необязательном поле или поле со значением по умолчанию
   дойдёт до маршрута как отсутствующее поле. С путём-литералом — ошибка
   (после ревью).
3. **Структурное тождество:** `{ id: int }` из двух несвязанных мест — один
   тип, функция одного примет значение другого (как в TypeScript).
4. **`{k: v}` без ожидаемого типа — структура** с полем "k". Старый код, где
   так писали словарь с ключом — значением переменной, после ревью не
   собирается: голое имя ключом словаря — ошибка, а литерал без ожидаемого
   типа, у которого имена полей — переменные int или str одного типа, значения
   одного типа и их не упоминают, — ошибка с подсказкой `{(k): v}` или
   `{"k": v}`. Молча остаётся только то, что под это правило не подходит:
   например, имена полей — переменные разных типов (`{id: 1, name: "a"}` при
   `id: int` и `name: str` — такой текст и раньше не собирался как словарь,
   поэтому смысл не меняется).
5. **`{ имя }` в теле лямбды** — структура `{ имя }` (тело лямбды —
   выражение); в ветке `match` — E-A1.

Порядок полей в JSON и BSON (ревью, HIGH) больше не тихое место: у каждого
анонимного типа свой порядок, смешение — ошибка.

Риски реализации: решение у `{` — по трём лексемам (и переводу строки у
сокращения), анализ чтения и предварительный проход — по лексемам (как и
раньше); всё сомнительное в анализе чтения остаётся write. Лексема `{` после
`fetch ... url` на той же строке теперь тело (кроме условия) — раньше такого
кода быть не могло. Проверка «был бы словарём» ложно срабатывает на части
настоящих литералов (у ревьюера — 5 из 34 примеров): имя поля совпало с
переменной int/str, а значение её не упоминает; исправление — кавычки у
ключа или другое имя, 0–2 токена.
