# Проверка на типичных задачах бэкенда

Главная цель Khrip — чтобы ИИ писал на нём дешевле, чем на Go, C# и Python. Здесь
набор задач, общие проверки и протокол, по которому это можно измерить честно,
в том числе не нам.

## Что в наборе

- `tasks/<задача>/task.md` — условие на английском, без упоминания языка: порт
  8080, данные в памяти, коды ответов, проверки ввода.
- `tasks/<задача>/check.sh` — сценарий запросов через `curl` к уже запущенному
  серверу: коды ответов, тела, заголовки, одновременные запросы. От языка не
  зависит.
- `run.sh <задача> <язык> [папка]` — собрать, запустить и проверить решение. Языки:
  `khrip`, `go`, `csharp`, `python`; для любого другого — `START="команда" run.sh
  <задача> other <папка>`.
- `solutions/<задача>/<язык>/` — наши решения на Khrip, Go, C# и Python. Все
  проходят проверки.
- `PROMPT.md` — текст запроса к модели и правила попыток.
- `results/` — таблицы токенов.

Задачи:

| Задача | Что проверяет |
|---|---|
| shortener | случайные коды, 302 с `Location`, проверка формата, 409 |
| bank | деньги в центах, переводы, 409 при нехватке, 60 одновременных переводов |
| notes | регистрация, пароли (соль + медленный хеш), токены, `Authorization: Bearer` |
| ratelimit | окно на ключ из заголовка, 429 с `Retry-After`, переменная окружения |
| catalog | дробные цены, фильтры, сортировки, страницы, PATCH, группировка |
| inventory | заказы «всё или ничего», отмена, одновременные заказы |
| polls | голос один раз на голосующего, проценты, 403/409 |
| bookings | разбор и проверка дат, пересечение интервалов, фильтр по дню |

## Что мы уже измерили сами

Размер правильного решения в токенах (`bench/tokens/eval.mjs`, код без
комментариев). Первые пять задач — **настроечные**: на них мы искали пробелы
языка и дорабатывали его (заголовки, `fail`, сужение `T?`, параметры по
умолчанию, `...` для PATCH, регулярные выражения, сырые строки). Три последние —
**отложенные**: написаны после того, как язык заморозили. Таблицы: «до доработок»
— [results/tokens-before.md](results/tokens-before.md), язык заморожен —
[results/tokens-frozen.md](results/tokens-frozen.md), итог —
[results/tokens.md](results/tokens.md).

| | Khrip | Python FastAPI | C# | Go |
|---|---:|---:|---:|---:|
| 5 настроечных задач, до доработок v0.9 | 2886 | 3168 (×1,10) | 3270 (×1,13) | 5079 (×1,76) |
| 5 настроечных задач, после | 2661 | 3168 (×1,19) | 3270 (×1,23) | 5079 (×1,91) |
| 3 отложенные задачи, язык заморожен | 2431 | 2186 (×0,90) | 2427 (×1,00) | 3425 (×1,41) |
| 3 отложенные, после `parse_time` | 1958 | 2186 (×1,12) | 2427 (×1,24) | 3425 (×1,75) |

o200k; в скобках — во сколько раз больше, чем у Khrip. Честный итог: на
отложенных задачах замороженный Khrip **не лучше Python** — бронирование без
разбора дат заняло 1046 токенов против 711; на складе и опросах Khrip меньше на
5–7%. После добавления `parse_time`/`parse_date` бронирование — 573, но это уже
снова доработка под увиденную задачу.

Чего эти цифры **не** доказывают:

- Все решения написаны одним автором — тем же ИИ, который проектировал Khrip.
  Решения на других языках написаны добросовестно и проходят те же проверки, но
  оценку самого себя нельзя считать независимой. Решение бронирования на
  замороженном языке сохранено: [results/bookings-frozen.kh](results/bookings-frozen.kh).
- Размер готового решения — не то же, что стоимость его получения. Настоящая
  метрика — токены на решённую задачу: спецификация в промпте + все попытки +
  исправления. Модель видит Khrip впервые, а Go, C# и Python знает по миллионам
  примеров, поэтому может ошибаться на Khrip чаще.
- Задачи придумал тот же автор. Отложенные задачи защищают от подгонки языка, но
  не от подбора удобных для Khrip задач.

## Протокол слепой проверки

1. Взять модель, которая не участвовала в разработке Khrip (любого поставщика).
2. Для каждой задачи и языка — новый диалог с текстом из `PROMPT.md`. Для Khrip в
   промпт входит `docs/KHRIP.md` целиком (~2900 токенов o200k), его стоимость
   учитывается.
3. Ответ модели сохранить в `attempts/<модель>/<задача>/<язык>/`, запустить
   `run.sh`. Не прошло — отправить вывод (ошибки компилятора или строки `FAIL`) и
   попросить файл целиком. Не больше 5 попыток.
4. Записать: прошло ли, число попыток, токены запроса и ответа по каждой
   попытке. Итог по языку — доля решённых задач и средние токены на решённую.
5. Повторить 3 раза на задачу и язык: модели недетерминированы.

Khrip выигрывает, только если при сравнимой доле решённых задач токенов на
решённую задачу меньше, чем у C# и Go, — с учётом спецификации в промпте.
