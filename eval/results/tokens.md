# Токены: стоимость задачи со скиллом (v0.13)

Считают `bench/tokens/skill.mjs` (стоимость со скиллом) и `bench/tokens/eval.mjs`
(размер решений); `bench/tokens/run.sh` печатает обе таблицы. Решения — код без
комментариев, скилл — весь текст файлов, как его читает модель.

## Как считается

Решение владельца (docs/design/v0.13-status.md, «Khrip доучивается скиллом»):
модель всегда работает со скиллом Khrip, и правило 2 меряется так, как работает
агент со скиллом. Всё — в выходных токенах:

    стоимость задачи = w × ядро скилла + c × прочитанные главы + программа

- **ядро** — `skill/khrip/SKILL.md` целиком; оно в system prompt и кэшируется:
  w = 0,02 (чтение из кэша — 0,1 цены входного токена, вход — 1/5 выходного);
- **главы** — входные токены, которые приходят в разговоре: с кэшем они
  записываются в него, c = 0,25 (запись — 1,25 × вход); без кэша w = c = 0,2.
  Строка «главы полным весом» — верхняя граница (c = 1, как будто главу пишут);
- **какие главы читает модель:** задачи на PostgreSQL — `postgresql.md`,
  остальные — ни одной. Так и было в пробных прогонах
  (bench/results/2026-10-28-tokens-part2.md);
- **Go, C#, Python, Java и JavaScript (Node)** модель знает: их спецификация
  пуста, стоимость — сама программа (однострочное правило языка из
  eval/PROMPT.md — меньше 30 токенов, при w = 0,02 это меньше одного токена);
- **файлы проекта не считаются ни у кого**: `go.mod`, `.csproj`, `pom.xml` с
  `application.properties`, `package.json`. У Java они заметны: 337 токенов на
  задачу без базы и 404 с базой (3908 на 11 задач; `.csproj` — 754, `go.mod` —
  471, `package.json` — 489). С ними Java по всем 11 задачам — 20 075 вместо
  16 167;
- **прежний способ** (до скилла): весь `docs/KHRIP.md` в prompt, w × KHRIP.md +
  программа.

Это стоимость **одного правильного ответа**, без неудачных попыток и без
повторно отправляемой истории. Настоящая метрика — счёт поставщика на решённую
задачу в слепой проверке (eval/README.md, «Протокол слепой проверки»): там
каждый вызов, попытки и сообщения о неудаче.

В скобках — во сколько раз дороже, чем Khrip (меньше 1 — Khrip дороже). Ядро —
3000 токенов, `postgresql.md` — 897, весь KHRIP.md — 8258 (полный справочник
v0.13). Java — Spring Boot (один файл `App.java`, без `pom.xml`), Node — Fastify
(`server.js`); решения Java и Node добавлены в выпуске 0.13.0 (часть 2), язык
Khrip под них не менялся.

Что это значит, честно:

- **С кэшем (w = 0,02)** Khrip дешевле всех в сумме и в каждой группе: ядро
  добавляет к задаче 60 токенов, глава с весом 0,25 — 224; запас программ
  (Python длиннее на 14–22 % без базы и на 38 % с базой) их покрывает. По
  отдельности Python и Node дешевле на одной задаче — ratelimit (396 и 416
  против 451); Java, C# и Go дороже на каждой. Прежний способ (весь KHRIP.md в
  кэше) по всем 11 задачам на 4,8 % дороже: без базы — на 15–18 % (ядро меньше
  справочника), на базе — на 7 % дешевле (справочник заменяет главу).
- **Только если считать главу выходными токенами** (полный вес — верхняя
  граница), на задачах с базой Khrip дороже Python (×0,82) и Node (×0,91), почти
  равен C# (×1,05); по всем 11 — дороже Python (×0,92), вровень с Node (×1,02).
- **Без кэша (w = c = 0,2)** ядро стоит 600 токенов на задачу — больше
  большинства программ: Khrip дороже Python, Node и C# во всех группах, кроме
  C# на базе (×1,13). Go и Java без базы дешевле Khrip (×0,91–0,92 и
  ×0,82–0,84), на базе и по всем 11 задачам — дороже (Go ×1,51 и ×1,16, Java
  ×1,29 и ×1,02).
- Это стоимость одного правильного ответа. Попытки и повторно отправляемая
  история меняют картину сильнее; ответ даёт только слепая проверка со счётом
  поставщика за каждый вызов.
