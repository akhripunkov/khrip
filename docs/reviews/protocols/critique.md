# Critique of docs/design/v0.14-protocols.md (independent critic)

Evidence files: /tmp/claude-0/-home-user-khrip/c69287a0-5c25-565c-bc10-daebb195400d/scratchpad/proto-critic/ (ts/p1_hono.ts, ts/p2_bun.ts, alt/p1_openai_sdk.py, alt/p1_openai_sdk.ts, alt/p2_subscribe_history.kh, alt/p1_anon.kh, lean_add.md). Token counts confirmed exactly (951 / 3,485 / 2,681 / 2,303; KHRIP.md 4,165 -> 4,952).

## Blockers
B1. Request deadline kills long streams (§2.4, §3.2, §3.3, §4.6). KHRIP_TIMEOUT (30 s) per coroutine; __co_wait cancels at the next wait; "no total limit" for `for x in fetch` is false; message loops die on a 40 s LLM answer; P-S2 mock streams only 10 s. Fix: lift the request deadline once a stream's head is sent (only idle/progress timeouts and client gRPC/Connect deadlines after that); for message loops the deadline applies until the item's first send; add a 2-minute upstream to P-S2 and llm-proxy checks.
B2. Topic operations take the store lock "in shared mode" -> data races (§2.3, §6.2). store_touch (src/api.kh:1047) only tests CTX_STORE_HELD; a later write in the same writer route runs under the shared lock with no upgrade. Fix: topic ops call __store_lock() in the route's mode (CTX_STORE_MODE); no lock at all in programs without store.
B3. Park/resume and per-pass reset do not specify ctx words; one corrupts data (§7.1, §7.2). Per-coroutine words [8, CTX_CO_END): CTX_WORKER, CTX_CATCH (jump buffer in the Worker), CTX_CORO, CTX_PINREC, CTX_PGHELD, CTX_MONGOHELD, CTX_CHHELD, CTX_TLS_PENDING, CTX_JNULLS. Restoring "ctx words apart from arena words" literally shares a GC record between contexts and lets a panic jump into another request's frame. CTX_JNULLS (lib/api.kh:1306) is a map keyed by struct address, lazily allocated in the arena: dangles after __item_end, or reused addresses make __json_null_sent report nulls never sent -> `for r in rows { sql "UPDATE t SET {r} WHERE id = {r.id}" }` silently sets columns to NULL. Fix: a table classifying every ctx word (stream-owned: STORE_MODE, CATCH and WORKER pointing into __Stream; coroutine-owned: CORO, PINREC, arena/alloc words; must be zero at park: STORE_HELD, PSAVE, PGHELD, MONGOHELD, CHHELD, TLS_PENDING; reset per item: JNULLS, JPATH); audit everything lazily allocated in the arena per request (JNULLS, §3.6 header index, string cache, fetch/pg buffers); in verify mode at park poison words pointing into the released setup arena or old Worker/Co.

## Rule 2
M1 (major). P1 ignores the SDK an AI would use; Khrip loses the flagship case. Python P1 hand-parses SSE (351); with the official openai SDK FastAPI P1 = 229 (246), Hono+SDK = 239 (255); Khrip P1 = 243 (264). TypeScript/Node missing although rule 1 names Node: Bun P2 with built-in topics = 327 (376); Hono P1 without SDK = 326 (360). 83 of Khrip P1's 243 tokens are upstream JSON type declarations; with anonymous nested types and anonymous struct literals P1 = 199 (218) (alt/p1_anon.kh). Fix: add SDK variants and a TypeScript column to §14 and §18; state P1 honestly; treat anonymous types as a separate language design (that is where rule 2 is lost).
M2 (major). KHRIP.md growth breaks DESIGN.md's ~3,000-token budget (principle 8, ROADMAP v0.16); it is already 4,165; additions can be ~40% smaller: lean_add.md covers the same surface in 476 (503) instead of 787 (production bullet -> one pointer to SERVER.md; drop "or gRPC" from the route bullet; streamed-sql bullet to docs; one-line gRPC pointer; M3 subscribe). Fix: aim for <= +500 and make gate 4 count tokens per task.
M3 (major). Replace `if !subscribe(t) { send history }` with `subscribe(t, history)`: the bool idiom is trap S3 (the KHRIP.md example ignores it) and forces "send never waits under the store lock" (R2). History is evaluated under the same lock hold, §6.2 ordering unchanged. P2 225 -> 209 (221); S3 disappears; send can always wait.
M4 (major). Required fields checked over REST but not gRPC (§10.2, S6). Fix: emit non-optional fields without defaults as proto3 `optional` and reject a missing one with INVALID_ARGUMENT naming the field (wire-compatible).
M5 (major). One sql write per pass outside tx -> partial imports and pool deadlocks (§2.2, §7.5). POST import answers once: a duplicate at line 500 returns 409 after 499 commits. Streamed sql: `for o: T in sql` counts as a stream loop, so an UPDATE per row is legal; the portal holds connection A in an implicit transaction -> either a second connection per request (pool deadlock) or the same implicit transaction (no per-pass commit). Fix: allow the relaxation only in message loops (WebSocket and gRPC bidi); in POST loops make partial progress loud (409 "line 500: ... (499 lines saved)"); inside `for o: T in sql` forbid other sql and every wait except send.
M6 (major). "Variables from outside act like store: assigning copies" contradicts KHRIP.md ("assigning shares"); an AI cannot tell that `for data in fetch` and `for o: T in sql` are "loops over a stream"; `state = State{...state, n: ...}` deep-copies the state per message (hidden cliff). Fix: name all three loop kinds explicitly; see R4 (share values already in the owner's region).

## Rule 1
P1 (major). Crypto gates compare only with Go (P-T1, P-T3, §13.4): targets ECDSA P-256 sign <= 50 us, X25519 <= 60 us, RSA-2048 sign <= 1.2 ms, AES-128-GCM >= 2.5 GB/s; OpenSSL ~20-25 us, 25-35 us, 0.5-0.7 ms, 4-5 GB/s without VAES (confirm on the bench machine). Kestrel, Node, Netty win even if targets are met. P-H1 compares only with Kestrel, P-U1 only with Go's json.Decoder. Fix: every gate is ">= best mainstream on the same run"; crypto at OpenSSL parity or an explicit owner exception; measure kTLS (TX and RX) before step 17's AVX2 code.
P2 (major). Benchmark method unsound: coordinated omission (wrk, h2load, ghz closed-loop) -> use open-loop constant rate (wrk2 -R, h2load --rps, ghz --rps) at the same offered load; 10 s runs give ~10 samples for p99.9; 3 s warm-up unfair to Java C2/.NET tiered PGO (need 30-60 s); the bench machine has 4 cores: P-S1 (1,000 msg/s x 10k subscribers = 10 M deliveries/s, ~2 GB/s on 2 cores) infeasible; P-W3 100k connections from one host need several source IPs and spare load-generator cores; memory: RSS slope at 10k/50k/100k connections after forced GC with documented runtime settings; Java measured nowhere.
P3 (major). Idle budgets omit what real connections carry: §5.1 copies the full request head at the 101 (browser upgrades with cookies 0.5-4 KB, can exceed 2.5 KB alone); TLS keys ~1 KB/connection; h2 4 KiB HPACK ring. Fix: copy only header names the route reads (header("...") literals); drop the copy for subscribed-only streams; separate targets for TLS and h2; benchmark with browser-like headers.
P4 (major). Lock and syscall churn per streamed chunk: __co_wait re-takes the store lock eagerly after each wait (store-writing LLM proxy takes the global exclusive lock + pin publish/withdraw per token); epoll_ctl ADD and DEL per wait. Fix: end the store unit of work at the loop head and re-take the lock lazily; keep stream fds registered with EPOLLET; add a P-S2 variant whose route writes store.
P5 (major). RSA signing (1.2 ms) runs in the event loop and stalls every connection on that thread. Fix: sign in a yieldable job or small thread pool; cap handshake CPU per loop turn.
P6 (minor). 100k WebSockets with 20 s ping ~1-2% of a core, above the <= 1% gate: 30 s default or a per-ping budget.

## Runtime mechanisms
R1 (major). SSE resume with several channels replays the wrong one (§4.5): id epoch.seq with per-channel seq; one Last-Event-ID for two channels. Fix: epoch.chanhash.seq; replay only the matching channel.
R2 (major). `send` never waits under the store lock -> large exports fail (`for u in users.values() { send(u) }` overflows 16 MiB and closes as a slow client; works in tests, fails in production). Fix: with M3, send under the lock waits through the audited __co_wait window like fetch.
R3 (major). Where a message loop may appear and what may stay live across a park is undefined: hidden iterator temporaries of an enclosing for are not copied; a message loop inside `for o in sql` or `for x in fetch` holds a pool connection/socket across hour-long parks; MongoCursor, BsonBuilder (banned from store, src/api.kh:557) and Buf would be deep-copied or grown into item memory by library code without a barrier. Fix: error — a loop over a stream parameter must be at the top level of the route body; error banning these library types across the loop (reuse store_raw_type).
R4 (minor/major, over-engineering). The keep heap with exact tree frees (~650 lines + forced deep copies). Simpler: per-owner bump region with copying compaction at item end or park, rooted at the outer variables (compiler knows them), using __deep_copy with forwarding; values already in the region stay shared; no deferred-free lists. Or reuse the store heap's span allocator.
R5 (major). No process-wide memory budget: per-owner caps (4 MiB per input message, 16 MiB output per stream, 64 MiB state per connection, h2 bodies 128 x 4 MiB per connection) multiply with connections. Fix: global budgets with shedding and metrics; much lower per-connection defaults.
R6 (major, process). The riskiest parts (keep semantics, park/resume on another coroutine) arrive at steps 8 and 11 but KHRIP.md promises them at step 6. Fix: a spike before step 6 under GC verify and stress.
R7. Design the generalised barrier together with GC step 6 SATB barriers; link keep cases only into programs with stream loops.
R8. §7.4 "the mark narrows publication" is unsafe for non-message loops: arena memory below the mark can hold store pointers.
R9. The test scheduler's coroutines leave the test's own frames unpublished: needs a new audited release site.
R10. Write the eventfd right after the channel lock is released (not at the publisher's next store-lock release); a "growing" MPSC ring under concurrent producers must be a segmented queue.

## Security
S1 (major). Slow request bodies become a DoS regression: today the body is buffered in the event loop before a coroutine is taken (lib/http.kh:423, :432); the design hands out the coroutine at end of head and only checks "no byte for 10 s"; 1 byte per 9 s pins a coroutine and arena slot; 4,096 clients per thread (32,703 per process) stop the server. Fix: buffer bodies of 16-64 KiB in the event loop as today; larger bodies require a minimum data rate (Kestrel: 240 B/s after 5 s grace); cap coroutines waiting for body bytes.
S2 (major). HTTP/2 resource gaps: windows refilled on append (one connection can buffer 512 MiB); each stream takes a coroutine and stream parameters dispatch at HEADERS (256 connections exhaust arena slots) — cap coroutines per connection; MadeYouReset (CVE-2025-8671) server-sent resets must count in the reset budget; "100 resets/s" will GOAWAY an Envoy connection aggregating many users; data dribble (CVE-2019-9511) tiny window updates; RFC 9113 §8.2.1 field value rules (NUL, CR, LF, edge whitespace) missing; __fetch writes header values verbatim (lib/fetch.kh:868), so an h2 header forwarded through fetch can split the upstream request — validate in h2 and inside fetch.
S3 (major). KHRIP_CORS=* reopens cross-site WebSocket hijacking (browsers send cookies on WS handshakes). Fix: * does not apply to WebSocket; compare scheme, host and port.
S4 (major). gRPC stubs pass upstream errors through (upstream UNAUTHENTICATED/PERMISSION_DENIED -> our 401/403). Fix: NOT_FOUND -> 404, UNAVAILABLE -> 503, DEADLINE_EXCEEDED -> 504, everything else -> 502; log upstream code and message.
S5 (minor). The 502 leaks 200 chars of the upstream body (R-F1): log it instead.
S6 (major). Constant-time claim has holes: ECDHE P-256 uses __ecdh_shared -> __pt_mul, which branches on each secret bit (lib/pk.kh:603) — needs a constant-time variable-base multiply; AES key expansion indexes the S-box with key bytes (cipher.kh:24-45) — use AESKEYGENASSIST; dudect is weak — add ctgrind (Valgrind with secrets marked undefined) or a compiler secret mode; transcribe fiat-crypto field code instead of writing from scratch; RFC 6979 KATs need an unhedged test mode.
S7 handshake floods: per-thread handshake CPU budget and per-IP concurrency limits. S8 grpc-timeout uncapped: min(client deadline, server cap). S9 reflection on by default on the public port. S10 failed cert/key reload never retried (mtimes already seen); zero PEM text from environment variables. S11 WebSocket PING floods and 1-byte fragments have no budget; coalesce PONGs.

## Scope and order
O1 (major). Order by risk: crypto (steps 14-18) gates h2 and gRPC for no technical reason (h2c and HPACK need no TLS; most gRPC is h2c behind a mesh/LB; Connect/gRPC-Web work over HTTP/1.1). Proposed: A and B; HPACK and h2c server (19-20); gRPC (22-25) plus Connect and gRPC-Web over h1; TLS server (14-18); h2 client and stubs (21, 26). Versions: v0.14 = A+B, v0.15 = h2c+gRPC, v0.16 = TLS + h2 client.
O2 (major). Rule 1 and rule 2 are already failed elsewhere and this plan delays the fixes: interim report — catalog C# 24,754 vs Khrip 12,814 req/s; bookings C# 18,785 vs 14,044; peak memory vs Go: patch 238.7 MB vs 14.5 MB, notes 125 MB vs 55 MB (fixed by codegen v0.15 and the GC, pushed back by this plan). The blind eval (v0.16) is the only independent test of rule 2 and is delayed four stages. Fix: run the blind eval before stage C; do the codegen work before stage D.
O3 (minor). Cut or defer: ChaCha20 AVX2; VAES path; gRPC-Web text mode; reflection v1alpha; session tickets; streamed JSON-array response; RSA-PSS signing as a later step after ECDSA.
O5 (minor). +200 KB per binary is fine (unused pages of a static non-PIE binary are never loaded: no RSS or startup cost), but a --no-tls build must refuse to start when TLS_CERT is set.

## Consistency
C2. "Route return -> close 1000" (§5.4) contradicts "stays open while subscribed" (§2.3).
C3. Streamed JSON arrays: Accept: application/json (axios, many SDKs) on an endless stream never completes; drop the format or refuse it for subscribing routes; add Vary: Accept.
C4. SSE `event: error` triggers EventSource onerror and reconnect, so fail(403) after the head loops every ~3 s; use another event name plus a long retry:.
C5. Undefined: GET to a WebSocket route without Upgrade (426); a GET stream parameter with a non-stream result; push-only WebSockets silently discarding client messages (use 1003); call on a route that subscribes.
C6. 409 -> ALREADY_EXISTS mislabels version conflicts and CHECK violations: map sql errors by SQLSTATE; Connect HTTP statuses must follow Connect's table (failed_precondition -> 400).
C7. Upstream EOF before the chunked terminator must give 502 or an error event (no silent truncation); handle upstream SSE event: error.
C8. Kubernetes: 5 s lame duck + 25 s drain + 1 s unwind exceeds the default 30 s grace, so the final KHRIP_DATA save is SIGKILLed; default drain 20 s.
C9. RFC 9112 §3.2.2: servers MUST accept absolute-form requests; accept-and-close at EMFILE needs a reserved fd.
C10. Proto file named app.proto / <main>.proto / shop.proto in different places; §4.2 says 60 s, R-Q1 30 s; log "topics are per process" always; khc -o must not silently create a missing .proto; adding a parameter to a single-struct rpc is breaking (GRPC.md); int32 encoding in stubs needs a range check.
C11. Interactive "stop" over WebSocket impossible (messages handled one at a time): document; recommend SSE + POST.

## Strengths (keep)
Evidence compiles and reproduces; memory measurements real; `-> stream T` with real statuses before the head and cancellation on disconnect; topics ordered with store, serialized once, per-thread fan-out, loud slow-client disconnects; defaults (timeouts, smuggling rules, origin check, no permessage-deflate, no 0-RTT, no h2c Upgrade, no TLS 1.2); gRPC field-number lock with breaking-change errors, enum 0 = UNSPECIFIED; HTTP/3 decision with triggers; standard conformance suites per step; candid silent-spot table.

## Verdict
Direction right; not ready as written. Stages A and B can proceed after B1-B3, M3, M5, R1-R3, S1, P4 and a memory-model spike before step 6. Stages C and D need re-ordering (O1), crypto at OpenSSL parity (P1), HTTP/2 DoS fixes (S2, R5). Rule 2 claims need SDK and TypeScript competitors (M1) and KHRIP.md additions trimmed to ~480 (M2). Rule 1 claims need a sound benchmark method (P2) and Java measured.
