## 1. Semantics: the contract for user code

### 1.1 Model

A `str` is an immutable byte sequence, normally UTF-8.

**Segmentation (Go's rule).** Starting at byte 0, at each position *q*:
- if bytes *q…* form a well-formed sequence of width *w* (Table 3-7: no overlongs, no surrogates, nothing above U+10FFFF), that is one character of width *w*;
- otherwise byte *q* alone is one character, whose value is U+FFFD.

Boundaries are 0, *n* and every step end. For example, `"\xFF\xFE".len()` is 2, `"\xE2\x82".len()` is 2, and `"À\x80"` is `À` followed by one U+FFFD.

**Properties the implementation relies on**, each proved in §3 and checked by property tests:
- **P1.** Every non-continuation byte (not `10xxxxxx`) is a boundary.
- **P2 (slice stability).** For boundaries *x < y*, segmenting `s[x..y)` on its own gives exactly the boundaries of `s` inside *[x, y]*.
- **P3 (valid regions).** If `[x, y)` is well-formed and *x* is a boundary, the boundaries in *[x, y]* are exactly the non-continuation positions plus *y*. Inside valid text, fast lead-byte counting is exact.
- **P4.** A match of a well-formed, non-empty needle starts and ends on boundaries. Byte search therefore finds character positions.

**Invariants for user operations** (property-tested, §8):
1. `s[..k] + s[k..] == s` for every *k*.
2. `s.len()` equals the number of `for c in s` iterations, and the concatenation of all `c` is `s`.
3. `s[i] == s[i..i + 1]` for `0 ≤ i < len`.
4. `s[a..b].len() == clamp(b) - clamp(a)`.
5. If `s.find(x) == some i`, then `s[i..].starts_with(x)` (for well-formed `x`).
6. Slices never split a well-formed character.
7. `s.lower().len() == s.len()`.

### 1.3 Character literals

In user files the lexer produces `T_CHAR` holding one code point (§5.2). In system files it produces `T_INT`, which must be ASCII; this is identical to v0.12. The type of a `T_CHAR` comes from `want`:

| Context | Result |
|---|---|
| `str` or `str?` expected: argument, return, `let x: str`, `+=` to a str, right operand of `==`/`<`/… after a str left operand, right operand of `+` after a str, `match` arm with a str scrutinee, element of `[str]`, map key/value of str type, field of str type, default parameter of type str | interned one-character `str` literal |
| `int`, `int?` or `float` expected, including `x == 'a'` with an int `x`, `s.byte(i) == '\n'`, and the right operand of `- * / % & \| ^ << >>` after an int | `int` code point (`'я'` is 1103) |
| Nothing expected | `int` if the next token is one of `- * / % & \| ^ << >>`; otherwise `str` (`let sep = ','`, `'a' + 'b'` is `"ab"`, `'a'.upper()`, `print('A')` prints `A`) |

With this rule, the idioms of Python, Go, C# and JS all compile and behave correctly:
- `c == 'a'`, `c >= 'a' && c <= 'z'`, `out += c`, `"{c}"`;
- `c.upper()`, `s.split(',')`, `s[0] == "a"`, `s[i] == 'x'`.

Arithmetic on a `str` character (`c - '0'`) is a compile error with the hint `c.to_int() ?? 0`. There is no silent int/str confusion: `c.to_str()` is the character itself, never `"97"`.

## 3. Representation and invariants

- **Header.** `[h] ptr, [h+8] nbytes`, unchanged. Every v0.12 reader of `[h+8]` (`expr.kh:313` bounds check, `atom.kh:878/1545/1697`, `stmt.kh` for-loop bound, boot, `api.kh:146`, `core.kh:1677`, the 32 `__str_len` callers) keeps its meaning: bytes.
- **I1 (immutability).** The bytes under a reachable header never change. Memory that held string bytes is reused only:
  - **(a)** by `__arena_end` zeroing, where the cache dies with the arena;
  - **(b)** by the `__call` rewind (`lib/api.kh:1434-1442`), after which the cache is cleared;
  - **(c)** by the store GC freeing or reusing STORE or HEAP, which bumps `__store_epoch` (§6).

  `x509.kh`/`db.kh` swap `CTX_PTR` to fresh heap and restore it; that is not a rewind. A future rewind must call `__strc_clear()`; this rule is written next to `CTX_PTR` in `core.kh`. All lib producers were audited:
  - `buf_str` copies;
  - fetch, pg and url-decode views point into fresh per-call `buf_new` arena buffers;
  - HTTP request fields point into the connection buffer, which is not touched until the request ends.
- **I2.** Cache entries hold only integers relative to `ptr` (counts, offsets) plus the arena address of a stride index. Keys are compared, never dereferenced.
- **Proofs of P1–P4** (§1.1):
  - **P1**: a Go step at *q* either consumes a well-formed sequence, whose interior bytes are all continuations, or one byte. A non-continuation byte is therefore never inside a step.
  - **P2**: a step at *q < y* depends only on bytes *q…q+3*. If the step is well-formed in `s`, it ends at or before *y* (because *y* is a boundary), and the same bytes are present in the substring. If it is ill-formed in `s`, truncating the bytes cannot make it well-formed.
  - **P3**: inside a well-formed region every step is a complete sequence, which starts at a lead byte.
  - **P4**: the needle starts with a non-continuation byte (P1). Its last character is well-formed in `s` at the same bytes, so the Go step there ends exactly at the end of the match.

## 4. Runtime

### 4.1 SIMD primitives (`src/simd.kh`; lib-only builtins in `atom.kh:parse_builtin`)

Convention:
- `rdi` = p, `rsi` = n, `rdx` = k; result in `rax`.
- They clobber only `rax rcx rdx rsi rdi r8–r11 ymm0–ymm15`. Khrip keeps no value live in vector registers across calls (`src/float.kh` uses `xmm0/xmm1` as temporaries only).
- They make no calls.
- Dispatch uses `__simd_level`: 2 = AVX2; 1 and 0 = SWAR/scalar (D0: SWAR is within 3–4× of AVX2 here, so there is no separate SSE2 path).

**`__simd_utf8_scan(p, n) -> int`** returns the number of code points if `[p, p+n)` is well-formed, else −1.
- **Source:** `utf8-final/scan3.asm` (new). It is Keiser–Lemire "lookup" with D0's verified tables `T1 T2 T3 MAXV`, plus continuation counting `vpcmpgtb ymm9, ymm10(0xC0×32), ymm0` → `vpmovmskb` → `popcnt` on non-ASCII blocks.
- **Tail:** the last 0–31 bytes are one 32-byte load when `(p+m) & 4095 ≤ 4064`, masked with `vpand [MASKT + 32 − r]`. `MASKT` is 32×FF followed by 32×00. Otherwise the tail is copied with overlapping moves into a zeroed 32-byte stack block. If r = 0 there is **no load** (a zero block); this bug was found and fixed during verification. The zero padding turns the "unfinished character at the end" check into the ordinary TOO_SHORT check.
- **Constants** come from DATA (`vmovdqu [abs32]`, like `emit_level_cmp`).
- **Fallback:** an 8-byte ASCII SWAR skip, then D0's `VALID_SCALAR` with counting.
- **Verified:** 125,962,506 cases, 0 mismatches:
  - 4M random cases (lengths 0–199; at page end, page start or mid-page; random bytes, multilingual text, single corruptions);
  - every 3-byte value at offsets 0, 7, 14, 21, 28–39;
  - every F0–F4 lead × continuation × all third bytes × sampled fourth bytes at offsets 28–32.

| `scan` (ns) | 8 B | 16–20 B | 31 B | 180 B | 1 KB | 64 KB |
|---|---|---|---|---|---|---|
| ASCII | 3.3 | 3.2–3.5 | 3.6 | 8.5 | 38 | 1,460 |
| Cyrillic | 4.2 | 4.1 | 5.0 | 22–25 | 91–131 | 5,400–6,800 |
| CJK | 6.8 | 6.3 | 7.3 | 16 | 85 | 5,800 |
| D0 valid+count, Cyrillic, for comparison | 9.9 | 19.5–24 | 48.7 | 53 | 176 | 11,900 |

**`__simd_utf8_skip(p, n, k) -> int`** returns the byte offset of the k-th lead-rule character, or n.
- It is D0's `kh_skip_avx2` / `kh_skip_swar`, verified on 9M random cases and re-run by judges.
- Exact on well-formed regions (P3).
- Timing: about 4 ns to the middle of 200 B, 20 ns of 1 KB, 65 ns of 4 KB, 0.6–2.9 µs of 64 KB, 11.5 µs of 1 MB.

**`__simd_find_json_hi(p, n) -> int`** is a copy of `emit_simd_find_json` that also ORs the raw high-bit mask:
- AVX: `vpmovmskb r8d, ymm0; or r9d, r8d` per block. In the hit block the mask is first limited to bytes before the stop: `lea r10,[rcx-1]; xor r10,rcx; and r8d,r10d`.
- Scalar: `cmp ecx,0x80`.
- Returns `index | (hi << 62)`.
- The existing `__simd_find_json` stays for other callers.

`emit_hex` bytes are taken from `objdump -d` of `scan3.o` and `utf8.o`. Code size: scan ≈ 420 B + 352 B of tables, skip ≈ 134 B, fallbacks ≈ 400 B. They are emitted only when reachable.

### 4.2 `lib/core.kh` (boot-compiled: plain loads, stores and loops; must not call `text.kh`)

**Byte API**, all with v0.12 semantics:
- `__str_byte_len(s)`;
- `__str_byte(s, i)`, which exists already;
- `__str_byte_slice(s, a, b)`, which calls the unchanged `__str_slice`. It remains the internal byte slice used by `__str_split` and others, and boot's slice codegen;
- `__str_byte_find(s, sub) -> int?` (renamed from `__str_find`);
- `__str_byte_find_from` (renamed from `__str_find_from`);
- `__str_ascii_lower`, `__str_ascii_upper` (renamed; SWAR `__str_case`);
- `__str_ascii_trim` (renamed; SP HT CR LF).

`__str_split`, `__str_replace`, `__str_contains`, `__str_eq`, `__str_cmp` and `__str_len` (bytes) keep their names and code.

**Scalar UTF-8** (boot-compatible; used by the lexer and as fallbacks):
- `__utf8_width(p, n, i) -> int`: Go-rule width, 1–4;
- `__utf8_decode(p, n, i) -> int`: code point, or 0xFFFD;
- `__utf8_bad_at(p, n) -> int`: first ill-formed offset, or n. It skips 8 ASCII bytes at a time; when masking after `>>`, it must use `((x & ~(x << 1) & H) >> 7) & L8` (D1's arithmetic-shift pitfall);
- `__utf8_go_count(p, n)`, `__utf8_go_skip(p, n, k)`;
- `buf_utf8(b, cp)`, moved from `api.kh:__buf_utf8`.

**Arena and context:**
- `CTX_SIZE` 256 → 4096 (`__thread_init` already maps a page). New constants: `CTX_STRC = 1024`, `STRC_SIZE = 640`.
- `__arena_begin`: after setting `CTX_PTR`, `let blk = __alloc(STRC_SIZE)`. This is always the arena base, and it commits pages when the arena is not pre-committed. Then `store64(blk, __store_epoch)`. `__arena_end` already zeroes `[base, CTX_PTR)`, so the cache dies with the arena (memset +640 B ≈ 10 ns per request).
- `fn __strc_clear()`: if in an arena, `memset(base + 8, 0, STRC_SIZE − 8)`. Called by `__call` after its rewind.
- `var __store_epoch: int`, which the store GC increments (§6).
- `fn __alloc_trim(p, old, new)`: if `CTX_PTR == p + round16(old)`, set `CTX_PTR = p + round16(new)`. The returned tail was never written, so it is still zero.

### 4.3 The string cache (`lib/text.kh`)

**Location.** `fn __strc() -> int` returns the cache block, or 0:
```
c = __ctx(); a = load64(c + CTX_ARENA)
if a != 0 { d = load64(c + CTX_PTR) - a; if d < 0 || d >= ARENA_SIZE { return 0 }; b = a }   // store mode or heap swap: no cache
else { b = c + CTX_STRC }                       // no arena: fn main, __init_globals, restore — per thread, single owner
if load64(b) != __store_epoch { memset(b, 0, STRC_SIZE); store64(b, __store_epoch) }
return b
```
Coroutines never run user code without an arena. The thread block is beyond `CTX_CO_END`, so it is never swapped.

**Layout** (structure of arrays, 8 entries; all-zero means empty):

| Bytes | Field |
|---|---|
| [0] | epoch |
| [8] | clock |
| [16..64) | spare |
| [64 + 8e] | `kp`: key byte address (`ptr`); 0 = free |
| [128 + 8e] | `kn`: key byte length |
| [192 + 8e] | `cnt1`: Go-rule character count + 1; 0 = unknown |
| [256 + 8e] | `vup`: `[0, vup)` known well-formed, and `vup` is a boundary |
| [320 + 8e] | `ck`: cursor character index |
| [384 + 8e] | `cb`: cursor byte offset (a boundary) |
| [448 + 8e] | `ix`: stride index (u64 offsets of characters 0, 64, 128, …) or 0 |
| [512 + 8e] | `use`: LRU stamp |
| [576 + 8e] | `far`: count of far jumps |

**Policy:**
- Only strings with `nbytes > STRC_MIN = 256` are cached.
- At most 2 entries per key (enough for two-pointer use). Up to 8 entries in total; LRU replacement.
- A facts memo (block word [48]) survives eviction. It is a 64-place, 2-way table of `(kp, kn, cnt1, vup, ix, far)`, allocated in the block's region at the first far jump. It is written on far jumps and index builds and read when a key gets a new entry. Without it, a long string that is evicted between uses, for example 9 or more strings in rotation or one long string among 8 others, would recount, reindex and leak a new index on every return. A drop also forgets the key in the memo.
- Facts (`cnt1`, `vup`, `ix`, `far`) are written to every entry of the key.
- Writes go in this order: the key is zeroed first and written last, so a recovered panic can never leave a half-entry looking valid.

**Defensive check on every use.** `0 ≤ cb ≤ n`, and if `cb < vup`, `byte[cb]` is not `10xxxxxx`. On failure the entry is dropped; under `KHRIP_STRCACHE=stress` it panics `internal: string cache`. A missed invalidation can therefore never read out of bounds.

**Seek** (the one routine behind index, slice and find): `__strc_off(b, p, n, k) -> off`.
1. If `cnt == n && vup == n` (known ASCII), return `min(k, n)`.
2. Candidate anchors:
   - `(0, 0)`;
   - `(cnt, n)` if the count is known and `vup == n`;
   - each cursor of the key;
   - stride point `(k & ~63, ix[k >> 6])` if indexed.

   Cost: forward = `k − ak`; backward = `8·(ak − k)`, allowed only when `ab ≤ vup`.
3. If the best cost is above 256, `n ≥ 4096` and the key's `far` reaches 2, then: scan the whole string (count and validity), build the index, and choose again. The index is built only on the second far jump, so entries that are being evicted never pay O(n) repeatedly.
4. **Forward:**
   ```
   off = ab + skip(p+ab, n−ab, k−ak)
   if off > vup:
       c = scan(p+ab, off−ab)
       if c >= 0 { if ab <= vup { vup = off } }        // P3: lead rule exact
       else { off = ab + __utf8_go_skip(p+ab, n−ab, k−ak) }
   ```
   **Backward:** step back over continuation bytes, `ak − k` times.
5. **Cursor update:**
   - if the anchor was a cursor of this key, move it to `(k, off)`;
   - otherwise use the key's second free slot or its older entry;
   - **only if `off < n`**, because skip cannot tell "k = count" from "k > count".
6. `use = ++clock`.

**Index build:**
- Valid string: `off += skip(p+off, n−off, 64)` per stride.
- Invalid string: Go walk.
- It allocates `8·(cnt/64 + 1)` bytes with `__alloc`, only when `__strc()` returned a block (arena or thread). For 1 MB of Cyrillic that is about 76 KB and 100 µs, once.

**Count:** `cnt` if known; otherwise `scan(p, n)`, then:
- if valid: `cnt = c`, `vup = n`;
- else: `cnt = go_count`.

**`KHRIP_STRCACHE`** is read in `__simd_init` into `__strc_mode`:
- `off`: `__strc()` returns 0;
- `stress`: `STRC_MIN = 0`, 1 entry, index threshold 0, `far ≥ 1`, defensive checks panic.

Tests run in all three modes and must print identical output (§8).

A debug counter `__strc_scanned()` sums the bytes passed to skip, scan and Go walks. Quadratic guards assert on it, so they are deterministic.

### 4.4 `lib/text.kh`: user-semantics operations

The compiler resolves a str method `m` in **user** code to `__text_m` if it exists, else `__str_m`. For index, slice, `len` and `for` it emits a direct call (never inlined). The functions:

| Function | Algorithm |
|---|---|
| `__utf8_scan(p, n)`, `__utf8_skip(p, n, k)` | wrappers over the builtins (never inlined: `decl.kh:can_inline` refuses `__simd_*` callers) |

| `__text_lower(s)`, `__text_upper(s)` | **Phase 1** finds the first character that changes. 8-byte all-ASCII words use `__case4`, as in v0.12; other characters are decoded and mapped. | `__case_map(cp, up) -> int` | 1. ASCII arithmetic.<br>2. U+0400–045F arithmetic: lower `0410–042F +0x20`, `0400–040F +0x50`; upper `0430–044F −0x20`, `0450–045F −0x50`.<br>3. `cp ≥ 0x1E980` → `cp`.<br>4. Two-level table (§4.5): `pi = s2[s1[cp>>6]·64 + (cp&63)]`; `pi == 0` → `cp`; else `cp + pal[pi].d(up)`.<br>The signed 32-bit load is `(load64(a) << 32) >> 32` (arithmetic shift; the palette is padded by 4 bytes). |
| `__cp_is_space(cp)` | the 25 White_Space code points, hard-coded |

**`__perm_alloc(n)`** (in `lib/rt.kh`) is process-lifetime memory for immutable data:
- a bump allocator over 64 KB `__mmap` chunks (direct `__mmap` when `n ≥ 16 KB`);
- guarded by the futex mutex word `__store_rw + 48`;
- it **never swaps `CTX_PTR`**, so a panic cannot leave the allocator redirected.

### 4.5 Unicode tables (`lib/text_tables.kh`, generated)

- **Generator:** `tools/unicode_tables.kh`, a Khrip program. It reads `UnicodeData.txt` (general category and simple mappings, fields 12/13) and `PropList.txt` (White_Space) from **UCD 17.0.0**, given by path. The output header records the version and the sha256 of each input. The build stays Khrip-only, and the generator is not run by `build.sh`.
- **Builtin `__data_hex("…") -> int`** is lib-only (next to `__db_root`, `atom.kh:1196`). It decodes a hex literal at compile time into 8-aligned DATA and returns the address; the hex text itself is not emitted. There is no runtime decode and no init race.
  ```
  fn __case_tab() -> int { return __data_hex("…") }   // s1 @0 (u8 × 1958, cp>>6 < 0x1E980), s2 @1958 (66 × 64 u8), pal @6182 (179 × {i32 dlower, i32 dupper}) + 4 B pad
  fn __word_tab() -> int { return __data_hex("…") }   // s1 @0 (u8 × 1608, cp>>7 < 0x32400), s2 (193 × 16-byte bitmaps)
  ```
- **Sizes** (computed with Go's Unicode 15.0 tables, `utf8-ergo/gen`, `utf8-final/wgen`; UCD 17 will differ by a few hundred bytes):

  | Table | Size | Notes |
  |---|---|---|
  | case | **7,614 B** | 1,433 lower / 1,450 upper mappings; 20 grow and 36 shrink in UTF-8 |
  | `\w` | **4,696 B** | 139,244 code points; 765 ranges |
  | White_Space | in code | 7 R16 ranges |

- **Regeneration check:** `tools/unicode_check.sh` (manual, not CI) compares the generated maps with Python `unicodedata` and Go `unicode` for code points whose properties are the same in all three versions.

### 4.6 Regex (`lib/regex.kh`)

**Pattern and nodes:**
- The pattern is decoded once into `[int]` code points. Positions in error messages are character indices.
- `RX_LIT` holds a code point, so `я+` repeats `я`.

**Program and classes:**
- Instructions: `RI_BYTE` → `RI_CHAR cp`; `RI_ANY`; `RI_CLASS k`.
- A class is:
  - a 2-word ASCII bitmap;
  - a sorted, merged list of `[lo, hi]` ranges ≥ 0x80 (the `\s` ranges are expanded inline);
  - flags `W` (non-ASCII `\w`), `NW` (`\W`), `NS` (`\S`), `ND` (`\D`) and negation.
- Match for `c ≥ 128`: binary search, OR `__cp_is_word` per flag, XOR negation.

**Run (`__rx_run`):**
- Steps per character: a byte < 0x80 costs a load and a compare, as today; otherwise the Go decode.
- An ill-formed byte is U+FFFD, matched by `.`, `\W`, `\S`, `\D` and negated classes.
- `{n,m}` counts characters. The run stays linear.

**Per-site cache:**
- `s.matches(<literal or const>)` gets an 8-byte zero DATA slot and compiles to `__text_matches_at(s, pat, slot)`.
- `load64(slot) != 0` → run the frozen program.
- Otherwise:
  1. `__rx_compile` in the **arena** (a panic here is an ordinary 500);
  2. `__rx_freeze(r)` copies only run-time data into one `__perm_alloc` block. The struct is `__RxProg {op, x, y, cmask, cflags, cstart, ranges}`, with list headers built in place;
  3. `__cas(slot, 0, prog)`; the loser drops its copy.
- Run state (`mark`, `cur`, `next`) stays per call in the arena.
- Non-literal patterns compile per call, as today.
- Expected: e-mail `[^@\s]+@[^@\s]+` drops from 4.6–17.6 µs to about 1.3 µs (D2 measured compile against run); the large pattern drops from 21–90 µs to about 2 µs.
- **Compile-time check:** §5.8.

### 4.7 JSON and HTTP (`lib/api.kh`, `lib/http.kh`, `lib/rt.kh`)

**`__find_json_hi(p, n)`** (rt.kh) is a wrapper over `__simd_find_json_hi`.

**`__Json`** gains `lenient: bool` and `replaced: int`. **`__json_decode`** skips a leading BOM.

**`__jd_str`:**
- **No-escape path:** `k = __find_json_hi(j.p, end − j.p)`. On the closing quote: if `hi` and `scan(start, len) < 0`, then strict → `__jd_fail(j, at, "invalid UTF-8")`, lenient → `__utf8_sanitize` and `replaced += …`.
- **Escape path:** OR together the `hi` of the raw segments. At the end, if `hi`, validate the **whole output buffer**. This catches a lead byte cut off by an escape. Escapes always produce well-formed bytes.
- **`\u` handling:**
  ```
  cp = hex4; cp < 0 → fail "bad \u escape"
  if D800 ≤ cp < DC00:
      if next is "\u" and hex4 = lo:
          lo in DC00..DFFF → combine
          lo < 0           → fail "bad \u escape"
          else             → strict: fail "unpaired surrogate \uD800"; lenient: FFFD, j.p back to that "\u"
      else → strict: fail; lenient: FFFD
  elif DC00 ≤ cp < E000 → strict: fail "unpaired surrogate \uDC00"; lenient: FFFD
  else buf_utf8(cp)
  ```

**`__json_str` (encode):** remember `b.len`, encode with `__find_json_hi` while OR-ing `hi`. At the end, if `hi` and `scan(p, n) < 0`, roll back `b.len` and re-encode through `__utf8_sanitize`.

**`__jd_found`:** 12 characters, cut at a boundary, sanitised.

**`lib/http.kh:281`:** `text/plain; charset=utf-8`.

**`__load_store` / generated `__store_restore`:** use `__from_json_lenient` and print the replaced count once.

### 5.7 Diagnostics (`src/diag.kh`)

- **`print_diags`:** column = number of characters in the line prefix (count of non-continuation bytes) + 1. The caret gets one space or tab per character. `--json` `col` is the same character column, and the `--json` notes say so. Example: `let s = "мир"; let x: int = "a"` reports col 33, not 36.
  - *As built (step H):* tokens keep byte columns; `print_diags` converts them when printing (`char_col`, Go segmentation of the line prefix, so a byte inside a character belongs to that character). The runtime SQL site location (`file:line:col`) uses the same column.
  - *Wide characters:* the caret line follows `wcwidth`: a tab is copied, East_Asian_Width W/F characters (CJK, kana, Hangul, fullwidth forms, emoji; a 123-range table from EastAsianWidth.txt 17.0.0 in `diag.kh`) get two spaces, combining marks (the main combining blocks), ZWSP/ZWJ/WJ, BOM and variation selectors get none, everything else one. Multi-code-point emoji (skin tones, ZWJ sequences) count as the sum of their parts; terminals that merge them show the caret further right.
- **`json_escape`:** escapes all control characters as `\u00XX`, passes valid UTF-8 and writes `\ufffd` for invalid bytes. `--json` is always valid JSON.
  - *As built:* `\n` and `\t` keep their short forms; `tests/run.sh` checks with python3 that `--json` of every `tests/errors` case, and of a file with `"`, `\\`, a tab and 0xFF in its name and invalid bytes in its text, is valid UTF-8 JSON with the same places and messages as the text output.
- **Characters outside ASCII in code** (`lex.kh:lex_non_ascii`): the whole character and its code, e.g. `identifiers use ASCII letters, digits and _; found 'п' (U+043F)`. Look-alikes of Khrip tokens get `use the ASCII X instead` (`“ ” « »` → `"`, `‘ ’` → `'`, dashes and U+2212 → `-`, `× ÷ ≤ ≥ ≠ → ⇒ …`, fullwidth forms U+FF01–FF5E); special spaces get `use a plain space instead`; ZWSP/ZWJ/WJ/BOM are `unexpected invisible character U+200B`; punctuation, symbols and emoji are `unexpected character '😀' (U+1F600)`; an invalid byte repeats `file is not valid UTF-8: byte 0xFF`; an ASCII control character is `unexpected control character U+0001`.
- **User functions named like str methods** (`atom.kh:str_method_clash`, called from `decl.kh:prescan_fn`): a user `fn` whose name is a built-in str method (`str_method_args`: `len byte_len byte byte_slice byte_find byte_find_from ascii_* contains starts_with ends_with find find_from trim lower upper split replace repeat to_int to_float to_str matches`) and whose first parameter accepts a `str` is an error at the declaration: `fn trim clashes with the built-in str method trim`, hint `rename it: s.trim() calls the built-in, never a function that takes str first`. This replaces the call-site `byte_api_shadow` check. In user code the same list now bounds str method dispatch: other `__str_*` library helpers (`__str_slice`, `__str_case`, ...) are no longer reachable as methods, so `s.slice(a, b)` calls the program's own `fn slice`, and without one it is `str has no method 'slice'` (hint `use s[from..to]`).
- **`method_hint`:** §1.4.

### 5.8 Compile-time regex check (`src/rx.kh`, new; no boot change)

- `fn rx_check(pat: str) -> RxErr` mirrors the `lib/regex.kh` grammar: literals, `.`, classes with ranges and escapes, `\d \w \s \D \W \S`, escaped metacharacters, `( )`, `|`, `* + ? {n} {n,} {n,m}`, `^` at the start and `$` at the end.

  - `(?i)` → `compare s.lower() with a lower-case pattern`;
  - `(?…)`, lookaround → `not supported`;

  - `\1` → `backreferences are not supported`;
  - `\p{L}` → ``use `\w` or list the ranges, e.g. [a-zA-Zа-яА-ЯёЁ]``.

## 6. Contract with the v0.13 store GC (sibling design)

- **No layout change for `str`.** The copier copies `[ptr, ptr+len)` into a fresh `len+1` block with a 16 B header, exactly as today. There is no new invariant on STORE strings.
- **The GC increments `__store_epoch`** (`core.kh` global) once per collection, under the exclusive lock. Every cache, arena or thread, clears itself on its next lookup. This makes the cache independent of the holder protocol: a parked or unlocked request, or main-thread entries from initialisation, can never use a STORE or HEAP key whose memory the GC freed or reused.
- **No cache entry is a GC root.** Keys are integers that are only compared. `ix` points into the arena.
- **Memory the GC must not free:** perm memory (`__perm_alloc`: regex programs, the char table). The GC may copy a header that points into it, like any HEAP header.
- **`CTX_SIZE` is now 4096 with the per-thread block at `CTX_STRC = 1024`.** A GC renumbering of words below `CTX_CO_END` does not interact with it.
- `__deep_copy` (`api.kh:146`) is unchanged.

## 13. Rejected alternatives

- **Header metadata (D1 packed, D2 24 B):** a raw-read hazard, or +7–11% store memory. The cache plus the fused scan give the same complexity.
- **Frame SPC (D0):** stateful single-pass codegen with reset points, and it misses fields and helpers.
- **Per-thread cursor cache (D1):** invalidation depends on convention.
- **`s[i]` as a compile error, or int code points:** costs an iteration, or silent digit printing.
- **Lead-byte rule:** drops valid characters on repair, and needs two rules.
- **Whole-body validation before parsing:** costs on ASCII bodies and gives worse messages than per-field checks.
- **Lenient user `from_json`:** a second rule; strict matches C#, Rust and the "Bad input gets 400" line.
- **ASCII `\w` (D2):** rejects Cyrillic names.
- **Unicode `\d`:** `` `\d+` `` then no longer implies that `to_int` succeeds.
- **A compile-time DATA table of 2,048 characters:** 36 KB in every binary that iterates strings.
- **A separate SSE2 path:** SWAR is within 3–4× of AVX2.
