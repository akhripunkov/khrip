# Khrip v0.13: final design for store garbage collection

This design is built on Design 2 (holders publish pins; precise, non-moving, incremental mark-sweep), which two of the three judges preferred. It adds the parts the judges required from Design 0 and Design 1, and it fixes every defect they found. The judge who preferred Design 0 asked for Design 0's allocator and lazy arena pins combined with Design 2's release discipline and SATB marking; that combination is also what is described here.

Repository state assumed: HEAD `b6c0307`. That commit already makes inlined helpers take the store lock, puts `map.clear()` slots in store memory, makes `Buf` in a `store` type a compile error, and gives `store x: float` a zero value.

I re-ran the size-class simulation: `/tmp/claude-0/-home-user-khrip/c69287a0-5c25-565c-bc10-daebb195400d/scratchpad/v013/design/final-gc/scsim.out`.

## 0. Decisions

| Question | Decision |
|---|---|
| Algorithm | **Non-moving, precise, incremental mark-sweep** over the STORE region. Nothing moves, so these hold by construction: aliasing (`users[2] = users[1]`), in-place mutation seen through old references, resurrection by write-back, and the identity of DATA enum/unit values. |
| Heap | **Size classes in spans** (Go's class table, 16 B to 32 KB; larger objects get their own large spans). **Address-ordered reuse**: the lowest-address partial span of a class first; a new span from the **lowest-address free page run**. Simulated footprint/(live+headroom): 1.04 at 1 MB live, 1.03 at 16 MB live. In the grow-then-shrink run, resident memory falls from 46 MB to 6 MB after sweep. |
| Object metadata | No headers. Side bitmaps at fixed addresses: **start** (1 bit per 16 B), **mark** (1 bit per 16 B), **ptr** (1 bit per 8 B word, set for pointer words of scan objects). Plus a pagemap and span table. About 4% of committed store. |
| Precision | **Ptrbits** are written at allocation, from the type where it is known and "all words" otherwise. Marking never needs a descriptor, so type-erased library code can shade values. Roots and the heap are precise. Pins are conservative for the **first hop only**. |
| Holders (requests, tasks and tests that hold store pointers without the lock) | **The holder publishes at every lock release that is not its last.** It copies, eagerly, the STORE-range words of its callee-saved registers, live stack, ctx words, `__Worker` object and jump buffers. Its **arena range is recorded and scanned lazily**, only if a cycle overlaps the window, with a CAS hand-off if the holder resumes first. Pins are withdrawn on the next acquisition. Every release goes through one API. |
| Marking | Runs on a **GC thread**. The cycle start takes the exclusive lock (about 20 µs). **Marking, termination and sweep slices take only the writers' mutex `rw[0]`**, so read-only routes keep running. Slices last at most 200 µs; duty is 25%, rising to 50% or 100% under pressure. **SATB deletion barrier** with allocate-black. Large arrays are scanned in chunks, with a **partial-array rule** for every in-library shift or permutation. |
| Sweep | Lazy, in address order, in slices under `rw[0]`. A span becomes allocatable only after it is swept. The next cycle starts only after the sweep ends. |
| Memory return | A scavenger releases free pages from the highest address down (`MADV_DONTNEED`, outside the lock) beyond a retain budget (1.1 × goal). After 10 s without store allocation everything free is released. |
| Pacing | Go-style goal: `marked × (1 + m·KHRIP_GC/100)`, at least 4 MB. The trigger is at 70% of the headroom. Design 1's **adaptive multiplier** `m ∈ {1,2,4,8}` grows for mostly-live stores. Optional soft limit. |
| Safety valves | **Writer assist** above 1.5 × goal. **Emergency collection** above the hard limit: inside a long writer request or every-task, the request publishes itself and collects stop-the-world; at a final release no publication is needed. |
| Boot | User globals are initialised and **KHRIP_DATA is restored inside a dedicated 64 GB NORESERVE boot arena** through `__persist`. After boot the store graph is STORE+DATA only, and the file buffer is freed. |
| Fixes that come with it | Iterative `__deep_copy` with forwarding: cycles no longer crash, and sharing inside a persisted value is kept. JSON encode with **real cycle detection** (an on-path set from depth 1000) and a 10,000-level depth guard. `__struct_alloc` uses `max(n,1)`. `__fetch` builds the request before unlocking. `__alloc_for` never grows heap owners into STORE. Barriers copy anything not in STORE∪DATA. `call` restores the test's lock. api-mode `var` globals are persisted and rooted. Vacated container slots are zeroed. |
| Rejected | Moving collection (Design 1): its soundness depends on complete typed stack maps, and the `tx` retry buffer is an unhealed register image (lib/db.kh:1459). Epochs/RCU: unbounded memory under long holders. Stop-the-world only: tens of ms on ratelimit. Transitive conservative windows (Design 0): over-retention. Eager arena scans at every release (Design 2): about 0.1 ms per MB of arena per wait. |

## 1. Requirements, facts, and how the judges' findings are resolved

### 1.1 Requirements

| Requirement | How it is met |
|---|---|
| Memory bounded under constant updates and returned to the OS | Every cycle frees all garbage (no quarantine). The heap stays at or below the goal; free pages above the retain budget are released, and on idle all free pages are released. Long holders pin only what they reference. |
| No use-after-free or lost updates in any interleaving, including long suspensions and long polling | Invariants I1–I10 (§2) and the proof (§9). Nothing moves. The collector never writes a live object. Published records cover every holder at every cycle start. |
| Minimal pause | Start ≈ 10–50 µs (exclusive). Slices ≤ 200 µs and termination ≤ 50 µs, both under `rw[0]` only, so readers are never paused. Sweep slices ≤ 200 µs under `rw[0]`. No pause grows with heap size; the only exception is the emergency path, which runs inside a request that already monopolises the lock. |
| Minimal throughput cost | Store allocation +10–20 ns per object. Barriers add one compare when idle. Container operations add one global load. GC CPU ≈ 25–35 ns per request on patch and ratelimit. A pin publication costs ≈ 0.2–0.4 µs, and only for store-touching requests that wait. |
| Several worker threads | Per-thread pin lists, mutated only under the store lock. All GC metadata is mutated only while holding `rw[0]`. Readers never touch GC metadata (except their own record's hand-off word, via CAS). |
| every-blocks, tests (`call`), KHRIP_DATA | §6.7, §6.8, §5.3, §8.5. |

### 1.2 Facts to respect

| Fact | Handling |
|---|---|
| Store objects have no headers | Side bitmaps plus span metadata. The span size class gives extents and resolves interior pointers. |
| Suspended requests hold store pointers without the lock (stack, registers, evicted stacks, arena) | Published records (§6). Eviction copies frames after publication, so the eager copy is already complete. |
| Aliases see in-place mutations by others | Non-moving collector; no copy on write-back. |
| Enum/unit values in DATA are compared by address | DATA is never marked, followed or moved. |
| Sharing and cycles | Mark bits. `__deep_copy` forwarding (§5.2). |
| KHRIP_DATA restore puts everything in the heap | Boot arena plus `__persist` (§5.3). |
| Inlined helpers, `map.clear()`, `Buf` | Fixed in `b6c0307`. In addition, every library operation that mutates a store container asserts the exclusive lock (§4.9), which turns any remaining classification bug into a 500 instead of a race. |
| `__deep_copy` and JSON encode recurse without cycle detection | Iterative copy (§5.2); JSON cycle detection (§10.1). |
| 98% garbage in catalog PATCH; `patch` grows to 140 MB in 13 s | Reclaimed every ≈ 0.22 s; expected RSS 6–8 MB (§11). |

### 1.3 Judges' findings and their resolution

| Finding | Resolution |
|---|---|
| D0: `call` reopens the same `__Win` (double link, n=0), so the test's pins are lost | No windows to open or close. One record per context **strictly alternates** with the lock: publish at release, withdraw at acquisition. `__call` publishes the test context explicitly at its GC point (§6.8). |
| D0: chunked continuation plus in-place moves (`remove_at`, `reverse`, `sort`, rehash compaction) loses marks | **Partial-array rule** for every shifting or permuting operation (§7.5). `remove_at` shades the one element that crosses the scan boundary; permutations finish the partial array. Verify mode re-marks independently at every termination. |
| D0: sweep, tree rebuild and madvise run inside an exclusive pause | Sweep is lazy, in slices under `rw[0]`. madvise runs outside every lock. The page tree is updated eagerly in O(log P) per span operation; there is no rebuild. |
| D0: scratch offsets overlap (`now_ms` 192–207, `__poll` 208–223, peek 232–239) | New ctx words: 144 (per-coroutine) and 184 (thread). JSON scratch at 240/248. No overlap (§3.3). |

| D2: no in-request safe point | Writer assist and an emergency self-published stop-the-world collection on the copy path (§8.4). |
| D2: a JSON depth limit of 1000 rejects legal values | Exact cycle detection from depth 1000, and a 10,000 guard only against stack overflow (§10.1). |
| D2: restore in a 1 GB arena | 64 GB NORESERVE boot arena (§5.3). |
| D2: eager O(arena) copy at every release | Lazy arena range with a CAS hand-off (§6.4). The eager part is only registers, stack, ctx and `__Worker` (≈ 230 words). |
| D1: tx retry buffer, int-typed pointers, stack-map completeness | Not applicable: the collector is non-moving. The tx jump buffer lives in the arena and is a conservative pin like any other arena word. |
| Keep from D1: adaptive ratio, `max(n,1)` structs, `__data_end`, holder test matrix, stop-the-world gate before incremental, long-holder report | §8.2, §5.4, §4.8, §15.2, §14 step 5, §8.6. |
| Keep from D0: emergency GC, lazy cached arena scan plus W1 hash, catch-path unlink, JSON on-path set, boot arena, address-ordered reuse and release, idle release, oracle test, random-op suite, stress plus verify over the whole suite, verify re-mark from descriptors, poisoning, zero-field structs, GC lock without touches, heap owners never in STORE, fragsim port | All included. Sections are noted where each is used. |

## 2. Invariants (every component relies on these)

- **I1 Closed graph.** Every root slot, and every word of an allocated STORE object whose ptrbit is set, holds 0, a scalar, a DATA address, or an address inside an allocated STORE object. No arena or heap object is reachable from roots. This is enforced by:
  - barriers and persist copying everything outside STORE∪DATA;
  - boot in an arena;
  - `__alloc_for` never putting heap-owner growth into STORE;
  - the `Buf` ban.
- **I2 Access.** A context dereferences a mutable STORE object only while it holds the store lock. Immutable STORE objects (strings, boxes) may be read in a window only if they are reachable from that context's published record (W2).
- **I3 Publication.** A context that has taken the store lock in its current unit of work, and does not hold it now, has a **linked** record. The eager words of the record, together with the arena words in `[lo, hi)`, contain every STORE pointer the context will use again, except pointers it obtains later under the lock. This is enforced by the single release API and the window rules W1–W3 (§6.6).
- **I4 Strict alternation.**
  - A record is linked only by `__store_release_keep` (or by an explicit self-publication, §8.4) and unlinked only inside `__store_lock` after acquisition, or by explicit self-unlink.
  - Per-thread lists are mutated only by a context of that thread while it holds the lock (shared or exclusive).
- **I5 Metadata ownership.**
  - All GC metadata (bitmaps, spans, page heap, grey stack, phase, counters) is written only by a thread holding `rw[0]` (the writer mutex, which exclusive holders also own).
  - The one exception is a record's `ast` hand-off word, which changes only by CAS or by a release store by its owner.
- **I6 SATB.** While `__gc_marking != 0`:
  - every pointer word of a store object or root slot that is overwritten or removed is shaded first;
  - an array being scanned in chunks is protected by the partial-array rule (§7.5) before any in-place move;
  - an array replaced by growth is shaded;
  - every new allocation is marked (black).
- **I7 Codegen contract.** A value that is live across a call sits in rbx, rbp, r12–r15, or memory (stack or arena). This holds today: temporaries are pushed (`emit_push`), register arguments are moved into locals at entry (src/stmt.kh:1816), and `end_fn` saves used callee-saved registers. It is written into DESIGN.md as a constraint for v0.15, whose R8–R11 cache must be spilled at calls.
- **I8 Collector context.** Freeing phases run only:
  - on the GC thread;
  - in a context that has just made its final release (it holds nothing it will use) — except the release of a request nested in a test's `call`, whose test still holds its values above it (§6.8);
  - or in a context that has published itself (emergency, test `call`).
- **I9 Hand-off.** For every record captured by cycle K, the STORE words of its `[lo, hi)` are resolved by cycle K before that context dereferences any store pointer after re-acquiring. No record is in state `GC` outside a running marker slice.
- **I10 Sweep order.**
  - A span is allocated from only after it is swept for the current cycle.
  - Termination resets every `cur` and `partial` list.
  - A new cycle starts only after the sweep cursor reaches the high-water mark.

## 3. Memory layout

### 3.1 Regions

| Region | Address | Notes |
|---|---|---|
| STORE | `0x1000_0000_0000`, 256 GB reserved `PROT_NONE` | Committed with `mprotect` RW in 4 MB steps as the high-water mark grows (works under strict overcommit). Page = 8 KB (2^13). The `(p>>40)==0x10` test stays. |
| GCMETA | `0x1800_0000_0000`, reserved `PROT_NONE` | Committed in step with STORE (§3.2). |
| Arenas | `[0x2000_0000_0000, 0x4000_0000_0000)` | `ARENA_SLOTS` drops from 32767 to **32703**. The last 64 GB, `BOOT_ARENA = ARENA_REGION + 32703·ARENA_SIZE`, is the boot arena (`BOOT_ARENA_SIZE = 64 GB`), still inside `(p>>45)==1`. |
| DATA | `[0x20000000, __data_end())` | `__data_end()` is a new lib-only builtin (§13.1). `__in_data(p) = p − DATA_BASE <u __data_end() − DATA_BASE`. |
| GC scratch | anonymous mmap | Grey stack, pin array, captured-arena list, verify shadow bitmap. Released with `MADV_DONTNEED` after a cycle when larger than 1 MB. |

### 3.2 GC metadata (fixed addresses, reserved at `__store_init`)

| Name | Address | Granularity | Size (virtual) | Committed per 4 MB of store |
|---|---|---|---|---|
| `START` | GCMETA + 0 | 1 bit per 16 B granule | 2 GB | 32 KB |
| `MARK` | GCMETA + 2 GB | 1 bit per 16 B granule | 2 GB | 32 KB |
| `PTRB` | GCMETA + 4 GB | 1 bit per 8 B word | 4 GB | 64 KB |
| `PAGEMAP` | GCMETA + 8 GB | u32 per page: span base page + 1, 0 = none | 128 MB | 2 KB |
| `SPANS` | GCMETA + 9 GB | 64 B record per page; the record sits at the span's base page | 2 GB | 32 KB |
| `PHEAP` | GCMETA + 12 GB | free / dirty / released bits per page, plus the summary tree | ≤ 64 MB | ~0.2 KB |

- Total ≈ 3.95% of committed store.
- Granule index: `g = (p − STORE_REGION) >> 4`. START/MARK word `g >> 6`, bit `g & 63`, low bit = low address.
- PTRB bit index: `(p − STORE_REGION) >> 3`.

**Span record** (8 words at `SPANS + base_page·64`; as built in step 3):

| Word | Contents |
|---|---|
| w0 | `base` (address of the first slot) |
| w1 | `npages` (32) \| `sc` (16) \| flags (16): `INUSE`, `NOSCAN`, `LARGE`, `NEEDZERO` |
| w2 | `elemsize`: the slot size; a large span's whole size |
| w3 | `freeindex` as an **address**: the slot to search from; no slot below it is free until the next sweep |
| w4 | `sweepgen` |
| w5 | `magic = ceil(2^32 / elemsize)` (32) \| `nelems` (32); exact division for offsets < 80 KB; a large span has `0 \| 1` |
| w6 | `next`: partial-list link, base page + 1, 0 = end; `nfree` in the high half (step 5) |
| w7 | fast-path end: the address past the last slot, or **0 when the span needs zeroing** (`NEEDZERO`), so every allocation from it takes the slow path |

- A span class without a span points at `__gc_none`, an all-zero record (freeindex = fast-path end = 0), so the fast path never tests for 0.
- A span changes state only through two helpers in gc.kh:
  - `__span_rewind(s)`, for a swept span that kept objects: `freeindex = base`, `w7 = 0`, `NEEDZERO` set (its freed slots hold old data);
  - `__span_free(s)`, for a span left without objects: the START, MARK and PTRB bits of all its memory are cleared, its PAGEMAP entries become 0, the record's `w1`, `w3` and `w7` become 0 (not `INUSE`), and the pages go back to the page heap as free and dirty.

**Page heap.**
- Leaves are 64-page words of the `free` bitmap. Internal nodes hold `(pre, suf, best)` as u32, in pages.
- They are updated **eagerly** on every span alloc or free, in O(npages/64 + log L). There are no lazy bounds.
- `first_fit(n)`: at each node, go left if `L.best ≥ n`; else, if `L.suf + R.pre ≥ n`, the answer is `L.end − L.suf`; else go right. At a leaf, scan bits for the first run ≥ n.
- `dirty` bit: the page held objects since it was last released, so a span built on it gets `NEEDZERO`.
- `released` bit: the page was `MADV_DONTNEED`'d.
- `__ph_hw`: one past the highest in-use page.
- Capacity doubles (and the tree is rebuilt, O(L)) when commit grows past it.

### 3.4 Pin record (`lib/gc.kh`, allocated in the thread heap with `__alloc_heap`, never in an arena)

```
type __Pin {
    next: int, prev: int        // links in the thread list (0 = end)
    linked: bool
    touched: bool               // took the lock in this unit of work (verify)
    top: int                    // highest stack address: sch.top for coroutines, thread top otherwise
    regs: int                   // 64-byte jmp_buf (thread heap)
    buf: int, len: int, cap: int   // eager STORE-range words (mmap, grows by doubling, 4 KB initial)
    lo: int, hi: int            // arena range frozen at publication; lo == hi means none
    ast: int                    // hand-off word: (cycle << 3) | state
    aoff: int                   // bytes of [lo, hi) already scanned by the GC this cycle
    hbuf: int, hlen: int, hcap: int   // words handed off by the holder (mmap)
    pub_cycle: int              // __gc_cycle_no at publication (long-holder report)
    whash: int                  // verify: hash of the STORE-range words of [lo, hi)
}
```

- `ast` states: `IDLE=0, PENDING=1, GC=2, SELF=3, HANDED=4, DONE=5`.
- Records are created in two places:
  - in `__co_new` (lib/http.kh:460) with `top = s.sch.top`;
  - lazily at the first `__store_lock` of a thread context (main thread, timer thread), with `top` from `__sp()` captured in `__entry`/`__thread_main` and kept in a lib global per thread.
- Plain programs never create records.
- `__gc_threads`: an mmap array `[n, ctx…]` (up to 4096 threads). A thread appends itself with `__xadd` at its first publication (flag at ctx+224).
- `__gc_recs`: an mmap array of every record, for verify.

## 4. Store heap and allocation

### 4.1 Size classes

- Go's `sizeclasses.go` table from 16 B to 32 KB: 66 classes, each with its page count, so tail waste stays ≤ 12.5%.
- Two span classes per size class: `sc = c·2 + noscan`, 132 in all.
- Lookup tables built in `__gc_init`:
  - `__sc_by16[(n+15)>>4]` for n ≤ 1024;
  - `__sc_by128[(n−1024+127)>>7]` for n ≤ 32768.
- Every class ≤ 256 B is a multiple of 16, which matches today's 16-byte rounding. Powers of two (list arrays, map slots) map exactly onto classes. **In practice there is no internal waste beyond today's**; only odd objects over 256 B waste up to 12.5%.

### 4.2 `__salloc(n, kind, mask)`

Called only in store mode, with the exclusive lock held, or from boot, test or emergency contexts.

```
fn __salloc(n, kind, mask) -> int                     // kind: K_NOSCAN 0, K_PTRS 1, K_MASK 2
    if n > 1024 || __gc_slow { return __salloc_slow(n, kind, mask) }
    let sc = class(n)*2 + (kind == K_NOSCAN ? 1 : 0)
    let s = __gc_cur[sc]; let p = freeindex(s)            // __gc_none when the class has no span
    if p < fastend(s) && !bit(START, p) {                  // fastend = 0: NEEDZERO or no span
        bit_set(START, p); freeindex(s) = p + elemsize(s)
        ptrbits(p, n, kind, mask)                         // K_PTRS: ones for the object; K_MASK: the mask
        __heap_live += elemsize(s)
        return p
    }
    return __salloc_slow(n, kind, mask)

fn __salloc_slow(n, kind, mask) -> int
    if __gc_verify { __gc_check_owner() }                 // I5, and marking ⇒ __gc_slow (§8.7)
    if n > 32768 { return __salloc_large(n, kind, mask) } // own span, ceil(n/8K) pages
    let sc = class(n)*2 + (kind == K_NOSCAN ? 1 : 0)
    var s = __gc_cur[sc]; var p = __span_take(s)
    if p == 0 { s = __refill(sc); __gc_cur[sc] = s; p = __span_take(s) }
    let es = elemsize(s)
    if __gc_marking != 0 { bit_set(MARK, p) }              // allocate black
    if needzero(s) { if __gc_verify { __check_poison(p, es) }; __memset(p, 0, es) }
    else if __gc_verify { __gc_check_zero(p, es) }
    if kind != K_NOSCAN { ptrbits(p, n, kind, mask) }      // the slot's tail keeps zero bits
    __heap_live += es
    if __heap_live >= __gc_trigger && !__gc_poked { __gc_poke() }   // step 5: futex wake, once per cycle
    return p
```

- **The fast path sets no MARK bit.** So allocation during marking must take the slow path: `__gc_slow` is `verify_slow || __gc_marking != 0`, and both are changed only through `__gc_set_marking(on)` (gc.kh), which recomputes `__gc_slow`. Nothing else writes `__gc_marking`; verify mode asserts `__gc_marking == 0 || __gc_slow` on every slow allocation, at every release and in every heap check.
- **The PTRB bits of free memory are zero.** Allocation only ORs bits in, so everything that frees memory clears them: `__span_free` for a whole span, the sweeper for each freed slot of a span it keeps (§7.7).
- `__span_take(s)` scans slots from `freeindex` and takes the first whose START bit is clear (0 when none is). `freeindex` only moves forward between sweeps, so the cost is amortised O(1).
- `__refill(sc)`:
  1. Pop the head of `partial[sc]`. These spans are swept and address-ordered, because the sweeper appends in address order.
  2. Otherwise `__span_new(sc)`: `__ph_alloc(npages)` gives the lowest-address run; write the pagemap entries and the record; set `NEEDZERO` if any page is dirty; set `sweepgen` to the current value.
- Cost ≈ 10–20 ns per object, against ≈ 2 ns for today's bump. A PATCH allocates 1–3 store objects, so about +40 ns of 12.3 µs.

### 4.3 Hook into the existing allocator

No change to compiled fast paths.

- `__pmode_on` (lib/core.kh:220):
  - checks `__gc_ready` instead of `__store_ptr != 0`;
  - saves the arena cursor in PSAVE as today;
  - sets **`CTX_PTR = CTX_END = 0`**.
- So every `__alloc` in store mode falls into `__alloc_slow` (core.kh:133). Its first line becomes `if load64(c + CTX_PSAVE_PTR) != 0 { return __salloc(size, K_PTRS, 0) }`. The STORE commit branch is deleted.
- `__pmode_off` only restores PTR/END from PSAVE.
- `__store_ptr`/`__store_end` are deleted.
- New helpers in core.kh:
  - `__alloc_k(n, kind, mask)`: in store mode `__salloc`, otherwise `__alloc`;
  - `__alloc_heap(n)`: swap SAVE_PTR/SAVE_END in for one allocation from the thread heap.

### 4.4 Typed allocation: where the kind comes from

Compiled code never runs in store mode, so only library code is involved.

| Object | Kind | Where |
|---|---|---|
| store string | **one K_NOSCAN object**: `[header (H bytes: 16 today, or whatever the UTF-8 design chooses)][bytes][NUL]`, with `header.ptr = obj + H` | `__str_copy_store(ptr, len)` (gc.kh), called by `__deep_copy`. Saves an object per string; interior slices resolve to it. |
| `int?`/`float?`/`bool?` box | K_NOSCAN, 16 B | `__deep_copy` |
| struct | K_MASK from the descriptor's new **`ptrmask` word** (§13.1); bit i means field i is a reference; more than 63 fields means K_PTRS | `__struct_alloc` (api.kh:93), which now uses `max(n,1)·8` |
| variant | mask shifted by one past the tag word | same |
| list header | K_MASK {0} | `__list_new_k(cap, esize, elem_ref)` (core.kh, new; `__list_new` keeps its signature) |
| list data | K_PTRS if the element type is a reference, else K_NOSCAN (`[int]`, `[float]`, `[bool]` with esize 1) | same |
| map header | K_MASK {0, 2, 3, 4} | `__map_new_k(str_keys, vals_ref, n)` (core.kh, new; pre-sized for n entries) |
| keys / vals / alive data, slots | keys K_PTRS iff str keys; vals K_PTRS iff the value type is a reference; alive and slots K_NOSCAN | same; `__map_rehash` and `__map_clear` slots K_NOSCAN |
| growth (`__list_grow`) | inherits K_NOSCAN from the span of the array being replaced | `__alloc_for_k` |
| any other store-mode `__alloc` | **K_PTRS (safe default)** | `__alloc_slow` |

- A wrong K_NOSCAN would cause a use-after-free. It is caught by the verify re-mark: a typed pointer word without its ptrbit is fatal.
- K_PTRS is never unsafe; at worst it retains.

### 4.5 Zeroing

- Allocation zeroes slots of `NEEDZERO` spans, and only those: reused memory.
- Fresh pages and released pages read as zero.
- Verify mode first checks that the 0xDE poison written at sweep is intact. This catches writes after free and double allocation (a lost-update guard).

### 4.6 `__alloc_for` (core.kh:191)

`__alloc_for(h, n)` becomes `__alloc_for_k(h, n, K_PTRS, 0)`, with these rules (as built in step 3):
- store mode, or `h` in STORE whatever the current allocator: `__salloc_for(h, n, kind, mask)` (gc.kh), which enters store mode for the one allocation if needed; `K_LIST_DATA` takes the kind of `h`'s current data array.
- `CTX_PTR` is in an arena and `h` is outside both arena and STORE (library heap owners): `__alloc_heap(n)`. **Never STORE**: today such growth lands in STORE and would be freed as unreachable.
- Otherwise: `__alloc(n)`.

The store test is `__store_for(h)` from gc.kh. nostore.kh defines it as `false` and its `__salloc_for` as a stub that exits, so a program without store links no store code.

### 4.7 Containers: zeroing vacated slots and the exclusive-lock assertion

When `__in_store(h)`:
- `__list_pop`, `__list_remove_at`, `__list_truncate` and `__list_clear` zero the vacated element slots (after reading the returned value).
- `__map_remove_word` zeroes the dead entry's key and value (after reading the value).
- `__map_rehash` zeroes keys/vals/alive in `[w, n)`.
- `__map_clear` zeroes the three arrays up to the old length.

This costs one store per removed element, plus O(len) for `clear` of a store list (O(1) today). It makes the ptrbit scan of whole arrays precise.

Every mutating container operation begins with `__store_mut(h)`:

```
if (h >> 40) == 0x10 && load64(ctx + CTX_STORE_HELD) != 1 { __store_mut_slow() }
```

`__store_mut_slow` panics with "internal: store changed without the exclusive store lock". A read-only route that has been misclassified becomes a 500 instead of a race with the marker. Both live in gc.kh; nostore.kh and the boot shim define `__store_mut` empty.

### 4.8 Page heap, high-water mark, scavenger

- `__ph_alloc(np)` is first fit. If no run fits, it extends `__ph_hw`; if the commit end is passed, it commits 4 MB of store plus the matching metadata (`__gc_commit_to`).
- `__ph_free(pg, np)` sets free and dirty, updates the tree, and lowers `__ph_hw` past trailing free pages.
- `__gc_scavenge(retain_bytes)`:
  1. Under `rw[0]`: walk pages from `commit_end` down, collecting runs that are free and not released, until the unreleased free bytes reach `retain_bytes` (at most 256 runs per call). Mark them allocated to an internal owner so that no span can take them.
  2. Release `rw[0]`; `madvise(MADV_DONTNEED)` each run; also release whole 4 KB pages of START/MARK/PTRB/PAGEMAP/SPANS that cover released 4 MB chunks above `__ph_hw`.
  3. Take `rw[0]` again; mark the runs free, released and not dirty.
- `retain = max(1 MB, 1.1·goal − heap_inuse)` normally; `retain = 0` on idle release.
- Commit charge is not reduced. This matters only under `vm.overcommit_memory=2` and is noted in DESIGN.md.

## 5. Keeping the graph closed: barriers, persist, boot, roots

### 5.1 Barriers (lib/api.kh)

```
fn __barrier_at(obj, off, v, d) -> int        // x.f = v       (new; replaces __barrier for fields)
    if __in_arena(obj) { return v }
    if __in_store(obj) { __store_mut(obj); if __gc_marking != 0 { __gc_shade(load64(obj + off)) } }
    if v == 0 || __in_store(v) || __in_data(v) { return v }
    return __persist_copy(v, d)

fn __barrier_idx(xs, i, v, d) -> int          // xs[i] = v     (new; the bounds check runs after it)
    same, with old = (0 <= i < len(xs)) ? load64(data(xs) + i*8) : 0

fn __barrier(obj, v, d) -> int                // map value / key, push, insert: no old value
    if __in_arena(obj) || v == 0 || __in_store(v) || __in_data(v) { return v }
    return __persist_copy(v, d)

fn __persist_root(v, d, slot) -> int          // store global / api-mode var global (store_write)
    if __gc_marking != 0 { __gc_shade(load64(slot)) }
    return __persist(v, d)

fn __persist(v, d) -> int                     // unchanged entry; copies anything outside STORE∪DATA
    if __is_scalar(d) || v == 0 || __in_store(v) || __in_data(v) { return v }
    return __persist_copy(v, d)

fn __persist_copy(v, d) -> int
    __gc_hard_check()                         // §8.4 emergency, before entering store mode
    let on = __pmode_on(); let r = __deep_copy(v, d); if on { __pmode_off() }; return r
```

- When idle, the arena fast path costs exactly what it costs today.
- Today's "copy only arena values" rule becomes "copy anything not in STORE∪DATA". This covers heap headers such as restored file slices and `env` strings.

### 5.2 `__deep_copy` (lib/api.kh:140): iterative, with forwarding, keeps sharing and cycles

- **State.** A forwarding table maps source address to copy (linear for ≤ 16 entries, then open addressing), plus a work stack of `(dst_slot, src, desc)`. Both are allocated **in the arena through the saved cursor** (`PSAVE_PTR`/`PSAVE_END`, helper `__arena_alloc_saved`). They are never in STORE.
- **`copy(v, d)`.** It returns `v` for scalars, 0, STORE and DATA values. Otherwise it returns the forwarded copy if one exists. Otherwise it allocates the **shell first** and records the forwarding, then:

| Kind | Copy |
|---|---|
| STR | `__str_copy_store` |
| OPT(scalar) | box |
| OPT(ref) | `copy(v, inner)` |
| SUM | `__variant_entry` gives the struct descriptor; a unit variant returns `v` |
| LIST | `__list_new_k(max(len, 4), es, ref)`; memcpy of `len·es`; for reference elements, push `(data + 8i, src_i, ed)` |
| MAP | `__map_new_k(str_keys, vals_ref, live)`, sized so it never rehashes during the copy; alive entries are appended in iteration order; keys are copied directly (strings are leaves); reference values are pushed as `(vals_data + 8·idx, src, vd)` |
| STRUCT | `__struct_alloc(d)`; scalars copied; reference fields pushed |

- **Main loop.** Pop `(slot, src, sd)` and do `store64(slot, copy(src, sd))`.
- **Effects.**
  - Cycles terminate: `cyc2.kh` no longer segfaults.
  - Sharing within a value is kept: `Pair{a: xs, b: xs}` persists to one list.
  - Existing STORE children are shared, as today.
  - Each copied object costs about 20–40 ns more; a PATCH copies 1–3 objects and stays on the linear path.

### 5.3 Boot (replaces initialisers and restore on the heap)

**Compiler.** `compile_init_globals` (src/stmt.kh:1870) splits:
- `__init_globals` initialises library globals, and all globals in non-api programs (unchanged).
- In `api_mode`, a new generated **`__init_stores`** initialises every user global in declaration order. Reference values go through `store_write(g.ty, g.addr)`, i.e. `__persist_root`.
- `src/main.kh:258` adds `gen_func("__init_stores", ty_void)` and compiles it next to `__init_globals`. It is empty when there are no user globals.

**Runtime.** `__store_boot(load: bool)` in gc.kh replaces the `__store_init(); __store_rw_init(); __store_lock(); __store_unlock(); __load_store()` prologue of `__serve` (http.kh:1107) and `__run_timers` (:1091), and the store part of `__tests_init` (api.kh:1324):

1. `__store_init()`: reserve STORE and GCMETA, run `__gc_init()` (class tables, knobs). Idempotent.
2. `__store_rw_init()`, then `__store_lock()` (exclusive; creates the main-thread record).
3. Attach the boot arena to the main ctx and call `__arena_begin()`. The arena limit is generalised in `__alloc_slow` and `__arena_begin` via `__arena_size(base)`, which is `BOOT_ARENA_SIZE` for `BOOT_ARENA` and `ARENA_SIZE` otherwise. `__arena_attach` tries RW NORESERVE and falls back to PROT_NONE plus commits, as today.
4. `__init_stores()`.
5. `if load { __load_store() }`: `read_file` and `from_json` allocate in the boot arena; the generated `__store_restore` assigns through `store_write`, so `__persist_root` copies everything into STORE.
6. `__arena_end()` (MADV_DONTNEED above 32 MB, which frees the file text and the decoded copy); detach and restore the previous `CTX_ARENA`/`ARENA_END`.
7. `__store_release_final()`.
8. `__heap_marked = __heap_live` (everything built at boot is live), then `__gc_pace()`. No boot collection is needed.
9. `__store_saved = __store_touches`.

**Result.** Restore peak is ≈ 3× the data size (file + decoded + STORE) until step 6, then about 1×. Today it is 2× and kept for ever. Restores up to about 20 GB fit in the boot arena.

### 5.4 Root table and api-mode `var` globals

- `gc_root_table()` (src/api.kh, new) builds the DATA table `[n, (slot_addr, type_desc(g.ty)) × n]` once. It covers every user (non-lib) global with `!is_scalar_ty(g.ty) && (g.is_store || api_mode)`.
  - It uses the real type, not the snapshot's `D_OPT(T)`.
  - It forces descriptor emission in `khc test` too.
- The lib-only builtin `__gc_roots()` returns the table address, like `__db_root` (src/atom.kh:1196).
- api-mode `var` globals exist only in test-only programs (`check_api` forbids them in servers). They become persistent:
  - reads and writes emit `store_touch` (src/atom.kh:181, src/stmt.kh:704);
  - assignment goes through `store_write`;
  - initialisation happens in `__init_stores`;
  - they are listed in the root table.
- This fixes today's dangling arena values after a test arena reset.

### 6.2 Publication and withdrawal (gc.kh)

```
fn __pin_publish(rec)                       // the lock (shared or exclusive) is still held
    __setjmp(rec.regs)                      // rip, rsp, rbp, rbx, r12–r15
    let sp = load64(rec.regs + 8); rec.len = 0
    __pin_take(rec, rec.regs, 64)
    __pin_take(rec, sp, rec.top - sp)                       // every live frame
    let c = __ctx(); __pin_take(rec, c + 8, CTX_CO_END - 8) // CTX_PANIC message, JNULLS, ...
    let w = load64(c + CTX_WORKER)
    if w != 0 { __pin_take(rec, w, WORKER_BYTES); __pin_take(rec, w.jb, 64) }
    let cj = load64(c + CTX_CATCH); if cj != 0 { __pin_take(rec, cj, 64) }
    let p = load64(c + CTX_PTR)
    if __in_arena(p) { rec.lo = load64(c + CTX_ARENA); rec.hi = p } else { rec.lo = 0; rec.hi = 0 }
    if __gc_verify { rec.whash = __pin_hash(rec.lo, rec.hi) }
    rec.pub_cycle = __gc_cycle_no
    __gc_register_thread()                  // once per thread (ctx+224)
    link rec at the head of load64(c + CTX_PINLIST); rec.linked = true
```

- `__pin_take` appends the words with `(w >> 38) == 0x40` (STORE range) using **`__simd_pinscan(lo, hi, out, room)`**: AVX2 `vpsrlq 38`, `vpcmpeqq`, `vmovmskpd`, with SSE2 and scalar fallbacks (src/simd.kh). The buffer grows by doubling.
- Typical eager size is ≈ 230 words: 0.2 µs scalar, under 0.1 µs SIMD.
- Arenas are not scanned here.

```
fn __pin_withdraw(rec)                      // the lock was just acquired
    unlink rec; rec.linked = false
    if __gc_verify && __pin_hash(rec.lo, rec.hi) != rec.whash { fatal "window code changed the arena (W1)" }
    loop {
        let s = rec.ast; let st = s & 7
        if st == PENDING {
            if __cas(&rec.ast, s, (s & ~7) | SELF) {
                scan [rec.lo + rec.aoff, rec.hi) with __simd_pinscan into rec.hbuf
                store rec.ast = (s & ~7) | HANDED     // plain store = release on x86
                break
            }
        } else if st == GC { __cpu_pause(); continue }   // the GC is scanning a ≤ 256 KB chunk
        else { break }                                    // IDLE, DONE or HANDED
    }
```

- Only a reader can ever see `GC`: a writer holds `rw[0]`, so no slice runs.
- The spin is bounded by one chunk, about 10–30 µs.
- No deadlock: the GC never waits for a reader while a record is in state `GC` (I9).

### 6.3 What the collector does with records

**At cycle start** (exclusive, cycle K): for every registered thread and every record on its list:
- append `rec.buf[0..len)` to the GC pin array (bounded memcpy);
- if `rec.hi > rec.lo`, add `(rec, lo, hi)` to `__gc_cap` and set `rec.ast = K<<3 | PENDING`, `rec.aoff = 0`.

**In slices**, captured arenas are processed before grey work:

| State | Action |
|---|---|
| `PENDING` | `CAS PENDING→GC`; resolve the words of `[lo+aoff, min(lo+aoff+256 KB, hi))`; `aoff += chunk`; then a plain store of `PENDING` (more to do) or `DONE` |
| `HANDED` | resolve `hbuf[0..hlen)`; store `DONE` |
| `SELF` | skip for now |
| `DONE` | — |

**At termination** (`rw[0]`):
- `PENDING`: the GC scans the rest itself.
- `SELF`: spin until `HANDED` (the holder holds the shared lock and needs nothing from the GC).
- `HANDED`: process the buffer.
- Termination requires every captured entry to be `DONE`.

### 6.4 Why lazy arenas are correct (W1) and when the hand-off fires

- During a window, the arena below `hi` does not change (W1). Scanning it at any time before the holder resumes is therefore equivalent to scanning it at publication.
- The holder resumes only after `__store_lock()`, whose withdraw guarantees the scan happened: GC chunk `DONE`, or its own SELF scan. That is I9.
- `__arena_end` and `__co_put` madvise, which reset or reuse the arena, always come after a final release, which withdraws.
- Cost:
  - a window with no overlapping cycle pays nothing for its arena (cycles are ≥ 0.2 s apart; most waits are ms);
  - a reader that resumes before the GC reached it scans its own arena once, the same cost an eager scan would have had;
  - a request with a 5 MB arena doing 20 SQL calls pays 0 instead of 20 × 0.15–0.6 ms.

### 6.6 Window rules (documented in DESIGN.md, checked in verify mode)

- **W1.** Code between `__store_release_keep` and the next `__store_lock` writes no word into arena memory below the published `hi`, except byte buffers allocated for that purpose before the release (PBKDF2 `out`; as built in step 4 there is no exception: PBKDF2 writes a buffer allocated in the window and copies it after re-acquiring). Verify mode compares the hash of STORE-range words of `[lo, hi)` at publication and at withdrawal.
- **W2.** Such code dereferences no mutable store object, and obtains store pointers only by reading immutable objects reachable from the record.
- **W3.** Every panic path that can leave a window ends in `__store_release_final`, which re-acquires the lock first if the record is linked:
  - `__serve_one`'s catch path (api.kh:1289) reaches its end;
  - `__run_task`'s catch (http.kh:1030);
  - `__test_end`.
  
  `__co_put` asserts `!rec.linked && !rec.touched` (verify).
- **Lint.** `tests/run.sh` checks that `__store_release_keep(` appears only at the audited sites of §6.5 and that `__store_unlock_raw(` appears only in rt.kh and gc.kh. A new site fails CI until it is audited.
- **Driver windows.** `mongo_command` and `__ch_run` are audited sites (§6.5): five in all with `__co_wait`, `__fetch` and `__pbkdf2_unlocked`. Today they use the raw `__store_unlock()`/`__store_lock()` like `__fetch`; step 4 turns both into `__store_release_keep`/`__store_lock` pairs and adds them to the lint. Until then `tests/mongo.sh` and `tests/clickhouse.sh` check that each window holds a single call over values copied before the release (W2), and that the callee does not read `Mongo`, `ChConfig` or the user's `Bson`. W1 holds: inside the windows only fresh arena objects above `hi`, mmap blocks and ctx words are written. W3 holds: the request-end hooks (`__db_end`) run before the final release, allocate nothing and do not touch store.
- **Library writes into user objects.** A library function writes no field of an object that user code can reach (and so may sit in store) unless the compiler emits the barrier for that write (docs/DESIGN.md). The drivers keep the rule by construction: the two types they change in place, `MongoCursor` and `BsonBuilder`, are rejected in store and in test-mode globals (src/api.kh, `store_raw_type`), so step 6 needs no library barrier table for them.

### 6.7 Every-blocks

- They run on the timer thread with `CTX_CORO=0`, using the timer thread's record (`top` = its entry `__sp()`).
- `sleep` and waits go through `__co_wait` and then `__poll`, so they publish like requests.
- A never-ending block pins only what it references.
- `__run_task` ends with `__store_release_final()`.

### 6.8 Tests and `call` (fixes Design 0's nested-window bug and "call drops the test's lock")

`__call` (api.kh:1408):


## 7. The collector

### 7.1 Phases

`IDLE → MARK → SWEEP → IDLE`.

- `__gc_marking` (a var in core.kh, 0 in plain programs) is 1 exactly in MARK. Only `__gc_set_marking(on)` (gc.kh) changes it, because it must change `__gc_slow` too (§4.2).
- `__gc_cycle_no` and `__gc_sweepgen` are counters.

### 7.2 Start (exclusive; ≈ 10–50 µs)

1. Require `IDLE`.
2. `cycle_no += 1`; `__gc_set_marking(true)` (marking = 1 and the slow allocation path, §4.2); `phase = MARK`.
3. For each root `(slot, desc)`: `__gc_resolve(load64(slot))`.
4. Capture records (§6.3).
5. Verify: every record with `touched` is linked, except the collecting context in emergency or test mode.
6. Long-holder statistics (§8.6).

### 7.3 Resolve and scan

```
fn __gc_resolve(w)                               // precise and conservative pointers alike
    let off = w - STORE_REGION; if off >=u __ph_hw_bytes { return }   // DATA, 0, scalars, out of range
    let sb = PAGEMAP[off >> 13]; if sb == 0 { return }
    let s = SPANS + (sb - 1)*64; if !INUSE(s) { return }
    let slot = LARGE(s) ? base(s) : base(s) + (((w - base(s)) * magic(s)) >> 32) * elemsize(s)
    if !LARGE(s) && slot >= base(s) + nelems(s)*elemsize(s) { return }   // span tail
    if !bit(START, slot) { return }              // free slot: stale word
    if bit_testset(MARK, slot) { return }
    __gc_marked_bytes += elemsize(s)
    if !NOSCAN(s) { grey_push(slot, elemsize(s)) }

fn __gc_scan(slot, from_word, to_word)           // ptrbits-driven; ctz over 64-bit PTRB words
    for each word i in [from, to) with PTRB bit set: __gc_resolve(load64(slot + 8i))
```

Variant values (allocation + 8), string slices and `s[len..]` (which points at the NUL) all resolve through the size class.

### 7.4 Draining with bounded grey memory

- Grey items are `(slot, size)`, 16 B each.
- An object of 16 KB or less is scanned whole.
- A larger object becomes a **partial frame** `(obj, pos, size)` on a stack of at most 8 frames. If the stack is full, the item goes to an overflow list and returns to grey when the depth drops.
- Marker loop, with priority order:
  1. captured arenas (§6.3);
  2. unresolved pin words (batches of 1024);
  3. grey items: pop and scan; a large one is pushed as a frame;
  4. if grey is empty and a frame exists: scan the next 2048 words of the top frame, and pop it when done.
- Frames are resumed only after the children of the previous chunk are drained, so the grey stack stays at about 2048 × depth plus the DFS frontier, instead of one entry per element of a million-element list.
- The clock (`clock_gettime`) is checked every 256 objects.
- The slice returns `true` when nothing is left except `SELF` entries.

### 7.5 SATB barrier, zeroing and the partial-array rule (complete table)

"Shade" means `__gc_resolve(old)`, and runs only when `__gc_marking != 0`. "Frame" means the array is one of the current partial frames, which takes ≤ 8 compares.

| Operation | Site | While marking | Always (store containers) |
|---|---|---|---|
| `x.f = v` (reference field) | `__barrier_at` (compiled `assign_field`, src/stmt.kh:767) | shade old `[obj+off]` | copy `v` if outside STORE∪DATA |
| `xs[i] = v` (reference element) | `__barrier_idx` (compiled `assign_index`, stmt.kh:860) | shade old `xs[i]` if `0 ≤ i < len` | copy |

- The verify re-mark catches any gap.

### 7.6 Termination (`rw[0]` only; ≈ 10–50 µs)

1. Finish captured entries (§6.3).
2. Drain until the grey stack, frames and overflow are empty. If this exceeds 2 ms, release and continue with slices; after 4 attempts, finish regardless.
3. `__gc_set_marking(false)`; `phase = SWEEP`.
4. `__heap_marked = __gc_marked_bytes`; `__heap_live = __heap_marked`; `__gc_pace()`.
5. `__gc_sweepgen += 1` (every existing span is now unswept); every `__gc_cur[sc] = __gc_none` (never 0: the fast path reads the current span's record without a test) and `partial[sc] = empty` (I10); `sweep_pg = 0`.
6. Verify: independent re-mark (§8.7) before any sweep.
7. Clear the pin array and `__gc_cap`.

**Why `rw[0]` is enough.**
- Writers, the only mutators of graph and metadata, are excluded.
- Readers cannot change reachability. Readers resuming during termination either find `DONE` or are waited for (`SELF`).
- Readers already running hold only objects that were snapshot-reachable or black, or that were in their record at start (§9).

### 7.7 Sweep (`rw[0]` slices, address order)

```
fn __gc_sweep_slice(budget) -> bool
    while sweep_pg < __ph_hw:
        span at sweep_pg (skip pages without a base) → if INUSE && sweepgen != __gc_sweepgen: __gc_sweep_span(s)
        sweep_pg += npages; check the clock every 64 spans
    phase = IDLE; return true

fn __gc_sweep_span(s)
    for each START/MARK word of the span:
        freed = START & ~MARK
        if verify: poison 0xDE over the slots in freed
        clear the PTRB bits of every slot in freed (free memory has none, §4.2)
        START &= MARK; MARK = 0
    LARGE: START bit clear → __span_free(s), heap_live -= bytes
    small: alloc = popcount(START words); nfree = nelems - alloc
           alloc == 0 → __span_free(s)          // START/MARK/PTRB and PAGEMAP cleared, pages free and dirty
           nfree > 0 → __span_rewind(s)        // freeindex = base address, fast-path end = 0, NEEDZERO
                       append to partial[sc] tail
    sweepgen = __gc_sweepgen
```

- A span leaves `__gc_cur` before it is swept (termination step 5), and a freed span's record is not `INUSE`, so `__gc_resolve` and the fast path never see a stale span.

- Allocations during SWEEP go only into swept partial spans or new spans; new spans carry the current `sweepgen`.
- With a 1 GB heap (128K spans × ≈ 100 ns), sweeping takes ≈ 13 ms of GC-thread CPU in 200 µs slices.
- `popcount` is a SWAR helper in gc.kh.

## 8. Driving the collector

### 8.1 GC thread (`__gc_thread_main`, spawned as `__thread_main(-2)`)

- Spawned by the generated `__gc_program_start()`, which is non-empty only when the program has store roots, from `__serve` and `__run_timers` after boot.
- Unpinned, with a 1 MB stack. Signals are blocked as in other threads.
- It has its own arena for temporaries such as log lines, so nothing leaks into its heap.

```
loop:
    futex_wait(&__gc_want, 0, 1000 ms)
    if __gc_want || __heap_live >= __gc_trigger:
        __store_lock_gc(); if phase == IDLE { __gc_start() }; __store_unlock_gc()
        while phase == MARK:
            sleep(duty_gap)                      // 3×slice (25%), 1×slice (50%), 0 (100%)
            __store_lock_marker()
            if phase == MARK && __gc_mark_slice(SLICE) { __gc_terminate() }   // re-check: emergency may have finished it
            __store_unlock_marker()
        while phase == SWEEP: __store_lock_marker(); __gc_sweep_slice(SLICE); __store_unlock_marker(); sleep(slice)
        __gc_scavenge(retain()); __gc_want = 0; __gc_poked = false; log
    else (1 s tick): if no store allocation for 10 ticks and heap_live > heap_marked + 1 MB → run a cycle;
                     then __gc_scavenge(idle ? 0 : retain())
```

### 8.2 Pacing

- `goal = max(KHRIP_GC_MIN_MB (4 MB), marked × (1 + m × KHRIP_GC/100))`.
  - Adaptive `m` (from Design 1): survival = `marked / heap_live` at termination start. Above 0.85, `m = min(2m, 8)`; below 0.5, `m = 1`.
  - Optional soft limit: `goal = max(min(goal, KHRIP_GC_LIMIT_MB), 1.1 × marked)`.
- `trigger = marked + 0.7 × (goal − marked)`.
- `hard = max(2 × goal, goal + 64 MB)`.
- Duty cycle:

| `heap_live` | Duty |
|---|---|
| below goal | 25% |
| above goal | 50% |
| above 1.25 × goal | 100% |
| above 1.5 × goal | writers assist (§8.3) |

### 8.3 Writer assist

In `__store_release_final` with `HELD == 1`: if `phase == MARK && heap_live > 1.5·goal`, run one `__gc_mark_slice(SLICE)` (plus termination if it is done) before unlocking. The writer already owns `rw[0]`.

### 8.4 Hard limit and emergency collection

- `__gc_hard_check()` runs at `__persist_copy` and at the STORE branch of `__alloc_for_k`, **before `__pmode_on`**, when `HELD == 1` and `heap_live ≥ hard`. It calls `__gc_emergency()`:
  1. `__pin_publish(rec)` for itself while holding the lock (the only allowed linked-while-holding case; verify knows it). This is sound by I7: the caller's values are in callee-saved registers, stack or arena.
  2. If MARK: finish stop-the-world (drain; scan captured arenas — no `SELF` is possible under exclusive; terminate).
  3. If SWEEP: sweep all.
  4. `__gc_start()` (which captures its own record), finish stop-the-world, sweep all.
  5. Unlink itself.
- At a final release with `heap_live ≥ hard`, the same steps run without publication: the context is done with the store (I8). A request nested in a test's `call` is the exception: its final release is not the end of the test's work (the test's frames and arena above it still hold store pointers), so it does not collect; the test point right after it (§6.8) collects with the test published. A collection *inside* the nested request (the steps above) publishes the whole stack, the test's frames included.
- This bounds memory for runaway requests and every-tasks, which the GC thread cannot interrupt. The pause falls only on a context that already holds the exclusive lock.

### 8.5 KHRIP_DATA

- Restore: §5.3.
- Save (`__save_store`, http.kh:1008):
  - uses `__store_lock()` and `__store_release_final()`;
  - wraps the snapshot in a catch (`__setjmp` into `CTX_CATCH`); on error it prints `khrip: cannot save store to <path>: <message>`, keeps the previous file, and retries after the next change.
- The GC's own locks do not bump `__store_touches`.

| Variable | Meaning | Default |
|---|---|---|
| `KHRIP_GC` | headroom percent; `off` disables collection (allocation still uses size classes) | 100 |
| `KHRIP_GC_MIN_MB` | minimum goal | 4 |
| `KHRIP_GC_LIMIT_MB` | soft memory limit for the store heap | none |

Example log line:

`gc 12: heap 3.0→0.7 MB, live 0.64 MB (16,120 obj), m 1, pins 3 rec/702 words, arenas 2 (18 KB, 1 handed off), start 14 µs, mark 0.58 ms in 4 slices (max 198 µs), term 22 µs, sweep 0.05 ms, released 1.2 MB, rss-store 4.1 MB, long holders 1 (31 cycles, 6,046 words), next at 3.0 MB`

"Long holders" are records published at least 10 cycles ago. They are reported, never waited for (Design 1's watchdog, adapted).

### 8.7 Verify mode

1. At each start: every touched record is linked. W1 hash at every withdrawal. `__co_put` asserts the record is unlinked.
2. At each termination, an **independent re-mark** under `rw[0]` into a shadow bitmap:
   - typed from roots by descriptor (Design 0's `tmark`: list tails, dead map entries and slots are not pointers);
   - from saved pin words via resolve, then ptrbits.
   - It asserts: shadow ⊆ MARK; every typed pointer word points to an allocated STORE start (or +8 for variants) or DATA; every typed pointer word has its ptrbit set (this catches a wrong K_NOSCAN); and **no ARENA or HEAP address appears in the graph** (I1).
3. Sweep poisons freed slots with 0xDE; allocation checks the poison before zeroing.
4. Every 1024 page-heap operations: recompute the tree and compare.
5. `__salloc` asserts `HELD == 1` or a GC context.
6. `__gc_marking == 0 || __gc_slow` (the fast path sets no MARK bit, §4.2), on every slow allocation, at every release and in every heap check.

The checks are linked into a program only when it is compiled with `KHRIP_GC_VERIFY` set (`1` or `fast`) or by `khc test` (lib/gc_verify.kh; otherwise the stubs of lib/gc_noverify.kh, which warn at start if the variable is set at run time only). At run time `KHRIP_GC_VERIFY=1` also sends every allocation through the slow path, so the per-allocation checks see all of them; `KHRIP_GC_VERIFY=fast` keeps the fast path and so tests it, with the same graph and heap checks.

## 9. Correctness argument

**Definitions.**
- A *holder* is a context in a unit of work (request, task, test) that has acquired the lock in that unit and has not made its final release.
- While a holder does not hold the lock, its record R has eager words E and an arena range A.

**Lemma 1 (complete snapshot).** At the start of cycle K (exclusive lock), every STORE pointer that any context may dereference later lies in at least one of:
- the roots;
- E ∪ A of a linked record;
- or the context will obtain it later while holding the lock.

*Proof.*
- No context holds the lock during the start.
- A context that has not touched the store in its unit holds no store pointers: it gets them only through `store_touch` or `__pmode_on` → `__store_lock`. The response and the arena of a finished unit are never dereferenced again.
- Every other context is a holder that is not holding the lock, so by I3 and I4 its record is linked and complete.
- Window code (W1, W2) neither creates new hidden copies nor loses pointers below `hi`, so A at any later time before withdrawal equals A at publication.

**Lemma 2 (marking covers the snapshot).**
- Eager words are copied at start.
- Arena words are resolved before the holder resumes (I9) or at termination.
- SATB (I6) means every object reachable at start from roots or pins is marked by termination: each path to it is either intact when the marker traverses it, or loses an edge whose target is shaded at deletion.
  - In-library moves cannot hide an element behind a scan position (partial-array rule).
  - A grown-away array is shaded.
- Objects allocated during MARK are black.

**Lemma 3 (pointers obtained during the cycle).** A pointer obtained under the lock at time t during MARK points to an object reachable from roots at t. The object is either snapshot-reachable (Lemma 2 marks it) or allocated after start (black). A pointer obtained in a window comes from an immutable object reachable from the record, and is therefore marked by Lemma 2 through ptrbits.

**Theorem (no use-after-free).**
- Suppose context H dereferences an object O after the sweep of cycle K freed it, so O was unmarked at termination of K.
- By Lemmas 1–3, every pointer held by any context at start(K), or obtained up to termination(K), points to a marked object. So H must have obtained O after termination, from a reachable object or root.
- But an unmarked object is unreachable at termination, and it cannot become reachable afterwards: re-attaching it needs a context holding it, which contradicts the above.
- The collecting context itself is covered by I8:
  - the GC thread holds no store pointers;
  - final-release collectors are done;
  - emergency and test collectors are in their own record (captured by the start they run).
- Readers running during termination or sweep hold only marked objects (Lemma 3), and readers never read GC metadata.
- Conservative words that hit free slots are ignored (START clear). Because the sweep completes before the next start (I10), a stale word can never revive a slot that is half-swept.

**No lost updates.**
- The collector never moves, copies or writes a live object. It writes only bitmaps, span and page metadata, freed slots (poison) and zeroes for newly allocated free slots.
- Writers remain serialised by `rw[0]`.
- Double allocation of a live slot would be a lost update; verify mode detects it (poison check), and I5 makes it impossible by construction because START bits are written only under `rw[0]`.

**No deadlock or starvation.**
- The collector never waits for a holder.
- It takes the lock as a writer does, and the lock is never held across a suspension.
- The only waits on a holder are a reader's bounded spin on `GC` (cleared within one chunk) and termination's spin on `SELF` (the reader needs nothing from the GC).

**Memory bound.**
- `heap_live ≤ hard` always (emergency).
- Under normal pacing, `heap_live ≈ goal`.
- Pinned garbage is bounded by what holders actually reference (first-hop conservative) and ends when they finish.
- RSS ≈ `heap_inuse + min(retain, free) + 4% metadata`.

### 10.1 JSON encode cycle detection (`__json_encode`, api.kh:379; `__json_enc`, :249)

- `__json_encode` resets the ctx+240 depth and the ctx+248 set to 0.

| # | Failure | Consequence | Mitigation |

## 14. Implementation order

Every step ends with `./build.sh` (khc2 == khc3) and `tests/run.sh` green. From step 3 on, it is also run with `KHRIP_GC_VERIFY=1`, and from step 5 on with `KHRIP_GC_STRESS=1`.

1. **Prerequisite fixes (no GC).**
   - `__struct_alloc` `max(n,1)`; iterative `__deep_copy` with forwarding; JSON cycle detection plus `__save_store` catch.
   - `__fetch` restructure; `__alloc_for` heap owners → `__alloc_heap`.
   - Barrier rule "not STORE∪DATA" plus the `__data_end` builtin.
   - `__call` restores the test's lock; api-mode `var` globals persisted; zeroing of vacated store slots.
   - **Tests:** arena cycle persist (was a segfault); `Pair{a: xs, b: xs}` sharing kept; cyclic KHRIP_DATA error with the old file kept; fetch with a store headers map under concurrent writers; `var` global across tests; the test lock is held after `call`; zero-field struct identity.
   - **Brought forward from step 2 after review.** The "not STORE∪DATA" rule would otherwise deep-copy user globals whose initial values were still on the heap, so sharing would depend on whether the global had been reassigned or restored. So `__init_stores` lands in step 1. In api_mode, user globals are initialised there through `store_write`. `__serve`, `__run_timers` and `__tests_init` call it under the store lock right after `__store_init`, and the `fn main` of a program with tests calls it before `main`. The Buf ban (`store_raw_type`) also covers api-mode `var` globals. Until the boot arena exists, the restore runs in a temporary NORESERVE region that is unmapped afterwards (`__load_store`), so restored data no longer stays resident on the heap. The `__deep_copy` state falls back to `mmap` when the request arena is full.
2. **Roots and boot.**
   - `gc_root_table`/`__gc_roots`, `__init_stores`, boot arena, `__store_boot`, restore through persist.
   - **Tests:** a debug walker (gc.kh, verify) confirms that after boot and after restore every graph pointer is in STORE or DATA; the RSS of a 50 MB restore drops after boot; restore/save round-trip; restore of a v0.12 snapshot.
   - **As built.** The boot arena is not reset with `__arena_end` but unmapped whole after boot: it is never reused, and `__arena_end` would keep up to 32 MB of zeroed pages resident (and its commit charge under strict overcommit). The lock calls are still `__store_lock`/`__store_unlock` until step 4, `__store_init` stays in core.kh until step 3, and `__heap_marked`/`__gc_pace` wait for the heap accounting of steps 3 and 5. The restore peak is ≈ 22× the file, not ≈ 3×: `read_file` takes 2.2× and `from_json` 15×, because the decoder builds every element's error path eagerly (lib/api.kh, `__jd`); all of it leaves with the arena (51 MB file: peak 1.1 GB, 174 MB after boot).
3. **Store heap without collection.**
   - Size classes, spans, page heap, bitmaps, typed allocation, descriptor `ptrmask`, combined strings, `nostore.kh` and shim stubs, `__store_mut`.
   - **Tests:** `__ph_selftest` (100k random alloc/free against a brute-force bitmap); verify-mode I5 checks on every request.
   - **Bench:** store allocation overhead on patch and bank ≤ 2%.
   - **As built.**
     - 65 size classes, not 66: Go's 24-byte class is dropped because objects sit on 16-byte granules (one START bit per 16 B), so 130 span classes. The class table is a `__data_hex` table (size / 16 and pages per span).
     - Span record: w2 is the slot size (all bytes for a large span), w3 freeindex as an address, w5 `magic | nelems << 32`, w7 the fast-path end of slots, 0 when the span needs zeroing (NEEDZERO). There is no verify allocation counter; `nfree` comes with the sweeper (step 5, high half of w6).
     - `__salloc` has a fast path for objects up to 1 KB when the freeindex slot of the current span is free and nothing else is on: no NEEDZERO (w7 = 0), and the flag `__gc_slow` clear (§4.2). The fast path sets no MARK bit, so `__gc_slow` covers marking as well as `KHRIP_GC_VERIFY=1`; `__gc_set_marking(on)` is the only way to change `__gc_marking` and recomputes `__gc_slow`, and verify mode asserts `__gc_marking == 0 || __gc_slow` (§8.7). Everything else goes through `__salloc_slow`. An empty class points at a zero span record (`__gc_none`), so the fast path does not test for 0. The START and PTRB words are addressed from `p` directly (`GC_START_P`, `GC_PTRB_P`), without subtracting `STORE_REGION`. Measured: ≈ 148 instructions per object in the fast path (Khrip's own codegen).
     - Invariant added: **the PTRB bits of free memory are zero.** Allocation only ORs bits in, so whatever frees memory clears them (§4.2, §7.7). The span transitions the sweeper needs exist already, with their tests (tests/api/gc_spans.kh): `__span_rewind` (freeindex = base address, fast-path end 0, NEEDZERO) and `__span_free` (START, MARK, PTRB and PAGEMAP of the span cleared, record zeroed, pages free and dirty).
     - The page heap grows its capacity (doubling, tree rebuilt) when first fit fails, not when commit grows; pages are committed after the run is found and before it is taken, so an `mprotect` failure changes nothing. `released` is allocated but unused until the scavenger.
     - Library selection is made after lexing: `gc.kh` for a program with a `store` token in its own source (not the library's) or `khc test`, otherwise `nostore.kh`, which every CLI program (khc included) now loads. Every store branch of core.kh and api.kh goes through a function that gc.kh defines and nostore.kh (and the boot shim) stubs: `__store_on`, `__store_for`, `__salloc_for`, `__struct_salloc`, `__store_mut`, `__store_panic`.      - With gc.kh, the verify code is a separate file: lib/gc_verify.kh (owner, zero and marking checks, the graph walker, the heap check and the page-tree check) is linked only when the program is compiled with `KHRIP_GC_VERIFY` set or by `khc test`; otherwise lib/gc_noverify.kh supplies empty stubs and warns at start if the variable is set at run time only.      - Out of memory inside store mode (the store region's `mprotect` refused, or the page heap at its limit) is a panic, not a stack overflow: `__panic` and `__panic_msg` leave store mode first (`__store_panic`), so the panic text is built in the arena, and the request ends with a 500. A second failure writes a fixed text and exits without allocating. 5. **Stop-the-world collector (the go/no-go gate).**
   - The GC thread runs whole cycles under exclusive.
   - `__gc_test_point`, emergency, sweep-all, scavenger, idle release, pacing (m fixed at 1), log, verify re-mark, poison.
   - Memory is bounded from here on.
   - **Tests:** the whole safety matrix (§15) plus eval patch at RSS ≤ 12 MB.
   - Pauses are proportional to live data at this step; it does not ship.
   - **As built.**
     - **Cycle.** One function, `__gc_collect_now(self, why)` (lib/gc.kh), runs a whole cycle; the caller holds store exclusively: the GC thread and the test points through `__store_lock_gc`, a writer through its own exclusive lock. Start (§7.2): with verify, the record check of step 4 now also runs at every cycle start (`__gc_verify_records(self, false)`: every other touched record is linked, the collector's own record is skipped); `__gc_cycle_no` and `__store_epoch` (string caches, lib/text.kh) grow; `__gc_set_marking(true)`; roots; records. The eager words of each linked record are resolved at once — no separate pin array: under exclusive no record can change before the cycle ends. A record with an arena goes to the captured list as `PENDING` and the drain scans it through the hand-off (`CAS PENDING→GC`, scan, `DONE`; `HANDED` and `SELF` are handled but cannot occur yet); termination requires `DONE` and sets every captured record back to `IDLE`, so the step 4 check "every `ast` is IDLE" keeps holding between cycles (I9). The marker and the verify skip the arena's first `STRC_SIZE` bytes (the string cache: keys, not references), as the W1 hash does.
     - **Mark.** `__gc_resolve` as §7.3 (pagemap, `INUSE`, magic division, span tail, START, MARK test-and-set), with the high-water mark frozen at start; a grey stack of `(slot, slot size)` pairs in mmap scratch (doubling; returned after a cycle when over 1 MB); `__gc_scan` walks the PTRB words of the slot with `ctz`. No frames or chunking (step 6): a 1M-element reference array is pushed element by element. Out of scratch memory is "out of memory in the store collector" and exit 101.
     - **Termination and sweep.** `__heap_marked = __heap_live =` marked bytes; `__gc_sweepgen += 1`; every `__gc_cur[sc] = __gc_none` and the partial lists empty (I10); then the sweep of every span in address order, inside the same pause. A first pass counts survivors (`popcount(START & MARK)`): a span without them goes to `__span_free` at once (verify poisons its objects first); otherwise each freed slot loses START and its PTRB bits (inline for slots up to 64 words), verify fills it with 0xDE, MARK is cleared, and a span with free slots is rewound (`__span_rewind`) and appended to the partial list of its class (`S_NEXT`: next base page + 1 in the low half, `nfree` at the sweep in the high half). `__gc_refill` pops the head of that list (lowest address first) before making a new span. Verify: the bytes the sweep kept equal the marked bytes, and the heap check runs after the sweep.
     - **Who collects.** The GC thread (`__thread_main(-2)`, 1 MB stack, its own arena for log lines) is started by `__serve` and `__run_timers` after boot when the program has store roots and `KHRIP_GC` is not `off`; it sleeps on a futex word (`__gc_ctl`) with a 1 s timeout, `__salloc_slow` and `__salloc_large` wake it once per cycle when `__heap_live` passes the trigger, and it re-checks the trigger under the lock (a writer may have collected meanwhile). Ten 1 s ticks without store allocation are idle, once per idle period: a cycle if more than 1 MB was allocated since the last one or store was taken exclusively since its start (`__store_touches` against `__gc_touches`: removals, `clear` and replacement by a smaller value free memory without allocating), and every free page goes back to the system. When store was taken exclusively and no cycle ran for two minutes, a cycle runs anyway (`forced`, as in Go): a delete-only workload never counts as allocation. Both snapshots start at `__gc_spawn`, so boot is not a write. (As first built, only the 1 MB rule existed: a 32 MB list replaced by an empty one was never collected.) A writer collects itself when the heap reaches `__gc_limit` at `__gc_hard_check` — in `__persist_copy` and in `__salloc_for` (growth of a store container outside a copy), before `__pmode_on` — by publishing its record, collecting and withdrawing (`__gc_emergency`); and at its final release without publication (`__pin_final`, I8) — except when the release belongs to a request nested in a test's `call` (`__gc_nested`: `__serve_one` has put the test's jump buffer back into `CTX_CATCH`, the marker `__mongo_request_end` uses too); then the test point after the request collects with the test published. (As first built, the nested release collected without publication while the test still held its values: an independent review found a test's value reused after `call` replaced it with 72 MB, and a crash under stress; tests/api/gc_nested.kh.) In `khc test`: `__gc_test_point(false)` after `__serve_one` in `__call` (exclusive GC lock, the test publishes itself, collect, withdraw), `__gc_test_point(true)` after the final release in `__test_end` (no publication); both collect when the heap passed the trigger, and always under `KHRIP_GC_STRESS`. `__gc_collect()` (tests, benchmarks) collects at once with self-publication; `__gc_stats()` returns `__GcStats`.
     - **Pacing** as §8.2 with m = 1: `goal = max(KHRIP_GC_MIN_MB, marked · (1 + KHRIP_GC/100))`, `trigger = marked + 0.7 (goal − marked)`, `hard = max(2 goal, goal + 64 MB)`. `__gc_limit` is the threshold for collections inside a unit of work: `hard`, or `marked + step` under `KHRIP_GC_STRESS`, where `step = max(64 KB, marked / 4)` (also the stress goal). A fixed 64 KB made the work quadratic in the heap: the 50 MB restore test of tests/http.sh fills 200 MB in one request, and thousands of verified full collections did not finish in 10 minutes; with the step it takes 15 s and 62 collections. Under `KHRIP_GC_STRESS` without a GC thread (`khc test`) every window is a collection point as well (`__gc_window_point`, after the unlock in `__store_release_keep`), as if the GC thread's cycle fell into the window. `KHRIP_GC_STRESS` implies the checks (`KHRIP_GC_VERIFY=1` unless the variable is set) and, set at compile time, links them.
     - **Scavenger** (`__gc_scavenge`): the candidates are free *dirty* pages (a free page that is not dirty was never touched or was already released); from the top down until `retain = max(1 MB, 1.1 · goal − pages in use)` bytes of them remain (0 when idle), at most 256 runs per call. The GC thread takes the runs under `__store_lock_marker` (`__ph_scav_take`: not free, the `released` bit marks them in flight — no span can take them, and the heap and page-tree checks treat them as free), madvises outside the lock, and gives them back as free and clean (`__ph_scav_done`). A context that collects under its own exclusive lock (`__gc_release_locked`) hands the release to the GC thread when there is one (`__gc_scav_due` and a futex wake: the request's pause holds no madvise), and otherwise (`khc test`) releases under the lock and adds the time to the pause, so `max_pause_us` and the log are honest. (As first built, contexts released under their lock outside the timed pause: freeing 288 MB took 22 ms of wall time against a reported 9.9 ms.) With each run the metadata pages (START, MARK, PTRB, SPANS, PAGEMAP) that describe only released pages are released too. `__ph_take` clears the `released` bits it takes.
     - **Log** (`KHRIP_GC_LOG=1`): `gc 31 (pace): heap 3.0->0.6 MB, live 0.6 MB (14008 obj), m 1, pins 13 rec/79 words, arenas 13 (64 KB), pause 0.47 ms (start 0.02, mark 0.31, sweep 0.13, release 0.00), released 0.0 MB, rss-store 3.1 MB, next at 3.0 MB` (`pace`, `idle`, `forced`, `in request`, `at release`, `test`, `window`, `explicit`; long holders when there are any; "pages released by the GC thread" instead of the released and resident numbers when the release was handed over).
     - **Verify** adds: the record check at every cycle start; before the sweep an independent re-mark — a PTRB walk from every word of every published record (eager words and arena) and the typed walk from the roots — in which every reached object must be marked (`__gcv_marks`), with the heap check; after the sweep the heap check again; 0xDE poison in freed slots, checked word by word (each word 0 or poison: memory where no object lived is zero) when a `NEEDZERO` span or a dirty large span is allocated from. The walker takes the shortest of a map's keys, values and entries lists: a collection inside `__map_set` (list growth) finds a key without its value yet.

"Live drops" is checked in the next test: a collection inside a test also keeps what the test's stack and arena still point at. 6. **Incremental collector.**
   - Marker lock mode, slices, frames, SATB (compiler `__barrier_at`/`__barrier_idx`/`__persist_root` and the library table), allocate-black, concurrent hand-off, termination under `rw[0]`, sweep slices, duty, assists, adaptive m, soft limit.
   - **Tests:** stress with 5 µs slices; the concurrency suite; verify re-mark at every termination.
   - **As built (6a: incremental marking; branch `v013-gc6a`, with the fixes of the independent review).** Sweep slices, duty cycle, writer assist, adaptive m and the soft limit are 6b.
     - **Cycle.** Start stays exclusive (`__store_lock_gc`): cycle number, `__store_epoch`, `__gc_set_marking(true)`, the roots (resolved, i.e. marked and greyed — not scanned), and the records: the eager words of every linked record are copied into a **pin array** (mmap scratch, resolved in slices, because a holder may re-publish as soon as it resumes), arenas go to the captured list as `PENDING`. There is no drain at start. The GC thread then runs **slices under `__store_lock_marker`** (`rw[0]` only: writers wait, readers keep running) of at most `KHRIP_GC_SLICE_US` (default 200; 5 under `KHRIP_GC_STRESS`), with a gap of three slices between them (marking takes a quarter of the time; the duty adaptation is 6b). The clock is read every 128 work units (a unit is about two words the marker looks at), and a slice ends when one more interval like the last would pass the budget, so it stays under the budget rather than one interval over it. Priority order as §7.4 — captured arenas, pin words, grey, the top frame, the overflow list — except that new words from arenas, handed-off buffers and pin words are taken only while the grey stack holds fewer than 4,096 pairs (otherwise a dense arena of 600,000 references grew the grey stack to 10 MB, and its doubling memcpy took 3 ms inside one slice); collector buffers now grow with `mremap`. Every indivisible unit looks at no more than 256 references and is weighed at least 128, so the clock is read right after it: a reference to a cold object in a large heap costs up to 0.75 µs (cache and TLB misses on the page map, span, START and MARK), and a 4 KB grey object took up to 0.4 ms. Captured arenas: chunks of up to 256 KB that stop after 256 words with a value in STORE (`CAS PENDING→GC`, then `PENDING` with `aoff` where it stopped, or `DONE`); a `HANDED` buffer is resolved 256 words at a time from its end (`hlen` shrinks; the record stays `HANDED` until it is empty — its context no longer touches it); `SELF` is skipped. A slice with nothing left but `SELF` arenas ends without starting termination; termination starts when they have handed off.
     - **Frames.** A grey object over **2 KB** (not 16 KB) becomes a frame `(obj, scanned bytes, slot size)`; at most 8 (a stack, the top one is scanned), further large objects wait in an overflow list and become a frame when one is popped. A frame is scanned **256 words** at a time, not 2048 (see the cost of a cold reference above). Chunks are scanned only when the grey stack is empty, so the children of a chunk are drained first.
     - **SATB.** Compiler: `x.f = v` emits `__barrier_at(obj, off, v, d)`, `xs[i] = v` emits `__barrier_idx(xs, i, v, d)`, a store global and an api-mode `var` emit `__persist_root(v, d, slot)` (programs without store keep `__barrier`/`__persist`). Both object barriers first run `__store_mut` on store objects (a compiled field or element store into store without the exclusive lock is a 500, not a race with the marker), then copy the new value into store, and only then shade the old value: the copy's hard-limit check can start a cycle (the `KHRIP_GC_STRESS` step in `khc test`), and a shade taken before it missed an old value that was in the start's snapshot (found by the new verify check, tests/api/gc_var.kh under stress). Library (core.kh): map set over a key, remove (key string and value), clear (every key and value) and the old slot table of rehash and clear; list growth (the old array), pop, truncate and clear (`[from, len)`), remove_at; the partial-array rule in remove_at (the one element on the scan boundary) and in reverse, sort, sort_by and rehash compaction of keys and values (the unscanned rest is shaded and the frame finished). Every hook is an unconditional call of a short gc.kh function that the compiler inlines — `if __gc_marking != 0 { ... }` — so without marking it is one load and branch; nostore.kh and the boot shim define them empty, and programs without store get no code. Shading always goes through `__in_store` of the container, so arena lists of readers never touch collector metadata (I5).
     - **Allocate-black.** `__salloc_slow` and `__salloc_large` set MARK during marking (the fast path is off then) and count the bytes; termination sets `__heap_marked = __heap_live =` marked + black, and verify's "the sweep kept exactly the marked bytes" compares with that sum.
     - **Hand-off (§6.3, I9).** A holder that resumes during MARK withdraws through the existing protocol: `PENDING → SELF`, scan of `[lo + aoff, hi)` into `hbuf`, `HANDED`; a reader that finds `GC` spins (pause, `sched_yield` every 1024 spins) for one chunk; termination waits on `SELF` the same way. `hbuf` grows with the words found, not with the arena: the arena is scanned 8,192 words at a time and the buffer doubles (a 600 MB arena of strings used to map a 1 GB `hbuf`). At termination every `hbuf` over 1 MB goes back to the system — the GC thread unmaps them after it releases the writers' mutex (unmapping 6 × 8 MB took 4–5 ms inside termination), a collection under the exclusive lock unmaps them at once. A failed `hbuf` allocation no longer ends the program (it used `__gc_scratch`, exit 101): the context marks the rest of its arena and the words it has found itself, where nothing else marks. A writer holds the writers' mutex (no slice runs) and a program without a GC thread marks only under the exclusive lock, so they do it at once. A reader runs in parallel with slices and cannot take the writers' mutex under its lock (a writer that holds it waits for readers), so it puts the record back to `PENDING` with `aoff` where it stopped (termination and a whole cycle treat that as collector work, so nobody waits for it), publishes it again, releases the lock, takes the writers' mutex, and if the arena is still `PENDING` — of this cycle, or of the next one, then from the start — marks the rest and the words found, sets `HANDED` with an empty buffer, and takes its lock again: an audited window (W1: it writes nothing; tests/store_windows.sh lists `__pin_self_fallback` among the `__store_unlock_raw` sites). The thread waits only for the mutex (a slice, a termination try or a writer's work), then holds it while it marks the rest of its arena. `__pin_self_scan` appends to `hbuf` (capture empties it every cycle). As first fixed, the reader instead waited for the collector, spinning on `ast` with two loads per check: a chunk ending between them (`GC → PENDING`) let it leave while its arena was still with the collector, and its next self-scan reset `hlen` and dropped the words it had found — a use-after-free the second review reproduced with growth failing only after a partial fill; the spinning also stopped every request of the worker thread (holds p99 565 ms on dense.kh). `KHRIP_GC_FAULT` (verify builds): `hbuf` makes every allocation fail, `hbuf2` only the growth of an `hbuf` that already holds part of the arena.
     - **Termination (§7.6)** under `rw[0]`: drain (arenas, `SELF` waits, pins, grey, frames) with a 2 ms budget; over budget the mutex is released and slices continue. From the fourth attempt on the drain is unbounded — but only once no captured arena is left: their work is finite (writers do not add to it), and a holder that scans its own arena needs nothing from the collector, so holding the writers' mutex for it is pointless (a 600 MB arena took 13–29 ms that way). Then the captured records go back to `IDLE` (large `hbuf`s are released), verify checks (below), marking is turned off, the live heap is set, every `cur` and partial list is reset, and — still in the same lock hold for 6a — the sweep runs, timed separately, then pacing.
     - **Whole cycles.** Emergency (`__gc_hard_check`), a final release past the limit, test points, `__gc_collect()` and `call` during MARK first finish the cycle in progress from its current state (`__gc_finish_stw`: drain, terminate, sweep; the collecting context needs no publication for that, because everything it held at the start is in the start's records and everything it obtained since is marked or black), then run a whole cycle with themselves published (or done, I8). The nested-release rule of step 5 stays: a release nested in `call` does not collect.
     - **Verify.** At every cycle start, under the exclusive lock, an **independent snapshot**: everything reachable from the roots, from the eager words of every linked record (found through the registry of all records, not the threads' lists or the pin array) and from the words of their arenas `[lo, hi)` read directly (not through captured chunks or `hbuf`), following PTRB — one bit per 16 bytes of STORE below the frozen high-water mark, like MARK. At termination every object in the snapshot must be marked; then the typed walk from the roots checks every reached object (which also catches an object allocated during marking without its MARK bit). This is SATB's own promise, so a lost object is reported even when nothing reaches it any more: a marker that drops pin words or skips arena words, or a missing barrier after which the object is held only by a waiting context. Records published during marking are not checked: their conservative stack and arena words can be stale (one tests/gc/server.kh record had 5 of 9 words pointing at garbage of the start). The simulated start at every exclusive acquisition accepts non-`IDLE` hand-off states of the current cycle during MARK, but never `GC` or `SELF` under the exclusive lock.
     - **Stress.** With a GC thread, `KHRIP_GC_STRESS` starts the next cycle 8 KB after a sweep and puts the in-work limit at marked + max(512 KB, marked/4): under load the thread is marking nearly all the time, and a request that outgrows the limit finishes the thread's marking stop-the-world. In `khc test` (no GC thread) stress points step incrementally instead of collecting whole: a hard-limit point starts a cycle (publishing itself and handing its own arena off at once) or runs 256 work units, a window starts a cycle (the resumed context hands its arena off); test points still collect whole. The stepping lives in gc_verify.kh (stress implies verify).
     - **Log.** `gc 41 (pace): heap 1.7->1.5 MB, live 1.5 MB (38351 obj, 1225 black), m 1, pins 15 rec/94 words, arenas 15 (70 KB, 2 handed off), start 8 µs, mark 2.77 ms in 12 slices (max 211 µs, cpu 198 µs) over 11.2 ms, term 4 µs (1 tries), sweep 0.34 ms, released 0.0 MB in 0.00 ms, rss-store 2.0 MB, next at 1.7 MB`; `cpu` is the largest thread CPU time of a slice in the cycle (it tells preemption from work); a cycle finished by someone else says `(pace, finished in request) ... finished in 2.10 ms`; a whole cycle keeps `pause P ms (start, mark)`.

     - **Sweep slices (§7.7).** Termination (`__gc_mark_done`) no longer sweeps: it ends with `__gc_sweepgen += 1`, every `cur` and partial list reset, the sweep cursor `__gc_sweep_pg = 0`, adaptive m and pacing (below). The GC thread then sweeps in slices of `KHRIP_GC_SLICE_US` under `__store_lock_marker` (`__gc_sweep(us, work)`): pages in address order from the cursor; the high-water mark is read again at every step, because writers create and the sweeper frees spans between slices; a page that does not start a span is skipped one at a time; a span whose sweepgen is already current (created after termination) is skipped. The clock is read every 32 START words (4 pages of spans) with the same "stop before the interval that would pass the budget" rule as marking. While the sweep runs, allocation takes only swept spans (the partial lists, which the sweeper appends to in address order) or new spans, which get the current sweepgen; the fast path cannot reach an unswept span because every `cur` was reset. **I10:** every start goes through `__gc_begin_cycle`, which finishes an unfinished sweep first, at once (whole cycles, the test API); the GC thread always sweeps its own cycle to the end in slices before it starts another, and in `khc test` the `KHRIP_GC_STRESS` steps step the sweep by `GC_STRESS_WORK` units like marking — so the whole stress suite allocates during sweeps. Termination by itself is now 2–4 µs. `__span_free` clears only the start bit of a large span and no PTRB bits of a NOSCAN span (both are known to be zero elsewhere): freeing a 20 MB list array took 0.2 ms of one sweep slice on bank. Verify: the start asserts that the sweep has ended (I10); the bytes the sweep kept are summed over the slices and compared with marked + black at the end, as before; the heap check counts an object of an unswept span as live only if it is marked and reports a MARK bit outside marking anywhere but on an object of an unswept span; the graph walk and `__gc_obj_of` (test API) treat a dead object of an unswept span as free, so a reachable object there without its mark — the trace of an allocation into an unswept span — fails the walk.
     - **Duty (§8.2).** The gap before each slice (marking and sweeping) follows the heap: three slices below the goal, one slice above it, none above 1.25 × goal; without a gap the thread gives the mutex away for 20 µs only when a writer waited for it (`__store_unlock_marker` now says so — the futex word was 2), because the mutex is not fair and a writer would otherwise never get it. The goal here is the goal of the cycle, `__gc_cgoal`: the goal, or the heap at the start if the heap is already above it — a dictionary or list that doubles right at the trigger (notes: the map rehash) put the heap past the goal before marking began, and every writer then assisted a cycle that was not behind (notes p99 doubled). A sweep runs without gaps once the heap passes the next trigger (the next cycle waits for it).
     - **Writer assist (§8.3).** In `__pin_final` (final release, `HELD == 1`, not busy, not in store mode): above the in-work limit the whole collection as before (except nested in `call`); otherwise, during MARK above the cycle goal, `__gc_assist()` under the writer's exclusive lock. Above 1.5 × goal it marks for one full slice; between the goal and 1.5 × goal it pays by credit, as in Go: the debt is the bytes allocated black since the last payment (`__gc_black_bytes − __gc_paid`), the price is the estimated remaining work (the previous cycle's total units minus the units done, at least an eighth of the estimate) over the room left to 1.5 × goal, and the work is bounded by the slice budget either way. If marking ends, the assist terminates the cycle (then nothing is left to drain, so it is short) and the GC thread sweeps. A release nested in `call` may assist (marking frees nothing); a window never does (assist runs only where the context holds the lock at its final release). Termination by anyone with a GC thread leaves `hbuf`s over 1 MB on the thread's list (it takes the list under the mutex and unmaps outside it); a handed-off `hbuf` over 1 MB is released as soon as it is resolved, not at the end of marking.
     - **Adaptive m, pacing base, soft limit (§8.2).** At termination, survival = bytes the marker traced / heap at the start (black excluded: objects allocated during the cycle are not part of the heap it traced); above 0.85 m doubles up to 8, below 0.5 m = 1. The goal is computed from `__gc_base` = traced + black × survival, not from marked + black: black objects are kept by this sweep, but a writer that makes garbage faster than the marker turns most of them into garbage at once, and counting them as live doubled the next goal from floating garbage (dense.kh: goal 160 MB from 20 MB live). If the estimate is short, the next cycle simply starts sooner and traces what really lives. With `KHRIP_GC_STRESS` the base stays marked + black. `KHRIP_GC_LIMIT_MB`: goal = max(min(goal, limit), 1.1 × base). The log line shows m.

Assists also run between the goal and 1.5 × goal, by credit; duty and assists use the cycle goal (raised to the heap at the start). At 100% duty the thread yields the mutex for 20 µs when a writer waited. With `KHRIP_GC_STRESS` and a thread the goal is halfway to the in-work limit. The log is linked only with `KHRIP_GC_LOG=1` at compile time. Records copy the stack from the publisher's register save area, not its rsp. A handed-off `hbuf` over 1 MB is released when resolved, and every termination with a GC thread defers unmapping to it.
     - **Risks.** Writers on an allocation-heavy store pay for marking with latency: dense.kh with 30 ms holders has a higher writer p99 than 6a (15–17 against 11–12 ms), and a tight `KHRIP_GC_LIMIT_MB` makes nearly every writer assist (bank at 100 MB: 9,221 assists in one cycle, each bounded by credit). An assist runs under the exclusive lock, so readers wait for it too (at most one slice). The pacing base trusts that black objects survive at the traced rate; a burst that builds a large live structure during a long marking is under-counted once, and the next cycle starts at once to correct it. The `hbuf`s of holders that resume in the middle of a cycle still dominate RSS with dense arenas. Wall-clock slices on this VM are often twice their CPU time (preemption and steal on 4 vCPUs shared with the load generator); no priority setting helped measurably. Per-cycle CPU maxima of 1–3.5 ms appear in single slices on bank; the units inside them are bounded, and the rest is kernel time this kernel charges to the interrupted thread.
7. **Measure and document.**
   - `eval/perf.sh` for every language, 60 s soaks, frag and delete-heavy benchmarks, report `bench/results/2026-xx-xx-v0.13-gc.md`, docs (§17), version 0.13.0.

## 18. Out of scope, and risks

### Deliberately not in v0.13

| Item | Why not | How it would fit |
|---|---|---|
| Evacuation of sparse spans (mostly-copying) | Only needed if the delete-heavy gate fails. | Pins name the non-movable objects, and ptrbits make every other reference precise. |
| Lock-free KHRIP_DATA snapshots | The save is still an O(live) JSON encode under the exclusive lock, once a second after changes; for large stores it is now the biggest pause. | The SATB barrier infrastructure is the basis for a snapshot-at-the-beginning serializer (v0.14 candidate). |
| Parallel marking | Not needed with slices. | — |
| Generational collection | Not needed by any measured workload. | — |

### Risks

1. **W1/W2 depend on a code invariant, not a mechanism.** Mitigation: three audited sites, lint, verify hash, stress CI.
2. **Barrier completeness in incremental mode.** Mitigation: complete table; verify re-mark at every termination; 5 µs-slice stress.
3. **Performance is extrapolated** from Khrip prototypes (mark 18–62 ns per object, publication 0.45 µs scalar). Steps 3–5 measure it before step 6.
4. **Coupling to the UTF-8 work.** A store string is one noscan object whose header is whatever the string design defines. The collector never looks inside strings beyond that, but `__str_copy_store` must follow the final header layout.
5. **Size of the change.** About 1.7k lines in lib/gc.kh, ≈ 600 lines across the other lib files, and ≈ 250 lines in src. The stop-the-world gate (step 5) makes it safe to stop there if step 6 slips, but v0.13 ships only with step 6.
