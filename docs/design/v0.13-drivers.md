# Khrip v0.13: final design for the MongoDB and ClickHouse API

This design is built on the **schema-first** design. Both judges ranked it first (7.73 and 7.38, against 7.48/7.30 for language-forms and 7.23/7.00 for library-first). Both judges decided on the silent-trap criterion: its filters keep Khrip's own `none` semantics, and its one-document operations are checked for uniqueness.

From the other two designs it takes what the judges asked for:
- **From library-first:** its proven compiler pieces (document-literal contexts, `ObjectId` route and JSON validation, fail-closed classification), `limit: int?`, the `int` → `Decimal(P,S>0)` startup error, read-only collections that must exist, result-size caps, the not-null guard, the readonly-user check, insert deduplication tokens, sample-value retries for `DESCRIBE`, and one audited store-lock window per driver with decoding after re-lock.
- **From language-forms:** the `$sample` + `$type` startup check, the subdocument-equality error, `log_comment`, `mutations_sync`, the `wait_for_async_insert = 0` error, `$lookup` against declared collections, one read retry on a stale pooled connection, and habit-to-rewrite diagnostics.

It also resolves every problem the judges raised about the winner. §1.3 lists each one.

Two choices depart from schema-first. Both are argued in §0:
- `ObjectId` becomes a type, and `_id` keeps its name (no `id` ↔ `_id` renaming).
- The number of documents a write touches is in the method name (`update` / `update_all`), not in the expected type.

**What was checked, not only argued:**
- **A compiler and runtime prototype** of the MongoDB half was built in a temporary worktree (`drvdesign/wt-final`, from HEAD `d01f6a5`). It includes the lambda-filter translator, the judges' biggest implementation risk for the winner.
  - It is 1,204 new compiler lines (`src/coll.kh`) and 352 new library lines. It sits on top of library-first's prototype (358 compiler lines of document literals and typed calls, about 60 lines of `ObjectId`, and 551 library lines), which was ported to HEAD.
  - The self-host check passes (khc2 == khc3). All 29 `tests/run` programs give their expected output, all 114 `tests/errors` fixtures give their expected messages, and all 9 `tests/api` suites pass under `khc test`.
  - It compiles and runs, against MongoDB 8.0.34 at 127.0.0.1:27019:
    - **P1 and P2 exactly as printed in §11**;
    - the judge's orders program;
    - a "careless" variant of it that reads the customer from `header("X-Customer")` directly. This is the variant that leaked every customer's orders on library-first's prototype. Here it returns nothing (§11.1).
  - 21 compile-time diagnostics, including the pipeline shape checks, fire with the messages marked ✓ in §9.7.
  - Files: `prototype.diff` and `proto/`. The worktree is removed.
- **Server behaviour this design relies on and that no earlier design measured** was probed on MongoDB 8.0.34 and ClickHouse 25.8.33 (Appendix A):
  - ClickHouse quoting, `#` comments and heredocs;
  - parameters inside `SETTINGS`, which are rejected;
  - `KILL QUERY` output and kill by `log_comment`;
  - `session_timezone`;
  - deduplication tokens on non-replicated MergeTree;
  - partial unique indexes with `$type`;
  - `$sample` with `$type`;
  - `$expr` comparisons of two fields;
  - claiming with `findAndModify` and `sort`.
- **Tokens** were counted with `bench/tokens/count.mjs` (code only, comments removed) and `spec_tokens.mjs` (whole text). o200k comes first, then the public Claude tokenizer.

## 0. Decisions

1. **The Khrip type is the schema.** `collection notes: Note` and `table events: Event` are top-level declarations, like `store`. A collection or table is not a value, but a local may shadow its name, as a local may shadow a `store` today. *Reason:* field names, value types, sort keys, update operators and pipeline shapes are checked at compile time without a server. The declaration costs 4–6 tokens once.
2. **Filters are lambdas with exactly the meaning of `list.filter`**, translated by the compiler into a MongoDB query. Sub-expressions that do not mention the parameter are evaluated in Khrip, left to right with short-circuit, and sent as typed values. `x.owner == u` is false when `u` is none, so a missing value can never widen a query. *Reason:* this closes the silent authorization leak that library-first's prototype showed. The prototype reproduces the judge's scenario and returns nothing (§11.1), and it reuses Khrip's own type errors.
3. **How many documents a write touches is in the name.** `one`, `update`, `upsert` and `delete` touch one document. They need a filter the declarations prove unique (`_id`, or every field of a `unique` index), or `Find { sort }` to take the first match. `update_all` and `delete_all` touch every match. *Reason:* there is no arbitrary-document write, and an `updateOne` habit can never become a multi-update silently. The prototype checks this.
4. **Results follow `sql`.** The expected type picks the shape:
   - `find` gives `[T]`, or `[P]` for a smaller struct `P`, which is then a projection;
   - `one` gives `T?`, or `T` with none → 404;
   - `insert` gives the stored `T`, none on a duplicate key into `T?`, or the count into `int`;
   - `update` gives the matched count (0 or 1), or the document after the change into `T`;
   - `DbResult` is the explicit outcome of a write.

   *Reason:* one mental model with `sql`, which an AI already reads in KHRIP.md.
5. **`ObjectId` is a built-in branded `str`** (24 lower-case hex digits), and **`_id` keeps its name**.
   - `object_id()` makes one and `parse_object_id(s) -> ObjectId?` checks one.
   - Route and JSON values are validated: 400 on a bad id.
   - An `ObjectId` and a `str` never compare with `==`.

   *Reason:* MongoDB data and AI habits use ObjectId `_id`. A type makes `_id: ObjectId` vs `id: str` a compile error instead of an empty result (schema-first's S5). One name for the field in Khrip, JSON and MongoDB removes the two-spellings problem both judges raised.
6. **`none` is never stored, and a struct change has `SET {patch}` semantics.**
   - Optional fields are set only if the client sent them.
   - An explicit JSON `null` becomes `$unset` for an optional field, and a 400 `missing value: notes.title` for a required one.
   - A none value in a `{"$set": ...}` literal writes nothing.
   - Removing a field is always the explicit `$unset`.

   *Reason:* the KHRIP.md PATCH idiom keeps working (В2), and "none" has one meaning in every write.
7. **Document literals exist only where MongoDB needs operators:** the change of `update`/`upsert` and the stages of `aggregate`.
   - Keys are string literals.
   - Operators, field paths and value types are checked against `T`.
   - Pipeline shapes are tracked, so `"$amout"` is a compile error.
   - `$lookup.from` must name a declared collection.
   - Strings from data in expression stages are sent as `{"$literal": s}`, recursively.
   - `$where`, `$function` and `$accumulator` do not compile.

   *Reason:* operator and field-path injection cannot be expressed (В3 analogue), and a typo can no longer silently give 0.
8. **Options are a literal `Find { sort, skip, limit }`.**
   - `sort` is made of string literals (`"-created, title"`), or of literal variants through `if`/`match`, like `ORDER BY {o}`.
   - `limit` is `int?`: none means no limit, 0 gives `[]`, and a negative value is 400.
   - `skip` or `limit` without `sort` is a compile error, mirroring `sql`'s `LIMIT` without `ORDER BY`.

   *Reason:* this closes the `?limit=0` → everything trap and unstable pages (schema-first S6/S7), and removes positional traps (Н2).
9. **ClickHouse queries are `ch "..."`** (also `` ch `...` `` and `ch NAME "..."`), lexed by `lex_sql` in a ClickHouse dialect.
   - `{x}` becomes `{pN:Type}`, with the type derived from the Khrip type.
   - `{x:Int64}` is a compile error with a hint.
   - Every `sql` rule carries over.
   - DDL is allowed only in `migration ch N`.

   *Reason:* injection cannot be written (В3), and the form is visible and consistent with `sql`. All three designs converged on it.
10. **ClickHouse rows are written with `table events: Event` and `events.insert(rows)`.** Rows are encoded to the real column types through the cached `DESCRIBE` plan, with Khrip's seconds semantics for dates.
    - `int` into `Decimal(P,S>0)` is a startup error.
    - Columns that would silently get `0`/`''`/1970 are startup errors.
    - `Insert { dedup }` sets `insert_deduplication_token`.
    - `async_insert` in the table block waits for the flush.

    *Reason:* В6 is closed, and the money-×100 and silent-default traps become loud.
11. **One error convention for `sql`, `ch` and collections.**
    - Duplicate → 409, bad value → 400, `T` without a document → 404.
    - Database down, busy or timed out → 503 with `Retry-After: 1`.
    - Write outcome unknown → 500, and anything else → 500.
    - `let r: DbResult = <write>` returns the outcome instead, and `r` must be checked.
    - Reads used as statements are compile errors.

    *Reason:* fail-closed like `sql` (В4), with no shared error slot (Н5).
12. **Configuration comes from the environment.**
    - `MONGODB_URI` names the database in its path; `CLICKHOUSE_URL`, `CLICKHOUSE_USER` and `CLICKHOUSE_PASSWORD` name the ClickHouse server.
    - `DATABASE_TIMEOUT` is shared, with per-driver overrides.
    - Results are capped at 64 MiB.
    - More servers are declared as `mongodb NAME = expr` and `clickhouse NAME = expr`.
    - Configuration is parsed once into permanent memory.

    *Reason:* no client values in programs, the same as `DATABASE_URL`, and nothing configurable lives in `store`.
13. **Startup checks everything, as `sql` does.**
    - **MongoDB:** connect and authenticate; create (or, in check mode, verify) the declared indexes; a collection the program never writes must exist; compare an existing validator; run `$sample` + `$type` over 20 documents. A comparison-class mismatch, such as an ObjectId field stored as a string, is an error.
    - **ClickHouse:** check for a readonly user; run migrations; `DESCRIBE` every table and insert type; `DESCRIBE (query)` every `ch` site, with sample-value retries.
    - `khc test` works in temporary databases.

    *Reason:* mistakes that would be silent, or loud only later, stop the deploy.
14. **Runtime.**
    - Collection and `ch` calls are forbidden inside `tx`.
    - There are no MongoDB transactions in v0.13; the conditional single-document update is the documented idiom.
    - There is exactly one audited store-lock window per driver (the low-level layer's), with request bytes built before the release and decoding after the re-lock.
    - There are no cursor values: lists are drained, and `for x in notes.find(...)` streams with a hidden cursor.
    - Typed calls are store-neutral for locking (С10).
    - The library never writes into user-reachable objects.

    *Reason:* the GC design's W1–W3, I1 and §4.3 hold without new sites or barriers, and К1/В5 cannot be written.
15. **Binary data (С11): there is no `bytes` type.**
    - A BSON Binary field is a `str` holding standard base64 when the collection block says `avatar: binary`. Reading Binary into an undeclared `str` is a decode error that names the fix.
    - ClickHouse `String` stays raw bytes, as `bytea` and fetch bodies do.
    - The low-level byte types (`Bson`, `ChResult.body`) are not reachable from the typed surface and are banned from `store` and `to_json`.

    *Reason:* v0.13-utf8.md makes user `str` text. `to_json` and KHRIP_DATA replace invalid bytes after steps E/F (D9), so only ASCII base64 survives them losslessly. Raw sources stay raw, as D9 already rules for `bytea`. §4.9 adds the D9 rows.
16. **There is no time type.**
    - Time stays `int` unix seconds or an ISO `str`.
    - A `date` storage hint makes a field a BSON Date, which also allows `ttl`.
    - ClickHouse `Date`/`DateTime`/`DateTime64` are read and written in seconds.
    - `DateTime64(p>0)` into `int` is a startup error.
    - Every ClickHouse query runs with `session_timezone = UTC`.

    *Reason:* one time model across PostgreSQL, MongoDB and ClickHouse, and the unit traps (Н11) become loud.
17. **Prompt.** The KHRIP.md section is **664 o200k / 691 Claude** tokens. It replaces the current 189 / 210-token paragraph, so the net change is +473 / +480. An optional habits line adds 65 / 72. KHRIP.md goes from 4,143 to 4,616 o200k (4,681 with habits). *Reason:* the section must be enough to write P1–P3 and the judges' programs. It also shows what the judges found missing from the other sections: the DDL path, the multi-key sort and the cardinality rule.
18. **Evidence.**
    - **Tokens:** P1 256 / 265, P2 287 / 287, P3 239 / 249, against the PR API's 742 / 703 / 424 and Go's 1,184 / 990 / 889. Go/Khrip over the three is **3.92** (o200k) / **4.62** (Claude), against 2.31 on the PostgreSQL eval tasks. P1 on PostgreSQL is 318.
    - **Remaining silent mistakes:** listed in §11.5.
    - **Eval tasks (§12):** they measure these claims in four languages before the section is promoted.
19. **Order of work.** ClickHouse first: it is common to all three designs and closes В3 and В6. MongoDB follows, starting from the prototype. The blind eval runs before KHRIP.md changes (§13).

## 2. Surface

### 2.1 Declarations

The new words are contextual, like `every` and `migration` today (src/decl.kh:743–746). They are keywords only where shown. Programs that use `collection`, `table`, `mongodb`, `clickhouse` or `ch` as names keep compiling.

```
collection_decl := "collection" NAME ":" TYPE ["in" CONN] ["at" STRING] [coll_block]
table_decl      := "table" NAME ":" TYPE ["in" CONN] ["at" STRING] [table_block]
conn_decl       := ("mongodb" | "clickhouse") CONN "=" EXPR        // str or str?, evaluated once at start
migration_decl  := "migration" ["ch" | CONN] INT STRING             // no word: PostgreSQL, as today
ch_form         := "ch" [CONN] STRING                               // "..." or `...`, starting on the same line
coll_block      := "{" { coll_item } "}"                            // one item per line
coll_item       := "index" keys | "unique" keys | "ttl" PATH [INT UNIT] | PATH ":" STORAGE | "validate"
keys            := ["-"] PATH { "," ["-"] PATH }
PATH            := IDENT { "." IDENT }                               // field names of TYPE
STORAGE         := "date" | "binary" | "uuid" | "int32" | "decimal"
UNIT            := "ms" | "s" | "min" | "h" | "d"                    // as in every
table_block     := "{" { "async_insert" } "}"
```

**`TYPE`.**
- It is a struct, not a variant type.
- A collection type **must have a non-optional `_id`** of type `ObjectId`, `str` or `int` (E-D7, E-D8).
- Fields may be:
  - `int`, `float`, `bool`, `str`, `ObjectId`;
  - enums and variants with fields, stored as in JSON: an enum as its label, a variant as an object with `"type"`;
  - structs, lists, `map[str, V]`;
  - optionals of these.
- ClickHouse rows are flat (§4.7).

**Default connections.**
- Collections read `MONGODB_URI`; tables, `ch` and `migration ch` read `CLICKHOUSE_URL`.
- `mongodb NAME = expr` and `clickhouse NAME = expr` declare more connections. They are used with `in NAME`, `ch NAME "..."` and `migration NAME N`.

**`at`.**
- `at "coll"` names the server object when it differs from `NAME`.
- For collections, `at "otherdb.coll"` is another database on the same connection.
- Tables take only an unqualified name (§2.8).

**Names.** Collection, table and connection names share the global namespace with functions, types, globals and stores; duplicates are errors, as today. A local of the same name shadows them (Fact 2). Using a collection as a value is E-D1.

### 2.2 The collection block

```khrip
collection users: User {
    unique email                 // unique index on email
    unique org, login            // compound unique index
    index org, -created          // compound index; - is descending
    ttl expires                  // delete a document when expires (unix seconds) has passed
    born: date                   // this int (unix seconds) is a BSON Date
    avatar: binary               // this str is base64 text; stored as BSON Binary
    validate                     // (step 8) install a $jsonSchema validator made from User
}
```

| Item | Effect |
|---|---|
| `index a, -b` | Index `{a: 1, b: -1}`, named as MongoDB names it (`a_1_b_-1`). Paths are field paths of `T` (`address.city`). |
| `unique a[, b]` | The same with `unique: true`. Its fields form a **unique set** that proves one-document filters (§2.3). An optional key field gets `partialFilterExpression: {a: {$type: <BSON type>}}`. Without it, two documents without the field collide (`dup key: { phone: null }`), and an explicit null written by another program also stays out of the index (measured, Appendix A.1). |
| `ttl f [N unit]` | Single-field index `{f: 1}` with `expireAfterSeconds: N` (0 without a duration). `f` must be an `int` or `str` time field, and is stored as a BSON Date automatically. |
| `f: date` | `int` (unix seconds) ↔ BSON Date (ms). On a `str` field: ISO 8601 ↔ Date. |
| `f: binary` | `str` with standard padded base64 ↔ Binary subtype 0 (§4.9). |
| `f: uuid` | `str` in canonical `8-4-4-4-12` form ↔ Binary subtype 4. |
| `f: int32` | `int` ↔ Int32, for collections whose validator wants `int`. Out of range → 400. |
| `f: decimal` | (step 8) `str` decimal text ↔ Decimal128. |
| `validate` | (step 8) `collMod` with a `$jsonSchema` generated from `T` and `validationLevel: "moderate"`. |

A storage hint applies to the field everywhere: stored documents, filter values (`x.born >= since` sends a Date), update operators, sort, projection, indexes. Paths into lists of structs are allowed (`lines.at: date`).

### 2.3 MongoDB operations

Notation:
- `C` is a collection of type `T`.
- `P` is a struct whose fields are fields of `T` with the same types; as a result type it is a **projection**.
- `f` is a filter lambda (§2.4); `chg` is a change (§2.5).
- "Unique" means the filter's top-level conjunction has an equality on `_id`, or on every field of one `unique` set, with a non-optional value or on a required field (§9.4).

| Call | Result by expected type (none expected → the first) | Wire |
|---|---|---|
| `C.find([f] [, Find {...}])` | `[T]`; `[P]` (projection). Any other expected type is E-M7. | `find` + `getMore` until drained, at most `MONGODB_MAX_RESULT` |
| `C.one(f [, Find { sort }])` | `T?`; `P?`; `T`/`P` (none → 404, route must list 404); followed by `else`/`??` → optional. Unique filter or `sort` required (E-M6). | `find`, `limit: 1` |
| `C.count([f])` | `int` | `aggregate [$match, $count]` |
| `C.distinct(x => x.path [, f])` | `[E]`, `E` the field's type (element type for a list). Null and missing are left out. | `distinct` |
| `C.aggregate([f,] [stage, ...])` | `[R]`, `R?`, `R` (none → 404). **A type is required** (E-M29). A scalar `R` reads the only non-`_id` field. `$out`/`$merge` last: only as a statement or into `DbResult`. | `aggregate`, `$match` from `f` first, `cursor: {}` |
| `C.insert(v)` with `v: T` | `T` (`v`, unchanged); `T?`/`else`/`??` → none on a duplicate key; `int` → 1; `DbResult` | `insert`, ordered |
| `C.insert(vs)` with `vs: [T]` | `[T]` (`vs`); `int` (count); `DbResult` (unordered: every document is tried, `r.failed` lists the indexes). The default form is ordered: a duplicate ends the request with 409 after the earlier documents were written. | `insert` (split by the low-level layer below the message size) |
| `C.update(f, chg [, Find { sort }])` | `int` (matched: 0 or 1); `T`/`P` (the document after the change; none → 404); `T?`/`P?`; `DbResult`. Unique filter or `sort` required. | `update` with `multi: false`; with a document result or a sort: `findAndModify`, `new: true` |
| `C.update_all(f, chg)` | `int` (matched); `DbResult` | `update`, `multi: true` |
| `C.upsert(f, chg)` | nothing; `T`/`P` (the document after; never none); `DbResult` (`r.upserted`). Unique filter required; completeness checked (E-M23, E-M24). | `update` with `upsert: true`; with a document result: `findAndModify` with `upsert`, `new` |
| `C.delete(f [, Find { sort }])` | `int` (0 or 1); `T`/`T?`/`P`/`P?` (the removed document); `DbResult`. Unique filter or `sort` required. | `delete` with `limit: 1`; `findAndModify` with `remove` |
| `C.delete_all(f)` | `int` (deleted); `DbResult` | `delete` with `limit: 0` |
| `for x in C.find(...)` | streams batches; `x: T` (§2.7) | `find` + `getMore` on demand, `killCursors` on early exit |

**Rules.**
- A read used as a statement is E-M12: its only effect would be load.
- `update`, `update_all`, `delete`, `delete_all` and `upsert` need a filter (E-M30). To touch every document, write `x => true`.
- `insert` takes `T` or `[T]` only (E-M13). `_id` is never generated implicitly: write `_id: object_id()`.
- A change never sets `_id` (E-M22). A struct change skips its `_id` field.

### 2.4 Filters

A filter is a lambda `x => condition` with the type rules and meaning of `list.filter`. `x` has type `T`, or the element type inside `any`.

**Outer values.** Sub-expressions that do not mention `x` (locals, parameters, calls, arithmetic, `header(...)`) are outer values:
- they are evaluated in Khrip, left to right, with `&&`/`||` short-circuit, before the query;
- each one is sent as a BSON value, encoded with the storage of the field it is compared with;
- an outer `bool` sub-expression folds at run time. For example, `tag == none || x.tags.contains(tag)` becomes `{}` when `tag` is none and `{tags: tag}` otherwise; the right operand is then not evaluated, exactly as in memory.

| Khrip | MongoDB | Notes |
|---|---|---|
| `x.p == v` | `{p: v}` | `v: U?` that is none: **false** if `p` is required (so `x.owner == header("X")` matches nothing when the header is missing); `{p: null}` if `p` is optional |
| `x.p != v` | `{p: {$ne: v}}` | `v` none: true if `p` is required; `{p: {$ne: null}}` if optional |
| `x.p < v`, `<=`, `>`, `>=`, and `v < x.p` … | `{p: {$lt: v}}` … | `int`, `float`, `str`, `ObjectId`; an int literal against a float field is sent as a Double; Khrip already refuses optionals here |
| `x.p == none`, `x.p != none` | `{p: null}`, `{p: {$ne: null}}` | `p` optional; absent and null both read as none |
| `x.p` (bool), `!x.p` | `{p: true}`, `{$nor: [{p: true}]}` | |
| `x.p == Admin` (enum) | `{p: "Admin"}` | labels, as in JSON |
| `x.a < x.b` (two fields) | `{$expr: {$lt: ["$a", "$b"]}}` | both non-optional and of the same type (E-M4) |
| `x.tags.contains(v)` (list) | `{tags: v}` | |
| `x.title.contains(v)`, `.starts_with(v)`, `.ends_with(v)` | `{title: {$regex: esc(v)}}`, `"^"+esc(v)`, `esc(v)+"\z"` | the value matches literally; `starts_with` uses an index |
| `x.title.lower() == v`, `x.title.lower().contains(v)` (… `starts_with`, `ends_with`) | `$regex` anchored or not, `$options: "i"` | if `v != v.lower()` the condition is false, as in Khrip |
| `x.title.matches("re")` | `{title: {$regex: "^(?:re)\z"}}` | literal or `const` pattern only, checked by the v0.13 regex checker (E-M5) |
| `xs.contains(x.p)` | `{p: {$in: xs}}` | `xs` an outer list |
| `x.tags.len() == n`, `x.tags.len() > 0` (or `!= 0`) | `{tags: {$size: n}}`, `{"tags.0": {$exists: true}}` | other `len()` comparisons: E-M3 |
| `x.lines.any(l => cond)` | `{lines: {$elemMatch: <cond>}}` | `cond` is a filter over the element type; `any(l => true)` is "non-empty" |
| `x.attrs["k"] == v` (map field, literal key) | `{"attrs.k": v}` | the key has no `.` and no leading `$` |
| `a && b`, `a \|\| b`, `!a` | conjunction, `$or`, `$nor` | folded at run time: `false && _` sends no query (a filter that folds to false gives `[]`/none/0 without a round trip) |

- Paths are Khrip field names, the same names stored: `x._id` is `_id`, `x.address.city` is `"address.city"`.
- Anything else that mentions `x` is E-M3. The hint names the supported forms and points to `aggregate` with a `{"$match": ...}` stage for other MongoDB operators.

**Remaining differences from in-memory Khrip,** all documented in DATABASES.md:
1. `$regex` with `i` folds case with PCRE rules, not Khrip's simple mapping; they agree on ASCII, Latin, Cyrillic and Greek.
2. Documents that do not conform to `T` (written by other programs) can match `$ne`/`$nor` where the field is missing. The startup sample reports such data (§7.2).

### 2.5 Changes and document literals

A **change** (the second argument of `update`, `update_all`, `upsert`) is a struct value or a document literal.

**Struct change `S`.** Its fields are fields of `T`, with the same type or its optional (E-M14).
- It becomes `$set` of every field of `S` except `_id`.
- An optional field of `S` with a value is set.
- An optional field that is none is left alone, unless the request body sent an explicit JSON `null` for it. In that case it becomes `$unset` if `T`'s field is optional, and a 400 `missing value: notes.title` if it is required.

This is `SET {patch}`, with the same marks (`CTX_JNULLS`, `__json_null_sent`). `{"$set": s}` with a struct `s` is the same thing. An empty change sends `{$set: {}}`: MongoDB accepts it (Appendix A.2), and a document without operators would replace the whole document.

**Document literal.** `{` STRING `:` value, ... `}`:
- values are nested literals, list literals, or any Khrip expression;
- keys are string literals or `const`s (E-M26);
- a `map[str, V]` value becomes a document whose keys are checked at run time: a key that starts with `$` or contains `.` is a 400.

| Operator | Key | Value |
|---|---|---|
| `$set`, `$setOnInsert` | a path of `T` (`items.$.qty` and `items.$[].qty` when the filter matches `items` through `any`) | the field's type. A `U?` value that is none writes nothing. A struct value nests (§4.4). |
| `$unset` | an optional field, or one with a default (E-M21) | any literal |
| `$inc`, `$mul` | a non-optional `int`/`float` field (E-M20) | the same number type; an int literal is fine for float |
| `$min`, `$max` | `int`, `float`, `str`, `ObjectId` field | the field's type |
| `$push`, `$addToSet` | a list field `[E]` | `E`, or `{"$each": [E], "$slice": int, "$position": int, "$sort": 1 \| -1 \| {...}}` |
| `$pull` | `[E]` | `E`, or a literal over `E`'s fields |
| `$pullAll` | `[E]` | `[E]` |
| `$pop` | a list field | `1` or `-1` |
| `$currentDate` | a `date` field | `true` |
| `$rename`, `$bit`, a top-level key without `$` | — | E-M15/E-M16 |

- A literal `none` anywhere in a document is E-M19. `none` writes nothing; removing a field is `$unset`.
- An unknown `$` operator gets a did-you-mean.
- A plain (non-literal) value of a `U?` type is allowed only as a `$set`/`$setOnInsert` value.

**Pipelines.** `aggregate(f, [stages])` sends `{$match: <f>}` first.
- Stage names are checked against MongoDB 8.0's list: `$match $group $sort $limit $skip $project $unwind $lookup $count $addFields $set $unset $replaceRoot $replaceWith $facet $bucket $bucketAuto $sortByCount $sample $unionWith $densify $fill $setWindowFields $graphLookup $redact $out $merge`.
- `$where`, `$function` and `$accumulator` anywhere are E-M25.

**Shape tracking** (prototyped):
- The shape starts as `T`'s fields.
- `$match`, `$sort`, `$limit`, `$skip`, `$unwind` and `$sample` keep it; `$addFields`/`$set` add their keys.
- `$group`, `$project` and `$count` with literal keys replace it.
- `$lookup` (whose `from` must be a declared collection, E-M36), `$facet`, `$replaceRoot` and non-literal stages make it unknown, and checking stops.
- While the shape is known, every `"$field"` value and every `$match`/`$sort` key must be a path of it (E-M27).
- At the end, every field of the result type without a default or `?` must be produced (E-M28). This is the same rule as `sql`'s "a column for every field".

**Values in stages.**
- In stages other than `$match`, every string that is not a literal in the source is sent as `{"$literal": s}`. This is recursive, so strings inside structs, lists and maps are wrapped too: a value `"$secret"` from a client cannot read a field. Library-first measured the leak and the fix.
- A `U?` value in a stage is E-M39.
- `$regex` in a `$match` stage literal takes a pattern literal only.

### 2.6 Find options

```khrip
type Find { sort: str = "", skip: int = 0, limit: int? }      // library type, linked with the drivers
```

- `Find { ... }` is written in the call (E-M11). Field shorthand works: `Find { sort: "-created", limit }`.
- `sort` is a string literal, a `const`, or a local made of string literals through `if`/`match`. This is the `ORDER BY {o}` rule (src/sql.kh:1664), with at most 16 variants.
  - Each variant is a comma-separated list of field paths, `-` for descending (`"-created, title"`).
  - Each path is checked against `T` (E-M8) and compiled into a constant BSON document.
  - A sort chosen by the client is `let s = match q { "new" => "-created", _ => "title" }`.
- `skip` is any `int`; negative → 400 `skip must not be negative`.
- `limit` is `int?`:
  - none means no limit;
  - `0` gives `[]` (none for `one`) without a round trip;
  - negative → 400 `limit must not be negative`.
- `skip` or `limit` without `sort` is E-M10, the `sql` rule for `LIMIT` without `ORDER BY`.
- In `one`, `update` and `delete`, only `sort` is allowed: it takes the first match by that order ("claim the next job").

### 2.7 Streaming

`for x in C.find(f, Find {...}) { ... }` (step 7) iterates without building the list:
- the cursor is a hidden local, so no cursor value exists;
- batches are decoded one at a time and reuse one raw buffer;
- `break`, `return`, `fail` and panics leave the loop, and the request-end hook sends `killCursors`;
- the decoded documents still live in the request arena.

It "streams the network, not memory". For unbounded scans DATABASES.md recommends keyset pages: `Find { sort: "_id", limit: 500 }` with `x._id > last`.

`for` has no element annotation in Khrip today. `for x in C.find(...)` therefore types `x` as `T`; a projection, or streaming `aggregate` (whose result type has to be written), would need a typed `for x: P in`, a language-wide change (§16).

### 2.8 ClickHouse

```khrip
migration ch 1 `
CREATE TABLE events (ts DateTime DEFAULT now(), user_id UInt64, page LowCardinality(String), ms Float32)
ENGINE = MergeTree ORDER BY (page, ts)
`
table events: Event { async_insert }     // block optional

events.insert(rows)                      // rows: [S] or S; S is Event or a struct of some of its fields
let top: [PageStat] = ch `SELECT page, count() AS views FROM events
    WHERE ts >= {from} AND page IN {pages} GROUP BY page ORDER BY views DESC LIMIT {n}`
let n: int = ch "SELECT count() FROM events WHERE user_id = {uid}"
ch "ALTER TABLE events DELETE WHERE ts < {cutoff}"
let r: DbResult = events.insert(rows, Insert { dedup: key })
```

| Form | Result by expected type |
|---|---|
| `t.insert(rows [, Insert { dedup }])` | nothing; `int` (rows sent and acknowledged); `DbResult`. An empty list sends nothing and gives 0. |
| `ch "SELECT ..."` / `WITH` / `SHOW` / `DESCRIBE` / `EXISTS` / `EXPLAIN` | as `sql`: `[R]` all rows; `R?` one row or none (more → 500); `R` one row, none → 404; one column's type for a scalar. No expected type is E-CH13. |
| `ch "INSERT INTO t SELECT ..."` | nothing; `int` (`written_rows` from `X-ClickHouse-Summary`); `DbResult` |
| `ch "ALTER TABLE ... UPDATE/DELETE ..."`, `DELETE FROM`, `TRUNCATE`, `OPTIMIZE`, `SYSTEM ...` | nothing; `int`; `DbResult`. `ALTER ... UPDATE/DELETE` runs with `mutations_sync = 1`, so a following read sees the change. |
| `ch "KILL QUERY WHERE ... ASYNC"` | rows into `[R]`, or `int` (queries found) |

**Rules shared with `sql`**, with the same messages:
- `{x}` is always a parameter;
- a table-name parameter is an error;
- `ORDER BY {o}` takes literal variants;
- an optional comparison needs `({x} IS NULL OR col = {x})`;
- `LIMIT` without `ORDER BY` is an error;
- `DELETE` without `WHERE` is an error;
- one statement per `ch`;
- no `ch` in a global initialiser.

**Not allowed in `ch`:**
- DDL (`CREATE`, `DROP`, `RENAME`, `ATTACH`, `DETACH`, `ALTER ... ADD/DROP/MODIFY/RENAME COLUMN`, …), which goes in `migration ch N` (E-CH3);
- `INSERT ... VALUES` and `INSERT INTO t {rows}`, which are `t.insert(rows)` (E-CH2);
- `FORMAT` (E-CH4), because the runtime reads RowBinaryWithNamesAndTypes;
- `SET` (E-CH17);
- `{x}` inside `SETTINGS` (E-CH10): ClickHouse refuses parameters there (measured);
- `wait_for_async_insert = 0` (E-CH9);
- database-qualified names other than `system.` and `INFORMATION_SCHEMA.` (E-CH5): one connection is one database, which `khc test` replaces. Another database is another connection, `clickhouse analytics = env("ANALYTICS_CLICKHOUSE_URL")`.

**`table events: Event`** binds a row type to a table, checked at start (§7.3).
- `S`, the type passed to `insert`, must have fields ⊆ `Event`'s (E-CH8).
- `async_insert` in the block sends `async_insert = 1, wait_for_async_insert = 1`: the call returns after the server flushed the batch. Fire-and-forget does not exist.
- `Insert { dedup: key }` sends `insert_deduplication_token = key`. A retry with the same key after `write outcome unknown` is then stored once. It works only on Replicated tables or with `non_replicated_deduplication_window > 0`, which startup checks (S21; measured: without the setting, a repeated insert with the same token is stored twice).

**`migration ch N`** (and `migration NAME N` for a named connection):
- it runs once, in order, at start or with `./app migrate`;
- it is recorded in `khrip_migrations` (MergeTree) in that database, with the text's sha256; an edited migration that already ran stops the server;
- the statements are split by the `ch` lexer (quotes, comments and heredocs are respected) and sent one per request;
- a failure names the statement: `khrip: ClickHouse migration ch 2 failed at statement 2 of 3: ...`. ClickHouse DDL is not transactional, so DATABASES.md recommends one statement per migration, or `IF NOT EXISTS`.

**Query ids and cancellation.**
- Every `ch` call gets `query_id = khrip-<16 hex>` and `log_comment = 'file.kh:line:col'`, so `system.query_log` shows where a query comes from. A readonly=1 user gets no settings at all (С4), so it gets no `log_comment`.
- On the client deadline, a SELECT gets a best-effort `KILL QUERY WHERE query_id = '…' ASYNC` on another pooled connection, never awaited. An INSERT is never cancelled: cancelling is not a rollback, so a lost reply is `write outcome unknown`.
- User-level cancellation is a statement: `ch "KILL QUERY WHERE Settings['log_comment'] = 'report.kh:40:12' ASYNC"` cancels the running queries of that site (measured, Appendix A.7). Per-call user query ids are out of scope (§16).

### 2.9 Library types and functions the AI sees

```khrip
type ObjectId                      // built-in: a str of 24 lower-case hex digits (§4.3)
fn object_id() -> ObjectId         // 4 bytes time, 5 random per process, 3 counter (lib/bson.kh)
fn parse_object_id(s: str) -> ObjectId?
type Find { sort: str = "", skip: int = 0, limit: int? }
type Insert { dedup: str = "" }
type DbResult {
    ok: bool               // the whole operation succeeded
    status: int            // the status the default form would have answered (200 when ok)
    code: int              // MongoDB code or ClickHouse exception code; 0 for client-side and transport failures
    error: str             // the response body the default form would have sent; "" when ok
    unknown_outcome: bool  // the write may have been applied (reply lost): do not retry blindly
    count: int             // inserted / matched / deleted documents; rows written
    modified: int          // MongoDB update: documents actually changed
    upserted: bool         // upsert inserted a document
    failed: [int]          // insert of a list into DbResult: indexes of the documents that failed
}
```

- The names exist only in programs that declare a collection or table or use `ch`. A user declaration with the same name is an error at the user's declaration, not in lib (E-D9; fixes the С8 symptom).
- `ObjectId`, `object_id` and `parse_object_id` exist in every program, because `ObjectId` is also a PostgreSQL and route type.

### 2.10 What stays below

The low-level API (`Mongo`, `mongo_command`, `bson_*`, `ChConfig`, `ch_query_params`, `ch_insert`, `ch_cancel`, …) stays in the library for system code and rare commands (`collMod`, `listCollections`, `dropIndex`, `SYSTEM ...`).
- DATABASES.md documents it under "Low-level API"; KHRIP.md does not mention it.
- The typed layer calls only `__`-prefixed entry points.
- The low-level byte types stay banned from `store` and `to_json`. The typed surface cannot produce them, so AI-written programs never reach them by accident.

## 3. Parameters and injection

### 3.1 MongoDB: nothing from data can become an operator, a key or a field path

| Channel | Why injection cannot be expressed |
|---|---|
| Filters | The compiler builds the query structure from the lambda. Data enters only as outer values, encoded by type: a `str` is always a BSON string and is never parsed. Field names come only from Khrip field names. `contains`/`starts_with`/`ends_with` escape every regex metacharacter of the value (`\ ^ $ . \| ? * + ( ) [ ] { }`; prototyped: `"50%"`, `"("` and `"."` match literally). `matches` takes compile-time patterns only. |
| Changes and stages | Keys are string literals or `const`s (E-M26). A `map[str, V]` value with a key starting with `$` or containing `.` is a 400 at encode time, which blocks `{"$where": ...}` and `{"$ne": ...}` arriving in a JSON body. Strings from data in expression stages are wrapped in `$literal`, recursively. `$where`, `$function` and `$accumulator` do not compile (E-M25). |
| Struct values (insert, change) | Encoded from the type descriptor: the keys are field names, and map keys are checked as above. |
| Sort, projection, indexes | Compile-time constants made from field names. A client-chosen sort goes through literal variants. |
| Collection, database and connection names | Declarations only; never values. |

### 3.2 ClickHouse: the query is a `sql` literal in a ClickHouse dialect

**Lexing.** `ch`, optionally followed by an identifier, then `"` or `` ` `` on the same line, starts a ClickHouse query. `lex_ch` is `lex_sql` (src/lex.kh:669) with a dialect flag stored in the `SqlLit`, producing a `T_SQL` token marked ClickHouse. Its states, all measured on 25.8 (Appendix A.4):
- `'...'` with `\'`, `\\` and `''` escapes;
- `"ident"`; backtick identifiers are possible only inside `ch "..."`;
- comments `--`, `#` and `/* */`;
- heredocs `$tag$...$tag$` and `$$...$$`;
- `{}`, `{3}`, `{1,2}` and `\{` stay text;
- `{` IDENT `:` IDENT … `}` is E-CH1 (the ClickHouse placeholder habit). Today it is a lexer hint for ordinary strings (d01f6a5).

`let ch = s[i]` and every other use of `ch` as a name is unaffected, because no string follows it.

**Rewriting.** This is `parse_sql` (src/sql.kh:1554) with a dialect parameter:

| Source | Sent | Note |
|---|---|---|
| `{x}` | `{pN:Type}` with `param_pN` in the URL | Type from §3.3; values escaped by the low-level `__ch_param`; NULL is `\N` (Н9) |
| `({x} IS NULL OR col = {x})` | the same `Nullable(T)` parameter twice | measured with `\N` and a value (schema-first A.6); no Bool rewrite is needed |
| `col = {x}` with `x: T?` and no `IS NULL` guard | E-CH14 (the `sql` message) | |
| `IN ({xs})` or `IN {xs}` | `IN {pN:Array(T)}` | both measured; an empty list matches nothing |
| `'%{q}%'` after `LIKE`/`ILIKE` | `concat('%', {pN:String}, '%')`, with the value's `\`, `%`, `_` escaped | unescaped, `_` matches any character (measured by schema-first) |
| `'...{x}...'` elsewhere | `concat('...', {pN:String}, '...')` | |
| `ORDER BY {o}` | one query variant per literal value | the `sql` rule |
| `{x}` after `FROM`, `JOIN`, `INTO`, `TABLE` | E-CH14 | the `sql` rule |
| `{x}` inside `SETTINGS` | E-CH10 | ClickHouse: `Syntax error ... Expected substitution type` (measured) |
| `?`, `$1` | E-CH12 | |
| `FORMAT ...` | E-CH4 | the runtime appends `FORMAT RowBinaryWithNamesAndTypes` to row statements |
| `;` followed by more | E-CH7 | |

Not carried over from `sql`:
- PostgreSQL catalog markers (`%%T`);
- `= ANY` and `SET {patch}`;
- the "write after another statement outside tx" rule, because ClickHouse has no transactions;
- `sq_check` schema checking from migrations. ClickHouse is checked against the server at start (§7.3).

### 3.3 ClickHouse parameter types from Khrip types

| Khrip type of `{expr}` | Parameter type | Value text |
|---|---|---|
| `int` | `Int64` | decimal |
| `float` | `Float64` | shortest round-trip; `nan`, `inf`, `-inf` |
| `bool` | `Bool` | `true` / `false` |
| `str`, `ObjectId` | `String` | escaped bytes |
| enum | `String` | the label |
| `[T]` | `Array(T')` | `[v1,v2]`, strings quoted |
| `map[str, V]` | `Map(String, V')` | `{'k':v}` |
| `T?` | `Nullable(T')` | `\N` for none; only behind the `IS NULL` guard |
| `[T]?` | E-CH11 | arrays are never NULL in ClickHouse; use `[]` |
| struct, list of structs | E-CH6 | rows go through `t.insert` |

Comparisons measured on 25.8 by the three designs:
- **These work:** `Int64` against `DateTime`, `DateTime64`, `UInt32`, `UInt64`, `Int32` and `Decimal`, and as `LIMIT`/`INTERVAL`; `String` against `LowCardinality(String)`, `Enum8`, `Date` and `UUID`; `Float64` against `Float32`.
- **`Date >= Int64`** is `ILLEGAL_TYPE_OF_ARGUMENT`. The startup `DESCRIBE` catches it, with the hint `compare a Date column with toDate({x})`.
- **An ISO string against `DateTime`** fails at run time (Code 53/41). The startup check prints the hint `parameter {from} is str and meets a DateTime: send int seconds, or parseDateTimeBestEffort({from})`.

## 4. Types and mapping

### 4.1 Principles

1. **The declared type is the schema.** Encoding follows the declared type and the block's storage hints. Decoding accepts exactly what the declared type could have written, plus lossless numeric widening.
2. **Nothing converts implicitly across comparison classes.** In MongoDB a string, an ObjectId and a Date never compare equal (measured: the string `"65a1…"` does not find an ObjectId `_id`). A stored type that differs from the declaration is a loud decode error, and at start a loud sample error. It is never a silent conversion or a silent empty result.
3. **One new Khrip type: `ObjectId`.** Every other storage choice lives in the declaration (`born: date` in the block, `born: int` in the struct).

### 4.2 MongoDB: Khrip → BSON (write) and BSON → Khrip (read)

| Khrip field | Writes | Reads | Otherwise: decode error (500, logged with collection, `_id`, path, found type and fix) |
|---|---|---|---|
| `int` | Int64 | Int64, Int32, Double with an integral value in range (low-level widening) | fractional Double, NaN, ±Inf, out of range, other types (Date: `add "f: date"`) |
| `int` + `int32` | Int32 (out of range → 400) | as `int` | |
| `int` + `date` | Date = seconds × 1000. A value above 10^11 (after year 5138) is 400 `looks like milliseconds`. | Date → seconds, floor | non-Date |
| `float` | Double | Double, Int32, Int64 exactly representable | Int64 that a Double cannot hold; Decimal128 (step 8 `decimal`) |
| `bool` | Boolean | Boolean | |
| `str` | String. Invalid UTF-8 → 400 `field body: invalid UTF-8` (D9). | String; UTF-8 checked here, with the path (low-level С3) | ObjectId (`declare it ObjectId`), Date (`add "f: date"`), Binary (`add "f: binary"`) |
| `str` + `date` | Date from ISO 8601 (`parse_time`; no zone = UTC; else 400) | Date → `time_iso` text, with `.123` when the ms are not zero | |
| `str` + `binary` | Binary subtype 0 from base64 (bad base64 → 400) | Binary subtype 0 or 2 → standard base64 | |
| `str` + `uuid` | Binary subtype 4 from `8-4-4-4-12` (else 400) | Binary subtype 4 or 3 → canonical text | |
| `ObjectId` | ObjectId (12 bytes) | ObjectId → 24 lower-case hex | String (`declare _id: str, or convert the data`) |
| enum | String (label) | String naming a variant | unknown label |
| variant with fields | Document with `"type"` and the variant's fields (as JSON) | same | |
| struct | embedded Document; none fields left out | Document. A missing field takes its default, or none for `T?`; otherwise an error. Fields not in `T` are ignored. | missing required field (`add a default or make it T?`) |
| `map[str, V]` | Document (key starting with `$` or containing `.` → 400) | Document | |
| `[T]` | Array; none elements → null (lists keep positions) | Array | |
| `T?` | value, or **nothing** when none | absent or null → none | |

Decimal128, JavaScript, MinKey/MaxKey, DBPointer and Timestamp are decode errors that name the BSON type found. A Decimal128 field gets a `decimal` hint in step 8.

### 4.3 `ObjectId` and `_id`

**Representation.** At run time an `ObjectId` is a `str` of 24 lower-case hex digits. The type descriptor carries a brand word (prototype: `[D_STR, 1]`).
- **GC:** the copier and ptrbits see a string.
- **JSON, store, KHRIP_DATA, interpolation:** they see a string.
- **The type checker:**
  - an `ObjectId` is accepted where a `str` is expected (interpolation, `+`, `len`, `str` parameters);
  - a `str` is never accepted where an `ObjectId` is expected;
  - `==`/`!=` between an `ObjectId` and a `str` is an error (`compare ObjectId with ObjectId: parse_object_id(s)`), in filters (E-M35) and in plain code.

**Boundaries.**
- **JSON input and route path/query parameters** accept 24 hex digits in either case and lower-case them. Anything else → 400, with these prototype messages:
  - `parameter 'id' must be an ObjectId (24 hex digits), found 'xyz'`;
  - `invalid JSON body: _id: expected an ObjectId (24 hex digits)`.
- **BSON:** type 0x07 ↔ hex.
- **PostgreSQL and ClickHouse:** a `text`/`String` parameter. Reading a text column into `ObjectId` validates it (500 on bad data).

**Functions.**
- `object_id()` follows the BSON spec: 4-byte big-endian seconds, 5 random bytes per process, and a 3-byte counter with a random start, incremented atomically (already in lib/bson.kh:1013). Ids sort by creation time, so `Find { sort: "_id" }` is insertion order.
- `parse_object_id(s)` returns `ObjectId?`.

**Operations.** `==`, `!=` and `<` (time order); interpolation; `map[ObjectId, V]` keys; `sort_by` keys.

**`_id`** is an ordinary field name, the same in Khrip, JSON and MongoDB, with no renaming.
- A collection type must declare it, non-optional (E-D7/E-D8).
- A type with `id` and no `_id` gets the hint `rename id to _id`.
- `_id: str` and `_id: int` are allowed (natural keys). `_id` is never generated implicitly.

### 4.4 none, null and the PATCH idiom

| Where | `T?` value that is none | Explicit JSON `null` in the request body |
|---|---|---|
| `insert` document | field not stored | not stored |
| struct change, or a struct value under `$set` | field left as it is | `$unset` if `T`'s field is optional; 400 `missing value: notes.title` if it is required |
| scalar `U?` value under `$set`/`$setOnInsert` | writes nothing | — (scalars carry no marks; the same as `sql`) |
| literal `none` in a document | E-M19 | — |
| filter `x.p == v` | Khrip's `==` (§2.4) | — |
| `ch`/`sql` parameter | NULL, behind the `IS NULL` guard | — |
| ClickHouse insert | NULL for `Nullable`; the column's DEFAULT for a non-Nullable column with a DEFAULT; otherwise a startup error (S13) | — |
| read | absent or null → none | — |

So `notes.update(x => x._id == id, patch)` with `type NotePatch { title: str?, body: str?, tags: [str]? }` changes only what the client sent, as `sql "UPDATE notes SET {patch} WHERE id = {id}"` does. The prototype's PATCH of `{"note": "hello"}` changed only `note` (§11.1). `{...old, ...patch}` followed by a struct change also works.

### 4.5 Dates and time

Khrip keeps time as `int` unix seconds (`now()`, `parse_time`, `parse_date`) or ISO text (`time_iso`). There is no time type (§16).

**MongoDB.**
- An `int` field is Int64 by default, so range filters work in Khrip.
- `f: date` (or `ttl f`) makes it a BSON Date in writes, filter values and sorts.
- Reading a Date into a field without `date` is a decode error. At start it is a sample error, because an Int64 filter would silently miss Dates.

**ClickHouse, column plans in seconds semantics.** The low-level plan works in raw units; the typed layer asks for seconds (§9.8).

| Column | `int` | `str` |
|---|---|---|
| `Date`, `Date32` | seconds at 00:00 UTC; writes floor to the day | `YYYY-MM-DD` |
| `DateTime` | seconds; 0…2^32−1, else 400 | `time_iso` (UTC) |
| `DateTime64(p)` | **writes:** seconds × 10^p. **Reads:** a startup error for p > 0, with the hint `select toUnixTimestamp(ts) AS ts (seconds) or toUnixTimestamp64Milli(ts) AS ts_ms`. Silent truncation and raw-unit confusion (Н11) are impossible. | ISO with p fraction digits |

**Time zone.** Every `ch` query runs with `session_timezone = 'UTC'`, so `toDate(ts)` and `toStartOfDay` give UTC days, as Khrip does. Measured: the same DateTime is 2026-10-23 in UTC and 2026-10-24 in Asia/Tokyo. A readonly=1 user cannot change settings; startup then compares `serverTimezone()` with UTC and prints a note when they differ.

### 4.6 Decimals

**ClickHouse `Decimal(P, S)`.**

| Direction | Khrip type | Rule |
|---|---|---|
| Read | `str` | exact text `"12.34"` |
| Read | `float` | rounded |
| Read | `int` | S = 0 only |
| Write | `str` | exact; too many digits → 400 |
| Write | `float` | rounded half-even to S |
| Write | `int` | S = 0 only |

**`int` into `Decimal(P, S>0)` is a startup error** (S14). KHRIP.md tells the AI to keep money in `int` cents, and scaling would store 100× the amount. The hint says to keep cents in an Int64 column, or to send a `str`/`float`.

**MongoDB Decimal128.** In step 8, `f: decimal` maps it to exact decimal text in a `str`, or to a rounded `float`. Until then it is a decode error that names the field, and a startup sample warning.

### 4.7 ClickHouse writes (`t.insert`, plan from `DESCRIBE TABLE` at start)

Columns are matched by name. `S`'s fields are sent in its order with names, so column order never matters. The plan is the low-level column plan, built once and kept in permanent memory.

| Khrip field | Columns it may fill (conversion) | Run-time check (failure: 400 `bad value: events.user_id: -1 is out of range for UInt64`) |
|---|---|---|
| `int` | `Int8`…`Int64`, `UInt8`…`UInt64`; `Date`/`Date32`/`DateTime`/`DateTime64` (seconds, §4.5); `Decimal(P, 0)`; `Bool` (0/1) | range of the column type |
| `float` | `Float32`, `Float64`, `Decimal(P, S)` (half-even) | finite, precision |
| `bool` | `Bool`, `UInt8` | — |
| `str` | `String`, `LowCardinality(String)`, `FixedString(N)` (≤ N bytes, zero-padded), `Enum8/16` (a known label), `UUID`, `IPv4`/`IPv6`, `Date`/`DateTime`/`DateTime64` (ISO 8601), `Decimal` (exact text) | length, label, syntax |
| `ObjectId` | `String`, `FixedString(24)` | — |
| enum | `Enum8/16` (every Khrip variant must be a label: startup), `String`, `LowCardinality(String)` | — |
| `[T]` | `Array(T')` | elementwise |
| `map[str, V]` | `Map(String, V')` | — |
| `T?` | `Nullable(T')`, `LowCardinality(Nullable(T'))` (none → NULL); a non-Nullable column **with a DEFAULT** (none → DEFAULT) | otherwise startup error S13 |
| struct, variant with fields | — | startup error (Tuple, Nested and JSON are out of scope) |

Startup refuses:
- a column that `S` lacks and that has no `DEFAULT`, `MATERIALIZED`, `ALIAS` or `EPHEMERAL` expression and is not Nullable (S12): it would silently get `0`, `''` or 1970-01-01;
- a field that is a `MATERIALIZED`/`ALIAS` column;
- `int` → `Decimal(P,S>0)` (S14);
- a Khrip enum variant missing from an `Enum8/16` (S24).

Measured by language-forms: `-1` into `UInt32` through `VALUES` stores 4,294,967,295 silently. The plan's range check makes it a 400.

### 4.8 ClickHouse reads (`ch` results; checked at start against `DESCRIBE (query)`, at run time against the RowBinaryWithNamesAndTypes header)

| ClickHouse | Khrip |
|---|---|
| `Int8`…`Int64`, `UInt8`…`UInt32` | `int`, `float` |
| `UInt64` | `int` (a value ≥ 2^63 at run time → 500 naming the column; select `toString(x)` into `str`); `count()` and `uniq()` are UInt64 |
| `Int128/256`, `UInt128/256` | `str` |
| `Float32/64` | `float` |
| `Decimal(P, S)` | `str` (exact), `float`, `int` if S = 0 |
| `Bool` | `bool` |
| `String`, `FixedString`, `LowCardinality(String)` | `str` (raw bytes, §4.9), `ObjectId` (validated) |
| `UUID`, `IPv4`, `IPv6` | `str` |
| `Enum8/16` | `str`, or a Khrip enum whose variants cover every label (startup) |
| `Date`, `Date32` | `int` (seconds at 00:00 UTC), `str` (`YYYY-MM-DD`) |

Columns are matched to fields by name, exactly first, then ignoring case, as in `__db_check` (lib/db.kh:867). Extra columns are ignored. A field without a column must be `T?` or have a default.

### 4.9 Binary data and UTF-8 (С11, v0.13-utf8.md D9)

**There is no `bytes` type, and no raw binary reaches a user `str` from MongoDB.**
- A BSON Binary field is declared `f: binary` and is then standard base64 text in Khrip: ASCII, which survives `store`, JSON, KHRIP_DATA, routes and the strict boundaries of UTF-8 steps E/F exactly.
- Reading a Binary into an undeclared `str` is a decode error with the fix, and a startup sample error.
- JSON APIs carry binary as base64 anyway.

**ClickHouse `String` columns are byte strings.** `ch` results and inserts pass `str` bytes through unchanged, like fetch bodies and PostgreSQL `bytea` (D9 "raw"). A program that keeps binary in ClickHouse selects `base64Encode(col)`. A raw invalid sequence sent to JSON becomes U+FFFD per D9, which is documented and listed in §11.5.

**The low-level byte types stay low-level.** `Bson`, `BsonBinary`, `BsonDecimal128` and `ChResult.body` are not part of the typed surface. They stay banned from `store` and `to_json` (К1 fix, D9), and DATABASES.md marks them as byte strings for system code (`byte_len`, `byte_slice`).

**Why not a `bytes` type:** it would be a new type kind with conversions, JSON rules and prompt tokens, for data that typical APIs pass through as base64. A storage hint gives the wire type without touching the type system, as `date` does.

Recommendation, not required by this design: before UTF-8 step E, PostgreSQL `bytea` could move to base64 `str` too, so that one binary rule covers all three databases.

**Rows to add to the D9 table (v0.13-utf8.md §2):**

| Source or sink | v0.13 rule |
|---|---|
| Typed MongoDB read, BSON String → `str` | Strict. Invalid UTF-8 → decode error: 500, logged with collection, `_id` and field path. The rest of the batch is unaffected (structure is checked once; low-level С3). |
| Typed MongoDB write, `str` → BSON String | Strict. Invalid → 400 `field <path>: invalid UTF-8` (as PostgreSQL 22021). |
| `binary`/`uuid` fields ↔ `str` | ASCII text (base64 / canonical UUID): lossless everywhere. |
| `ch` results, `ch` parameters, `t.insert` values (String, FixedString) | Raw bytes, like fetch bodies and `bytea`; `to_json` sanitises with U+FFFD. |
| `Bson`, `BsonBinary`, `ChResult.body` (low-level) | Byte strings; banned from `store` and `to_json`. |

## 5. Errors

### 5.1 One convention for `sql`, `ch` and collections

Every operation has three outcomes:
1. **Success:** the value of the expected type.
2. **Failure, default form.** The request ends with a status through the existing path (`__db_answer`, lib/db.kh:1289):
   - inside a request it calls `fail(status, body)` and adds `Retry-After: 1` on 503;
   - outside a request (`every`, test code, start) it panics with the message.

   5xx failures print one stderr line with the source location, e.g. `app.kh:14:12: mongodb failed [11600] InterruptedAtShutdown (notes.update)` or `app.kh:21:12: clickhouse failed [241] MEMORY_LIMIT_EXCEEDED (query_id khrip-3f…)`. Response bodies never contain stored values, only names; values go to the log.
3. **Failure, explicit form.** When the expected type is `DbResult`, nothing ends the request (§5.4). This form exists only for writes and non-row `ch` statements. Reads always fail closed (E-M40: `a failed read ends the request; DbResult is for writes`), as with `sql`.

Two forms keep the default usable:
- `T?` on `insert`, or `insert(...) else { }`, or `?? x`, turns a duplicate key into none. This is `ON CONFLICT DO NOTHING` into `T?`.
- `T` on `one`/`update`/`delete`/`aggregate`/`ch` turns "no document/row" into 404, and the route must list `| 404` (E-M33). This is the existing `sql_note_404` check (src/sql.kh:271), with the hint `answer yourself: let n: Note = notes.one(...) else { return 401 }`.

### 5.2 MongoDB status mapping

| Condition | Status | Body |
|---|---|---|

### 5.4 `DbResult`, the explicit form

```khrip
store buffer: [Event]

every 10 s {
    let rows = buffer.copy()
    buffer.clear()
    let r: DbResult = events.insert(rows)
    if !r.ok && !r.unknown_outcome {
        for e in rows {
            buffer.push(e)         // not stored: keep them for the next flush
        }
    } else if !r.ok {
        eprint("flush of {rows.len()} events: outcome unknown ({r.error})")
    }
}
```

- It is available on `insert`, `update`, `update_all`, `upsert`, `delete`, `delete_all`, `t.insert`, and `ch` statements without rows.
- **Fields** (§2.9):
  - `status` is exactly what the default form would have answered, so explicit code can still call `fail(r.status, r.error)`;
  - `code` is the server's code;
  - `count` is documents or rows;
  - `failed` lists the indexes of a list insert that failed (unordered in this form).
- **It must be checked (E-M32).** A local of type `DbResult` must be read in `.ok`, `.status`, `.code`, `.error` or `.unknown_outcome` on some path. Reading only `.count` does not count: on failure it is 0, which looks like "nothing matched". The compiler tracks reads of this one type with a flag set in `parse_ident`.
- There is no shared error slot (`bson_error()`, `ch_error()`) and no `error` field inside values (Н5).

### 5.5 Unused results

| Code | Rule |
|---|---|
| `notes.find(...)`, `notes.one(...)`, `notes.count()`, `notes.aggregate(...)`, `ch "SELECT ..."` as a statement | E-M12 / E-CH13: `the result of notes.find is not used` |
| `let r: DbResult = ...` never checked | E-M32 |
| `notes.update(...)`, `notes.delete(...)`, `events.insert(rows)`, `ch "ALTER ..."` as a statement | allowed: a failure cannot be lost, because it ends the request. A count of 0 is not a failure, as with `sql "UPDATE ..."`. §11.5 lists ignored counts as a remaining risk. |

- the store-lock windows read no store object (§8.3).

### 6.2 More databases


## 7. Startup, schema and tests

### 7.1 Order and reporting

1. **Configuration (§6.1).**
2. **PostgreSQL**, unchanged: migrations, then `sql` verification.
3. **Each ClickHouse connection** (§7.3).
4. **Each MongoDB connection** (§7.2).

Every check runs, and all failures are printed: `file:line:col: error: ...` for sites and declarations, `khrip: ...` for configuration. Then the process exits 1, as `__db_start_here` does (lib/db.kh:1105).

Network failures at start are retried for up to 60 s, because the database may still be starting. Authentication and configuration errors are not retried. Startup state is allocated in permanent memory, not in `store` and not in an arena:
- parsed URIs;
- index lists;
- DESCRIBE plans;
- readonly flags;
- sample results.

### 7.2 MongoDB

Per connection:
1. **Connect and authenticate**, then `hello`. MongoDB 6.0 or later is required (S23). A program that writes, connected to a secondary, is refused: `MongoDB at h:27019 is not a writable primary`.
2. **`listCollections`** once per database.
3. **Indexes.**
   - In `apply` mode, `createIndexes` runs once per collection with all declared indexes. "All indexes already exist" is success.
   - IndexOptionsConflict (85) or IndexKeySpecsConflict (86) → S5. A duplicate key while building a unique index → S6.
   - In `check` mode, `listIndexes` runs and is compared with the declaration; a missing index → S7.
   - Undeclared indexes are left alone (they may belong to someone else) and are listed once: `khrip: note: users has index legacy_1 that is not declared`.
4. **A collection the program never writes**, and that declares no index, must exist (S8, with did-you-mean against the existing names). Without this, a typo in `at "..."` would read nothing.
5. **Validator.** If the collection has a `$jsonSchema`:
   - each property's `bsonType` must allow what the Khrip field (with hints) writes (S9);
   - each `required` property must be a non-optional field of `T`.

   Other validator operators are not interpreted.
6. **Sample.** `aggregate [{$sample: {size: MONGODB_SAMPLE}}, {$project: {f: {$type: "$f"}, ...}}]` over `_id` and `T`'s top-level fields gives the stored BSON types without decoding (measured, Appendix A.2). Each is classified against §4.2:

   | Found | Result |
   |---|---|
   | **Comparison-class mismatch** in any sampled document: ObjectId vs string, Date vs int/string without `date`, Binary vs string without `binary` | **error S10**: Khrip's filters would silently miss these documents, and reads would fail |
   | Missing or null in a required field; a double in an `int` field; another incompatible type | **warning S11** with counts: reads of those documents fail loudly with 500; one odd old document must not stop a deploy |
   | Empty collection | passes; documents written later fail at decode with a precise 500 |

`./app migrate` and `DATABASE_MIGRATE=apply` create indexes. On large collections the build blocks start until it finishes; DATABASES.md recommends `./app migrate` as a deploy step.

Filters, changes, sorts, projections and pipelines need no server: they are checked at compile time against `T` (§2.4–§2.6).

### 7.3 ClickHouse

Per connection:
1. **`SELECT version(), getSetting('readonly'), serverTimezone()`.**
   - A readonly=1 user disables all settings.
   - A program that inserts, migrates or runs write `ch` with a readonly user → S20.
   - A non-UTC server time zone with readonly=1 → note (§4.5).
2. **Migrations** (`migration ch N`, §2.8). In `check` mode they are only verified.
3. **Tables.** `DESCRIBE TABLE t` (also the low-level DESCRIBE cache) gives name, type, `default_type` and `default_expression`. The rules of §4.7 are checked for `T` and for every `S` passed to `t.insert` (S12–S14, S24). A table with `Insert { dedup }` sites must be Replicated, or must show `non_replicated_deduplication_window` > 0 in `system.tables.create_table_query` (S21). The result is the insert plan.
4. **`ch` sites**, each `ORDER BY` variant separately.
   - **SELECT-like:** `DESCRIBE TABLE (<query with {pN:Type}>)` with sample parameters: int `1` (0 breaks `intDiv` and `toIntervalSecond`), float `1`, bool `true`, str `''`, list `[]`, optional `\N`, enum its first variant, ObjectId 24 zeros.

     - Messages reuse the `sql` wording (S15, S16), and error messages show the `{expr}` source text instead of `pN`.
     - Value-dependent errors from the samples (6, 27, 38, 41, 53, 69, 70, 72, 153, 321, 376, 457, 691) are retried with the str samples `'1970-01-01 00:00:00'`, `'00000000-0000-0000-0000-000000000000'`, `'1970-01-01'` and `'0'`.
     - If they still fail, the site gets warning S19, and its first run checks the response header against the type before decoding, so a mismatch is a loud 500, never wrong data.
     - Type and name errors (43, 47, 60, 62, 386) are site errors with the server message. Known cases get a hint (S18).
     - `materialize()` wrapping was tried by library-first and rejected: it changes typing.
   - **`INSERT ... SELECT`:** DESCRIBE of the SELECT and of the target table, matched by name.
   - **Other statements:** `EXPLAIN AST` (syntax) and `EXISTS TABLE` for the named table.

## 8. Concurrency and the runtime

### 8.1 `tx`

**No collection, table or `ch` call inside a PostgreSQL `tx`**, whether direct, as a method, or through functions (E-M43, E-CH16). `driver_io` (src/drivers.kh:4) and `fn_effect` (src/sql.kh:416) learn the new forms:
- an `SK_COLL`/`SK_TABLE` identifier followed by `.`;
- a ClickHouse `T_SQL` token.

The reason: `tx` re-runs its block on a serialization conflict, and neither database takes part in the PostgreSQL transaction. Building values inside `tx` is allowed.

### 8.2 MongoDB transactions: not in v0.13

Multi-document transactions need:
- a replica set (the test server is a standalone mongod, schema-first A.9);
- sessions (`lsid`, `txnNumber`), which the low-level driver does not have;
- a retry loop over `TransientTransactionError`/`UnknownTransactionCommitResult` that re-runs user code. That is exactly what `tx` does for PostgreSQL. A later `tx` whose body has only collection calls would fit the same block, with mixing databases in one block a compile error (§16).

The v0.13 idiom, taught in one KHRIP.md line:
- **a conditional update plus the count:** `orders.update(o => o._id == id && o.status == "new", {"$set": {"status": "paid"}}) == 0` → 404/409;
- **`$inc`** for counters;
- **`update` into `T` with `Find { sort }`** to claim one document atomically (measured, Appendix A.2);
- **unique indexes**, plus `insert` into `T?`, for idempotency.

Unlike `sql`, a MongoDB write after a read outside `tx` is not an error, because a conditional update cannot always replace the read. §11.5 lists the race (S1).

### 8.3 Store-lock windows (v0.13-store-gc.md §6.5/§6.6)

Every typed operation runs in three phases:
1. **Under the lock, if held.**
   - Evaluate the outer values. This is user code, which may read `store`.
   - Build the complete request bytes: the filter document from the nodes, the change, documents or rows, the URL with `param_pN`, the RowBinary body.
   - Copy the deadline, limits and connection descriptor from permanent memory.
2. **Window.** It calls the low-level layer's run function: `__mongo_run(q)` inside `mongo_command`, or `__dh_exchange(...)` inside `__ch_run`. These are GC §6.5's audited sites 4 and 5, built on `__store_release_keep` → exchange → `__store_lock`.
   - The window reads only the request bytes, mmap pool memory and permanent configuration.
   - It allocates the reply above the published `hi`.
   - It writes only mmap and ctx words.
   - **The typed layer adds no window**, so the lint count stays at five.
3. **After `__store_lock()`.** Classify; decode into fresh arena values; fail if needed.
   - A drained `find` repeats steps 2–3 per `getMore`, decoding each batch after re-locking, so raw batches do not accumulate.
   - Decoding after re-lock follows `__fetch`. That was judge 2's request; schema-first decoded inside the window.

Invariants:
- **W1:** nothing below `hi` is written in the window.
- **W2:** no store object is dereferenced; configuration is permanent, and values were encoded before the release.
- **W3:** unchanged; request-end hooks run before the final release.

**Lock classes (С10).** Typed operations and `ch` neither read nor write `store`. `rw.kh` lists them as store-neutral, so a route that reads `store` and calls MongoDB or ClickHouse takes the shared lock.

### 8.4 Library writes and GC

**The library never writes into a user-reachable object.**
- Typed operations only read their arguments and return fresh values.
- `insert` returns its argument unchanged.
- No cursor or builder object exists for library code to mutate.

This is the DESIGN.md rule from the review (§4.3), satisfied by construction. GC step 6's library barrier table needs no driver entries.

| GC concern | How it holds |
|---|---|
| Driver values in `store` | None are reachable: no cursor or `Bson` values in the typed surface; low-level byte types stay banned. `DbResult` and `ObjectId` are plain data. |
| Configuration and plans | Permanent memory, not roots, holding no pointers into STORE or arenas. |
| Compile-time data | Declarations, sites, sort documents, index specs and literal plans are DATA. |
| Descriptors | `ObjectId` is a `str` at run time (brand word only in the descriptor), so ptrbits and the copier are unaffected. |
| ctx words | Only the low-level words (MONGOHELD, CHHELD, TLS_PENDING, pools, the request cursor list). Streaming adds no word: the hidden cursor is a frame local registered in the low-level request cursor list. |

### 8.5 Cursors and streaming

- `find`, `aggregate` and `distinct` into a list drain the cursor inside the operation. Every batch is decoded after re-lock, bounded by `MONGODB_MAX_RESULT`. No cursor id outlives the call, except after a failure, where the request-end hook queues `killCursors` (С9).
- `for x in C.find(...)` (step 7) compiles to a loop over a hidden cursor local:
  - the first batch comes from `find`;
  - each document is decoded into `x` and the body runs;
  - at the end of a batch comes a `getMore`, which is one window;
  - `break`, `return`, `fail` and panics leave through the request-end hook (`killCursors`);
  - one mmap buffer is reused for raw batches.

  It has no total-size cap. Decoded documents stay in the arena until the request ends (§2.7).
- ClickHouse results are materialized and bounded by `CLICKHOUSE_MAX_RESULT`. Streaming them needs `wait_end_of_query=0` and exception detection inside RowBinary, which is out of scope.

### 8.6 Cancellation, deadlines and retries

- **Deadline.** Every operation has one: now + the driver timeout (§6.1). Server-side limits get the remaining budget (Н12).
- **On the client deadline:**
  - a read → 503;
  - a ClickHouse SELECT also gets the best-effort `KILL QUERY WHERE query_id = '…' ASYNC` on another pooled connection;
  - a write that was sent → 500 `write outcome unknown`, never retried. MongoDB discards the connection, and the server stops by itself through `maxTimeMS`.
- **Retries.** A **read** is retried once, within the deadline, after a network error on a reused pooled connection (a stale socket) or after NotWritablePrimary-class codes. Writes are never retried: there are no sessions or `txnNumber`, hence no retryable writes, so a lost write is "unknown".
- **Client disconnects** are not observed, as with `fetch` and `sql`.

### 9.1 Lexer (src/lex.kh)

- **`ch` queries.** `ch`, an optional identifier and `"` or `` ` `` on the same line start a ClickHouse query: `lex_sql` with a dialect flag (§3.2). `sql_string_next` (src/lex.kh:657) gets a variant that skips one identifier.

### 9.2 Declarations (new src/coll.kh; hooks in src/decl.kh `prescan_from`)

**Prescan.** Pass 2 of `prescan_from` (src/decl.kh:713) dispatches:

| Tokens | Handler |
|---|---|
| `collection` IDENT `:` | `prescan_collection` (prototyped) |
| `table` IDENT `:` | `prescan_table` |
| `mongodb`/`clickhouse` IDENT `=` | `prescan_conn` |
| `migration` (`ch` \| IDENT) INT | a ClickHouse migration, beside `prescan_migration` (src/sql.kh:586) |

**Symbols.** New symbol kinds `SK_COLL`, `SK_TABLE` and `SK_CONN` index the arrays `colls`, `tables` and `conns`.

**Checks** run after `prescan_struct_fields`:
- `T` is a struct with a non-optional `_id`;
- block paths are fields;
- hints are allowed for the field types;
- `ttl` is on a time field.

The compiler then computes per collection:
- the **unique sets**: `[["_id"]]` plus each `unique` line (prototyped);
- the **storage plan** (path → storage kind), passed to every encoder and decoder of that collection.

**Descriptors in DATA**, one per collection, table and connection, like `sql` sites. Each holds:
- the connection index, the database and object names, and `T`'s type descriptor;
- the storage plan and the unique sets;
- the index specs as constant BSON, from a small BSON writer in the compiler;
- the block options and the location.

The root table entries sit next to `sql_root()`.

### 9.3 Type inference rules (exact)

1. **Expected type.** `w` reaches a collection method or `ch` exactly as it reaches `sql` today:
   - `let x: T =`;
   - `return` (the route's type for that status, or the function's result);
   - struct field values;
   - arguments with a declared parameter type;
   - `else`/`??` follow-ups, which make the shape optional (`optional_follow`, as in `parse_sql`).
2. **Shapes** are the tables of §2.3 and §2.8. A `T` shape in a route requires `| 404` unless `else` follows (E-M33, through `sql_note_404`).
3. **Defaults without `w`:**

   | Call | Default |
   |---|---|
   | `find` | `[T]` |
   | `one` | `T?` |
   | `insert(v)` | `T` |
   | `insert(vs)` | `[T]` |
   | `update`/`delete` | `int` |
   | `update_all`/`delete_all`/`count` | `int` |
   | `upsert` | nothing |
   | `distinct` | `[E]` |
   | `aggregate`, `ch` row statements | E-M29 / E-CH13 |
   | other `ch` statements | `int` |
4. **Results that are not `T`:** `R` for `find`, `one`, `update`, `delete` and `upsert` must be a struct whose fields are fields of `T` with identical types (E-M37). The projection document is built from `R` at compile time; `_id: 0` when `R` has no `_id`.
5. **Filter lambdas.** The parameter has type `T`, or the element type inside `any`.
   - Outer operands are parsed with the expected type of the field they meet (`want = field type`), so `[]`, enum labels and `none` take their types from the field.
   - Comparisons are type-checked with the existing rules (`coerce`, `compare_ok`), and type errors keep their familiar wording.
   - `x == none ||` / `x != none &&` narrowing reuses `none_test_at` (prototyped).
6. **Changes.** A struct's fields ⊆ `T` (E-M14). Literal values are parsed with the expected type of their path (`{"$set": {"tags": []}}` types `[]` as `[str]`).
7. **`ch` parameters.** Parameter types follow §3.3. `T?` without the `IS NULL` guard is the `sql` error.
8. **`DbResult`** is a shape for writes only (E-M40 for reads). Its local is tracked for reads of `.ok/.status/.code/.error/.unknown_outcome` (E-M32).

### 9.4 The filter translator (as prototyped in src/coll.kh)

**Input:** the lambda parameter, its type `T`, the collection's storage plan and unique sets.

**Output:** code that leaves a filter node in RAX. A node is a runtime value `__Mf { k: false | true | doc, parts: [Bson] }`, where `parts` is a conjunction of one-condition documents. `__mf_doc` turns it into the final filter:
- `{}` for true;
- `{_id: {$in: []}}` for false, which uses the `_id` index and scans nothing (schema-first A.3);
- otherwise the document.

In the final version a false filter never reaches the server for `find`, `one` or `count`. The prototype still sends `{_id: {$in: []}}`.

1. **Structure** is a recursive descent on tokens:

   ```
   or  := and ('||' and)*     →  __mf_or, short-circuit when the accumulator is true
   and := not ('&&' not)*     →  __mf_and, short-circuit when it is false
   not := '!' not | '(' or ')' | atom
   ```

   The accumulator is on the stack; a `jcc` over the remaining terms reproduces Khrip's `&&`/`||` exactly. Narrowing of `x == none ||` and `x != none &&` is pushed and popped as in `parse_or`/`parse_and`. A parenthesis is a group if its matching `)` is followed by `&&`, `||`, `)` or `,`.
2. **Atom classification.** A scan to the atom's end (a depth-0 `&&`, `||`, `)`, `,`) decides whether the atom mentions the parameter. A parameter token preceded by `.` is a field named like it, not the parameter.
3. **Outer atom** (no parameter): `parse_cmp()` → `bool` → `__mf_const`.
4. **Path atom.**
   - Parse `x.f.g`, checking each segment with `field_find`; unknown fields get the existing did-you-mean.
   - Then one of:
     - a comparison operator;
     - a method (`contains`, `starts_with`, `ends_with`, `lower()` + one of those or `==`, `len()` + comparison, `any(l => ...)` with a nested translator state);
     - a bare `bool` field.
   - The other operand is parsed with `parse_add()` under `want = field type`.
   - The call is `__mf_cmp(path, op, value, descriptor, flags)`, where the flags carry "field optional" and "lower-cased". The runtime applies §2.4's none rules and encodes the value with the path's storage.
   - Field vs field → `__mf_fields(a, op, b)` → `$expr`.
   - The reversed forms `v < x.p` and `xs.contains(x.p)` need the value side parsed up to a stop position. They get a `stop_at` check in `parse_postfix`, which is not prototyped (§9.9).
5. **Uniqueness.** While parsing, an equality whose value is non-optional (or whose field is required) records its path in `mf_eq`. Paths recorded under `||` or `!` are dropped when that subtree ends. The filter is unique if `mf_eq` contains `_id`, or every field of one unique set (prototyped).
6. **Values** are evaluated once, left to right, when their atom is reached, so short-circuit skips them: `lim == none || x.price <= lim.max` never reads `lim.max` when `lim` is none (prototyped).

### 9.5 Document literals and pipeline shapes

- **Document literals** use library-first's `parse_doc_lit`/`parse_doc_arr`/`parse_doc_value` with contexts:
  - `CHANGE` (operators at the top level);
  - `STAGES` (`$match` → match context; other stages → expression context with `$literal` wrapping);
  - `VALUE`.

  Additions over the prototype: operator tables per §2.5; path and value typing from `T`; `U?` rules; positional `$` checked against an `any` in the filter (E-M31); upsert completeness (E-M23/E-M24).
- **The JSON-null marks** of a struct value are read at encode time. This is the same code as `sql`'s `SET {patch}` path (src/sql.kh:1810).
- **Pipeline shapes** are checked by a token-level pass over the stage literals before they are compiled: `coll_check_pipeline`, prototyped, 120 lines. It holds a list of known top-level keys, or "unknown". `$lookup.from` is matched against the declared collections.

### 9.6 Sites and code generation

- **MongoDB.** Each operation pushes its arguments in this order:
  - the collection descriptor;
  - the filter node or document;
  - the change document;
  - the options (`MongoOpts` from `__mf_opts`);
  - the shape;
  - the result descriptor.

  It calls one runtime entry. The prototype uses `__mt_find2`, `__mt_one`, `__mt_count`, `__mt_insert`, `__mt_update_n`, `__mt_delete_n`, `__mt_modify2`, `__mt_remove2` and `__mt_aggregate2`.

  The final version replaces the prototype's per-call `bson_*` building with a site in DATA (24 words, like `SITE_*`). The site holds:
  - the kind, collection descriptor, shape and result descriptor;
  - the projection and sort documents prebuilt as BSON;
  - templates for the change and the stages, with hole tables.

  `__docdb_run(site, vals)` copies static bytes and encodes the holes. Constant sub-documents are built once, at compile time.
- **ClickHouse.** A `ch` form is a `sql`-style site with a dialect word, ClickHouse parameter type names, the connection index, the location and the variant list. `__chdb_run(site, vals)` runs it. `t.insert` sites record `S`'s descriptor, which startup checks, and the plan pointer that start fills in.

````markdown
- A filter is a lambda with the meaning of `filter`, run by the database: fields
  against values or fields, `&& || ! none contains starts_with lower len any`.
- `find` gives `[T]` (a smaller struct: its fields only); `limit` needs `sort`.
  `one`, `update`, `upsert`, `delete` touch one document: filter on `_id` or a
  `unique` field, or take the first by `Find { sort }`.
- `none` is never stored. A struct change sets its fields (`T?` ones if sent;
  `null` removes); `{...}` holds operators, checked against `T`. `ObjectId` is
  24 hex digits in JSON and paths.
- `ch "..."` is `sql` for ClickHouse (DateTime: `int` seconds or `str`); DDL
  goes in `migration ch N`; tables and queries are checked at start.
- Failures end the request as with `sql`; `let r: DbResult = <write>` returns
  `r.ok`, `r.status` instead; `insert` into `T?` gives none on a duplicate. Not
  in `tx`; MongoDB has no `tx`: put the condition into the update filter and
  check the count. Tests: `KHRIP_TEST_MONGODB_URI`, `KHRIP_TEST_CLICKHOUSE_URL`.
````

### 11.2 The programs

The three programs of the review (`pr1-evidence/1/p1`, `p2`, `p3`), rewritten. They keep the PR versions' type declarations, with `_id: str` → `_id: ObjectId`, so the differences come from the API. P1 and P2 compile and run on the prototype exactly as printed. Files: `final/progs/`.

**P1, notes CRUD on MongoDB** (`p1_notes.kh`; with `index tags, -created`: `p1_notes_indexed.kh`)

```khrip
type NoteIn { title: str, body: str, tags: [str] = [] }
type Note { _id: ObjectId, title: str, body: str, tags: [str], created: int }

collection notes: Note

route POST "/notes" (body: NoteIn) -> 201 Note {
    return 201 notes.insert(Note { _id: object_id(), created: now(), ...body })
}

route GET "/notes/{id}" (id: ObjectId) -> Note | 404 {
    return notes.one(n => n._id == id)
}

route GET "/notes" (tag: str?, limit: int = 20) -> [Note] {
    return notes.find(n => tag == none || n.tags.contains(tag), Find { sort: "-created", limit })
}

route PUT "/notes/{id}" (id: ObjectId, body: NoteIn) -> Note | 404 {
    return notes.update(n => n._id == id, body)
}

route DELETE "/notes/{id}" (id: ObjectId) -> 204 | 404 {
    if notes.delete(n => n._id == id) == 0 {
        return 404
    }
    return 204
}
```

**P2, orders: insert, conditional update, aggregation** (`p2_orders.kh`)

```khrip
type NewOrder { customer: str, category: str, amount: int }
type Order { _id: ObjectId, customer: str, category: str, amount: int, status: str, created: int }
type CategoryStat { _id: str, total: int, orders: int }

collection orders: Order

route POST "/orders" (body: NewOrder) -> 201 Order | 400 str {
    if body.amount <= 0 {
        return 400 "amount must be positive"
    }
    return 201 orders.insert(Order { _id: object_id(), status: "new", created: now(), ...body })
}

route POST "/orders/{id}/pay" (id: ObjectId) -> 204 | 404 {
    if orders.update(o => o._id == id && o.status == "new", {"$set": {"status": "paid"}}) == 0 {
        return 404
    }
    return 204
}

route GET "/stats/categories" (since: int = 0) -> [CategoryStat] {
    return orders.aggregate(o => o.status == "paid" && o.created >= since, [
        {"$group": {"_id": "$category", "total": {"$sum": "$amount"}, "orders": {"$sum": 1}}},
        {"$sort": {"total": -1}}
    ])
}
```

**P3, ClickHouse batch insert and parameterised report** (`p3_events.kh`; with the DDL as `migration ch 1` on the realistic schema: `p3_events_migration.kh`). The leading `CREATE TABLE` comment is the PR program's and is not counted.

```khrip
// CREATE TABLE events (ts Int64, user_id Int64, page String, ms Float64)
//     ENGINE = MergeTree ORDER BY (page, ts)
type EventIn { user_id: int, page: str, ms: float }
type Event { ts: int, user_id: int, page: str, ms: float }
type PageStat { page: str, views: int, users: int, avg_ms: float }
type Inserted { inserted: int }

table events: Event

route POST "/events" (body: [EventIn]) -> 202 Inserted | 400 str {
    if body.len() == 0 || body.len() > 10000 {
        return 400 "send 1..10000 events"
    }
    let t = now()
    return 202 Inserted { inserted: events.insert(body.map(e => Event { ts: t, ...e })) }
}

route GET "/stats/pages" (from: int, to: int, limit: int = 10) -> [PageStat] {
    return ch `SELECT page, count() AS views, uniq(user_id) AS users, avg(ms) AS avg_ms
        FROM events WHERE ts >= {from} AND ts < {to}
        GROUP BY page ORDER BY views DESC LIMIT {limit}`
}
```

What the compiler and runtime do with them:
- **P1.** `notes` binds to `MONGODB_URI`'s database, and `one` is unique by `_id`.
  - The list filter folds `tag == none` at run time into `{}` or `{tags: tag}`.
  - The sort is a constant `{created: -1}`, and `limit` is `int` into `int?`.
  - `update` into `Note` is `findAndModify {_id}, {$set: {title, body, tags}}, new: true`.
- **P2.**
  - The pay route replaces a transaction with one conditional update.
  - In the pipeline, `"$category"` and `"$amount"` are checked against `Order`, the `$group` keys against `CategoryStat`, and the `$sort` key against the `$group` output.
  - `{"$sum": 1}` comes back as Int32 and widens into `int`.
- **P3.**
  - At start, `DESCRIBE TABLE events` checks `Event` and builds the plan.
  - On the realistic schema `(ts DateTime, user_id UInt64, page LowCardinality(String), ms Float32)`, this is int → DateTime (seconds, range-checked), int → UInt64, str → LowCardinality and float → Float32. The PR's `ch_insert` could not write to that schema (В6).
  - `DESCRIBE TABLE (SELECT ... {p1:Int64} ...)` with samples gives `LowCardinality(String), UInt64, UInt64, Float64`, which matches `PageStat` (measured by all three designs).
  - `events.insert` into `int` (the field `inserted`) is the number of rows.

### 11.5 Remaining places where an AI can still make a silent mistake

Silent means that the program compiles, starts and passes a quick test, but gives wrong results or loses data.

| # | Mistake | Example | Why the design does not stop it | Mitigation |
|---|---|---|---|---|
| S1 | Check-then-act without a transaction | `let o: Order = orders.one(...)`, then `if o.status == New { orders.update(x => x._id == id, ...) }` | MongoDB has no `tx` here; a rule like `sql`'s "write after a read outside tx" would also reject correct code | KHRIP.md teaches the conditional update. Candidate lint: a `one` followed by an `update` of the same collection whose filter repeats only the `_id`. |
| S2 | Two writes in one route are not atomic (insert an order, decrement stock) | — | no MongoDB transactions in v0.13 | DATABASES.md patterns; eval task `polls-mongo` measures it (§12) |
| S3 | Ignoring the matched count | PUT/DELETE answers 204 for a missing id | legal on purpose (idempotent handlers), as with `sql` | the KHRIP.md example uses the count; eval checks |
| S4 | Units | `ts >= {from}` with milliseconds against a `DateTime`; `now_ms()` into an `int` field without `date` | both are `int` | `date` fields reject values above 10^11; DateTime inserts are range-checked; queries are not checked |
| S5 | Field references after a stage with an unknown shape | `"$totl"` after `$lookup` or `$facet` | shape tracking stops at stages it cannot model | most pipelines are `$match/$group/$sort` and fully checked |
| S6 | Data written by other programs **after** start, with other BSON types | a later string `_id` | the startup sample saw only earlier data | reads are loud 500s; filters may miss those documents until the next start |
| S7 | Defaults hide renamed fields | `views: int = 0` while another program writes `view_count` | a default is right for schema evolution | the startup sample warns about missing required fields only |
| S8 | Substring search expectations | `x.title.contains(q)` is case-sensitive and not indexed | the same meaning as in memory | `lower()` form; documented |
| S9 | PUT with defaulted fields clears data | `tags: [str] = []` absent from the body → `$set: {tags: []}` | the same as `SET {body}` in PostgreSQL | patch types with `T?` fields |
| S10 | ClickHouse engine semantics | `ReplacingMergeTree` read without `FINAL` double counts | engine rules, not types | DATABASES.md; candidate startup note when a `ch` SELECT reads such a table without `FINAL` (the engine is in `system.tables`) |
| S11 | Retrying after `write outcome unknown` duplicates ClickHouse rows | a client retry of the same batch | the server may have applied the insert | 500, not 503; `Insert { dedup }` with S21's startup check |
| S12 | Losing rows in an `every` flush | `let rows = buffer.copy(); buffer.clear(); events.insert(rows)` panics when ClickHouse is down | fail-closed in a task is a panic | documented `DbResult` pattern (§5.4) |
| S13 | ClickHouse `String` holding binary returned as JSON | invalid UTF-8 → U+FFFD (D9) | `String` is bytes by design | `base64Encode` in the query |
| S14 | A query that could not be checked at start | DESCRIBE failed on sample values | samples are not real values | warning S19; the first run checks the header before decoding, so a mismatch is a loud 500 |
| S15 | Case folding outside ASCII, Latin, Cyrillic and Greek in `lower()` filters | Turkish dotless i | PCRE folding differs from Khrip's simple mapping | documented difference (§2.4) |

| S17 | Float columns round | a `float` into `Float32` or `Decimal(P,S)` | the schema's choice | documented |

## 16. Deliberately out of scope, and risks

| Item | Why not now | How it would fit |
|---|---|---|
| MongoDB multi-document transactions | Need sessions, a replica set and a retry loop that re-runs user code | A `tx` whose body has only collection calls, with mixing databases in one block a compile error |
| Explicit failure handling with `else e` for every form | `DbResult` covers writes. `else e` would change PostgreSQL too, and reads would gain a fallback form; that needs its own design | language-forms' `else e { ... }` with a mandatory read of `e` |
| A read fallback (serve a stale cache when the database is down) | Same as `sql` today: reads fail closed | `else e` above |
| A time type | Language-wide; `int` seconds plus storage hints cover v0.13 | a branded `int` with ISO JSON, for all three databases at once |
| A `bytes` type | Base64 `binary` fields and raw ClickHouse `String` cover the cases (§4.9) | — |
| A typed `for x: P in ...` | Language-wide | projection and `aggregate` streaming |
| Text and geo filters and indexes, collation, `hint` | Each needs its own declaration and typing | `index title: text`, a `$text` filter form |
| Decimal128 writes, `validate` | Step 8 only if the eval asks | §2.2 |
| Change streams (`watch`), GridFS, `bulkWrite`, SRV/seed lists/SDAM | Not needed by the API patterns; the low-level layer has no SDAM | low-level first |
| Once-only MongoDB data migrations (`migration mongodb N { ... }`) | Data rewrites are ordinary code for now | recorded in a `khrip_migrations` collection |
| Compile-time parsing of ClickHouse migrations (`khc check` without a server) | Startup DESCRIBE checks the real schema | as `sqlcheck` does for PostgreSQL |
| ClickHouse `Tuple`, `Nested`, `JSON`, `Dynamic` columns | Startup errors with hints | named Tuple ↔ struct |
| Streaming ClickHouse results | Needs `wait_end_of_query=0` and exception detection inside RowBinary | `for row in ch "..."` |
| Per-call user query ids and a cancel API | Cancellation by site through `log_comment` covers the need | an `Insert`-like options literal for `ch` |
| Generating `CREATE TABLE` from Khrip types | Khrip types cannot express engines, ordering, codecs or partitions, and there would be two sources of truth | — |
| Qualified ClickHouse database names in `ch` | One database per connection keeps `khc test` isolation simple | rewriting names per test database |
| Lints for S1 (check-then-act) and S3 (ignored counts) | Need evidence that they do not reject correct code | candidates after the eval |

- **Prompt growth against the measured gain.** Mitigated by the eval gate.
- **The low-level additions.** Small, listed, and gated in step 0.

## Appendix A. Probes on the real servers (this synthesis)

MongoDB 8.0.34 (standalone, 127.0.0.1:27019) through the prototype and pymongo 4.19; ClickHouse 25.8.33.6 (127.0.0.1:8125) through curl. All databases (`fin_p1`, `fin_p2`, `fin_orders`, `fin_sem`, `fin_probe` in MongoDB; `fin_t` in ClickHouse) are dropped.

**A.1 Partial unique index with `$type`.** `email_1` with `partialFilterExpression: {email: {$type: "string"}}`:
- documents without `email` insert;
- a duplicate `"a@x"` → `DuplicateKeyError 11000 {'email': 1}`;
- two documents with an explicit `email: null` insert.

**A.2 MongoDB building blocks.**
- **`$sample` + `$project {$type}`** over `{ObjectId, "a", 5}`, `{"str-id", "b", 7.5}`, `{ObjectId, "c"}` gives `objectId/string/int`, `string/string/double` and `objectId/string/missing`.
- **Claiming:** `find_one_and_update({st: "new"}, {$set: {st: "taken"}}, sort t, new)` claims `_id 0`.
- **Empty change:** `{$set: {}}` → `n: 1, nModified: 0`.
- **Field vs field:** `{$expr: {$gt: ["$p", "$c"]}}` matches `{p: 5, c: 3}` only.

**A.3 Prototype runs.** §11.1.

**A.4 ClickHouse lexing.**
- `SELECT 'it\'s', 'a''b' # comment` + `-- other` + `/* c */` → `it\'s	a\'b`;
- `SELECT $$x{y}$$` → `x{y}`.

**A.5 Parameters in SETTINGS.** `SELECT 1 SETTINGS log_comment = {c:String}` → `Code: 62 ... Syntax error ... Expected substitution type`. The same holds for `max_threads = {n:UInt64}`.

**A.6 Deduplication tokens.**
- A MergeTree table without settings: the same `insert_deduplication_token` twice stores 2 rows.
- With `SETTINGS non_replicated_deduplication_window = 100`: 1 row.
- `system.merge_tree_settings` default: 0.

**A.7 Query ids and cancellation.**
- `query_id=khrip-test-1&log_comment=app.kh:12:5` appears in `system.query_log` with that comment.
- `system.processes` has `query_id`, `user` and `elapsed`, but no `log_comment` column.
- `KILL QUERY WHERE Settings['log_comment'] = {c:String} ASYNC` kills the running `sleepEachRow` query of that site and returns `kill_status, query_id, user, query`.
- `KILL QUERY WHERE query_id = 'nope'` returns no rows.

**A.8 Time zone.**
- `serverTimezone()` is UTC.
- With `session_timezone=Asia/Tokyo`, `toDate(toDateTime(1792782805))` is 2026-10-24; with UTC it is 2026-10-23.
- `toDate({x:Int64})` works.
- `toDate('2026-10-24') >= {x:String}` with `'2026-10-23'` → 1.

**Measured by the earlier designs and relied on here**, not repeated:
- `DESCRIBE TABLE (query)` needs parameter values; sample-value failures (38, 41, 153, 376);
- `Date >= Int64` → 43;
- `IN {p:Array(Int64)}`;
- Nullable parameters with `IS NULL`;
- LIKE `_` without escaping;
- `input_format_null_as_default`;
- `-1` into `UInt32` through `VALUES`;
- `createIndexes` idempotence and conflicts 85/86;
- the `$literal` field-path leak;
- `$sum` of a misspelt field gives 0;
- string `_id` against ObjectId gives `[]`;
- update without operators replaces the document.
