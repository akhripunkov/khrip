## Заметки для следующих шагов

**UTF-8, шаг E**
- `str_method_fn` (src/atom.kh) жёстко отображает пользовательские `find`, `find_from`,
  `lower`, `upper`, `trim` на байтовые функции; поиск `__text_*` должен идти раньше.
- В проекте нет `__text_find_from`: без него `s.find_from` останется байтовым, а `find`
  станет символьным. Нужен `__text_find_from` (начало — номер символа; отрицательное — с
  начала строки, как у `__str_byte_find_from`).
- `s.byte(i)` в пользовательском коде встраивается: паника «at файл:строка» вместо «at str».

**UTF-8, скорость.** Цели §9 после шага D не достигнуты:
- индексный цикл по 1 МБ — 38 мс (цель ≤ 30);
- 100 тыс. случайных `s[i]` — 29 мс (цель ≤ 8);
- `lower()` на 180 Б кириллицы — 1,9 мкс (цель 0,4–0,9);
- промах кэша на 1 КБ дороже простого сканирования на 0,2 мкс.

Ревью профилировало, куда уходит время; что исправлено сразу — в коммите правок по ревью.
Остальное — до шага I.

**UTF-8, шаги H и I**
- `byte_api_shadow` ловит только 7 новых имён. Вопрос: общее правило «функция с именем
  встроенного метода str и первым параметром str — ошибка в объявлении» (сейчас
  `fn trim(s: str)` молча проигрывает встроенному `s.trim()`).
- Документировать байтовый API в KHRIP.md.
- Рост khc: 1 171 024 Б до A+B, 1 209 832 Б после C+D.

**Сборщик, шаг 4.** `__perm_alloc` (lib/rt.kh) занимает слова `__store_rw + 48` (futex) и
`+ 56` (текущий кусок).

**Сборщик, шаг 1 — побочные эффекты до шага 2**
- Начальные значения store-глобалов лежат на куче: вложение такого значения в другой
  store-объект копирует его, а не делит.
- Восстановление KHRIP_DATA копирует всё в STORE, декодированная копия на куче остаётся
  жить (уйдёт с загрузочной ареной шага 2).
- DESIGN.md, п. 4, описывает старое правило «копируются только значения арены» — обновить
  в шаге 7.

## Как продолжить в новом контейнере

- `./build.sh`, затем `tests/run.sh` (сейчас 272 из 272 до правок по ревью).
- PostgreSQL: `service postgresql start` (postgres/khrip, 127.0.0.1:5432).
- Две копии могут гонять тесты одновременно, если у каждой свои порты:
  `HTTP_PORT CORO_PORT TLS_PORT PG_PORT W_METEO W_HOOK W_APP W_TICK EVAL_PORT` и
  `EVAL_DB_PREFIX`.
- Настоящие MongoDB и ClickHouse для тестов PR: `dockerd &`, затем образы
  `mirror.gcr.io/library/mongo:8.0` и `mirror.gcr.io/clickhouse/clickhouse-server:25.8`
  (Docker Hub напрямую ограничивает анонимные загрузки). Переменные: `MONGODB_URI`,
  `CLICKHOUSE_URL`, `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`.
- Данные UCD 17.0.0 для `tools/unicode_tables.kh`: unicode.org закрыт прокси, файлы есть в
  github.com/unicode-org/unicodetools, `unicodetools/data/ucd/17.0.0/`.
