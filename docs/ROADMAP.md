# Дорожная карта Khrip

Сначала рабочий минимум, затем скорость. Компилятор с самого начала написан на Khrip
и собирает сам себя. Каждый шаг заканчивается тестами и замером в `bench/` против Go
и C#. Выигрыш объявляем только по результатам замеров.

| Шаг | Что делаем | Как проверяем |
|---|---|---|
| **v0.0** ✅ | Название, цели, дизайн, стенд замеров, эталонные цифры Go и C# | `bench/run.sh` выдаёт таблицу |
| **v0.1** ✅ | Самокомпилирующийся компилятор: зерно на ассемблере + `khc` на Khrip | `khc` собирает сам себя, поколения побайтно совпадают; 21 тест |
| **v0.2** | Первый HTTP-сервер на Khrip | правильно отвечает на `/plaintext`, первый замер |
| **v0.3** | Многоядерность и арены | первое честное сравнение на `/plaintext` |
| **v0.4** | API-слой языка | сценарии `/json` и CRUD в памяти |
| **v0.5** | SIMD: SSE2, затем AVX2 | ускорение разбора HTTP и JSON по замерам |
| **v0.6** | Оптимизации генератора кода | прирост на всех сценариях, самокомпиляция не ломается |
| **v0.7** | Инструменты для нейросетей | доля решённых задач в сравнении с Go и C# |

## v0.1. Самокомпилирующийся компилятор ✅

Компилятор `khc` сразу написан на Khrip (`src/khc.kh`, подмножество
[Khrip-0](KHRIP0.md)). Первый раз его собирает зерно `bootstrap/khc0.asm` на
ассемблере x86-64; ни Go, ни C, ни других компиляторов в цепочке нет. Компилятор сам
генерирует машинный код и записывает статический ELF без libc.

Проверка (`build.sh`): зерно собирает `khc1`, тот собирает себя (`khc2`), тот снова
себя (`khc3`); `khc2` и `khc3` совпадают побайтно. Тесты: `tests/run.sh`.

## v0.2. Первый HTTP-сервер на Khrip

Однопоточный сервер на `epoll`, который правильно отвечает на `GET /plaintext` с
keep-alive. Для этого расширяем стандартную библиотеку: сокеты, буферы, разбор
запроса. Первый замер против Go и C#; скорее всего, проиграет: сервер занимает одно
ядро из двух, а генератор кода пока самый простой.

## v0.3. Многоядерность и арены

Рабочий поток на каждое ядро со своим `epoll` и сокетом `SO_REUSEPORT`. Полноценный
HTTP/1.1: keep-alive, конвейерные запросы, `Content-Length`. Арена на запрос вместо
сборщика мусора. Первое сравнение, в котором у Khrip те же условия, что у Go и C#.

## v0.4. API-слой языка

Типы `type`, объявления `route`, параметры пути, тело запроса, ответы с кодами
(`-> 200 User | 404`). Сериализация и разбор JSON генерируются при компиляции.
Хранилище `store`. Тесты `test` и команда `khc test`. Генерация OpenAPI.
Замеры на `/json` и CRUD в памяти.

## v0.5. SIMD

Сначала SSE2 (есть на любом x86-64), затем AVX2 с проверкой возможностей процессора
и ОС и запасным путём на SSE2. Применяем там, где API тратит время: поиск конца
заголовков, разбор и экранирование строк JSON.

## v0.6. Оптимизации генератора кода

По очереди, с замером после каждой:

1. Слияние соседних операций: например, загрузка переменной и арифметика с константой.
2. Локальные переменные в регистрах с сохранением при рекурсии и вложенных вызовах.
3. Верхние значения стека вычислений в регистрах R8–R11; при нехватке регистров старое
   значение уходит в память, на границах ветвлений и вызовов кэш выгружается в стек.

## v0.7. Инструменты для нейросетей

`KHRIP.md` — спецификация для промпта до ~4000 токенов. `khc check --json` с готовыми
исправлениями в ошибках. `khc fmt`. Набор задач «напиши API» с тестами и замер доли
решённых задач на Khrip, Go и C#.
