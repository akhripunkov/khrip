# Khrip-0

Khrip-0 — начальное подмножество Khrip. На нём написан компилятор `src/khc.kh`, и только
его понимает зерно раскрутки `bootstrap/khc0.asm`. Синтаксис уже тот же, что у будущего
Khrip, поэтому код на Khrip-0 останется корректным по мере роста языка.

Все значения — 64-битные знаковые целые (`i64`). Указатель — тоже целое: адрес в памяти.
Типы в объявлениях пишутся (`x: i64`), но пока проверяется только их наличие.

```khrip
const SYS_WRITE = 1

var greeted: i64

fn strlen(s: i64) -> i64 {
    var n = 0
    while load8(s + n) != 0 {
        n = n + 1
    }
    return n
}

fn main(argc: i64, argv: i64) -> i64 {
    let msg = "Hello, Khrip!\n"
    syscall(SYS_WRITE, 1, msg, strlen(msg))
    greeted = 1
    return 0
}
```

## Лексика

- Комментарии: `// до конца строки`.
- Целые: `42`, `0xFF`. Символ: `'a'`, `'\n'` — это его код.
- Строка: `"текст\n"` — адрес байтов в сегменте данных, в конце добавляется нулевой байт.
  Экранирование: `\n \t \r \0 \\ \' \"`.
- Точек с запятой нет. Переводы строк не важны, кроме одного правила: значение `return`
  должно начинаться на той же строке, что и `return`.

## Объявления верхнего уровня

| Объявление | Смысл |
|---|---|
| `const ИМЯ = 42` | Константа времени компиляции (целое или символ, можно с `-`) |
| `var имя: i64` | Глобальная переменная, начальное значение 0 |
| `var имя: i64 = 5` | Глобальная переменная с начальным значением (константа) |
| `fn имя(a: i64, b: i64) -> i64 { ... }` | Функция; `-> тип` можно опустить |

Функцию можно вызывать до её определения. Константы и глобальные переменные нужно
объявить до использования.

## Операторы

| Оператор | Смысл |
|---|---|
| `let x = выражение` | Неизменяемая привязка; тип можно указать: `let x: i64 = ...` |
| `var x = выражение` | Изменяемая переменная |
| `x = выражение` | Присваивание переменной `var`, параметру или глобальной переменной |
| `if условие { } else if условие { } else { }` | Ветвление; скобки вокруг условия не нужны |
| `while условие { }` | Цикл; внутри `break` и `continue` |
| `return выражение` / `return` | Возврат; без значения возвращается 0 |
| `f(x)` | Вызов как отдельный оператор |

Условие истинно, если не равно 0. Переменные видны до конца блока, в котором объявлены;
внутреннее объявление закрывает внешнее с тем же именем.

## Выражения

Приоритеты как в Go, от слабого к сильному:

| Уровень | Операторы |
|---|---|
| 1 | `\|\|` |
| 2 | `&&` |
| 3 | `== != < <= > >=` (без цепочек) |
| 4 | `+ - \| ^` |
| 5 | `* / % << >> &` |
| 6 | унарные `- ! ~` |

`&&` и `||` вычисляются по короткой схеме и дают 0 или 1. Деление и остаток — со знаком,
с округлением к нулю. `>>` — арифметический сдвиг. Переполнение заворачивается.

## Встроенные функции

| Функция | Действие |
|---|---|
| `load8(адрес)` | Байт по адресу (0–255) |
| `load64(адрес)` | 8 байт по адресу |
| `store8(адрес, значение)` | Записать младший байт значения |
| `store64(адрес, значение)` | Записать 8 байт |
| `syscall(номер, a1, ..., a6)` | Системный вызов Linux, результат — значение rax |

Стандартной библиотеки в языке пока нет. Небольшой набор функций (`print`, `print_int`,
`alloc`, `strlen`, ...) лежит в `lib/std.kh` и подключается как ещё один входной файл:

```
build/khc -o hello lib/std.kh hello.kh
```

## Программа

Выполнение начинается с `fn main()` или `fn main(argc: i64, argv: i64)`. Значение,
которое вернула `main`, становится кодом выхода процесса.

Компилятор выдаёт статический ELF для Linux x86-64 без libc: код загружается
с адреса `0x400000`, строки и глобальные переменные — с `0x10000000`. Память
для данных программа берёт у ядра через `mmap` (`alloc` в `lib/std.kh`).

## Как устроен код

Генератор кода — стековая машина: значение выражения в `rax`, промежуточные значения
в стеке. Аргументы функции кладутся в стек слева направо, вызывающий снимает их сам;
параметр `i` из `n` лежит по адресу `rbp + 16 + 8*(n-1-i)`, локальные переменные —
ниже `rbp`. Это простая и медленная схема; ускорять её будем на шаге v0.6 (регистры
вместо стека).

## Чего пока нет

Типов кроме `i64`, структур, массивов, срезов, модулей, `for`, `+=`, проверки
выхода за границы. Всё это появится по мере роста языка; см. [ROADMAP.md](ROADMAP.md).

## Раскрутка

```
bootstrap/khc0.asm --nasm--> khc0 --> khc1 --> khc2 --> khc3
```

`build.sh` собирает зерно ассемблером, зерно собирает `src/khc.kh`, дальше компилятор
дважды собирает сам себя. `khc2` и `khc3` обязаны совпасть побайтно. Сейчас совпадают
все три поколения: зерно и `khc` генерируют одинаковый код.

Когда `khc.kh` начнёт пользоваться возможностями, которых нет в Khrip-0, цепочка
удлинится: зерно соберёт замороженную версию компилятора на Khrip-0, а та — текущую.
Зерно при этом не меняется.
