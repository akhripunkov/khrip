# Khrip 0.13.0

`khc --version` — `khc 0.13.0`. Предыдущий выпуск — 0.12.0 (PostgreSQL). Ход работы
по шагам — [docs/design/v0.13-status.md](../design/v0.13-status.md), итоги и
планы — [ROADMAP.md](../ROADMAP.md).

## Что нового

- **Сборка мусора в `store`.** Заменённые и удалённые значения освобождаются;
  объекты не перемещаются. Разметка идёт в отдельном потоке кусками примерно по
  200 мкс, которые задерживают только пишущие запросы, читающие идут
  параллельно; уборка — тоже кусками; свободные страницы уходят системе. Запрос,
  который ждёт (`fetch`, `sql`, драйверы, `sleep`, хеш пароля), публикует свои
  ссылки на `store`, поэтому то, что он держит, остаётся целым. Настройки:
  `KHRIP_GC` (запас кучи, 50 %, `off` — без сборки), `KHRIP_GC_MIN_MB` (4),
  `KHRIP_GC_LIMIT_MB` (мягкий предел), `KHRIP_GC_LOG=1` (строка о каждой сборке;
  программу тоже собирают с ним). Проект —
  [v0.13-store-gc.md](../design/v0.13-store-gc.md).
- **Память вне `store`.** Тёплые арены (две на поток, остальные остывают до
  32 КБ), буферы соединения из запаса потока (молчащее соединение — 0,2 КБ),
  рост большого словаря по частям, компактное представление данных `store`
  (строка с заголовком 8 байт, компактные словари, заголовок списка 16 байт).
- **Строки UTF-8.** `len`, `s[i]`, срезы, `find`, `for c in s` и регулярные
  выражения считают символы; `lower`, `upper`, `trim` знают Юникод; `byte_len()`
  и байтовый API (`byte(i)`, `byte_slice`, `byte_find`, `ascii_lower`, ...) для
  байтов; `\u{e9}` в строках; строгий UTF-8 на входе и замена на U+FFFD на
  выходе; колонки в ошибках — по символам. Проект —
  [v0.13-utf8.md](../design/v0.13-utf8.md).
- **ClickHouse в языке**: `ch "..."` (как `sql`: тип результата — из ожидаемого
  типа, `{x}` — всегда параметр), `table t: T` и `t.insert(rows)` с кодированием по
  настоящим типам столбцов, `migration ch N`, именованные соединения `clickhouse
  ИМЯ = env(...)`, проверка каждой таблицы и запроса при запуске, `khc test` во
  временной базе. **MongoDB** — библиотечный драйвер: `Mongo`, `mongo_insert`,
  `mongo_find_with`, курсоры, `to_bson`/`from_bson`. Оба драйвера — свой протокол и
  TLS, без libc. Подробно — [DATABASES.md](../DATABASES.md).
- **Анонимные типы и литералы.** Тип `{ id: int, name: str }` пишется везде, где
  пишется тип; литерал `{ id: 1, name: "a" }` берёт тип, который там ждут, иначе —
  анонимный тип своих полей. Анонимные типы структурные; порядок полей — часть
  типа. `T { ...x }` делает из анонимного значения именованное.
- **Скилл для агентов** [skill/khrip/](../../skill/khrip/SKILL.md): ядро (3000
  токенов o200k) и главы `postgresql.md`, `mongodb.md`, `clickhouse.md`,
  `production.md` (до 900). Сжатая форма [KHRIP.md](../KHRIP.md), сверяется с
  компилятором тестами.
- **Скорость**: быстрые `lower()` и `x.lower().contains(y)` без копии ASCII-строки,
  вынос неизменных подвыражений из лямбд, слияние цепочек методов в один проход,
  больше маршрутов, которые компилятор признаёт читающими (`khc check --locks`);
  генерация кода khc (операнды без стека, свёртка констант, пересылка записи в
  чтение).
- **Компилятор**: предупреждения (`warning:`, в `--json` — `"severity"`), например
  анонимный тип, записанный трижды; подсказки к привычкам других языков: новые —
  к `x in xs`, `m.get(k, 0)`, `{x:.2f}`, `sum(xs)`, `xs.sort(cmp)`, точнее — к
  `if let` как значению и `int * float`; константы float; поля с именами `type`,
  `in`, `match`, `test`, `call`, а параметры и локальные — `type` и `test`;
  программа с типом `T`, `K` или `V` телом маршрута собирается (в 0.12
  сгенерированный разбор путал его с параметром обобщённой функции).

## Изменения поведения

Каждое изменение проверено на одной и той же программе компиляторами 0.12.0 и
0.13.0.

| Было в 0.12 | Стало в 0.13 |
|---|---|
| `{k: v}` без ожидаемого типа — словарь с ключом — значением `k` (с переменной типа str ключ получался неверным) | литерал без ожидаемого типа — анонимная структура; если `k` ещё и переменная int или str, а `v` её не упоминает, — ошибка с подсказкой `{(k): v}` или `{"k": v}` |
| — | порядок полей — часть анонимного типа: `{ a: int, b: int }` и `{ b: int, a: int }` не смешиваются, ошибка говорит про порядок |
| `=> { name }` в `match` — блок со значением `name` | ошибка: после `=>` `{ name }` читается как литерал структуры без скобок; значение — `=> name`, структура — `=> ({ name })` |
| `return 409 "busy"` при `\| 409` без типа: ответ 409, текст молча терялся | ошибка «status 409 has no body here», подсказка `\| 409 str` |
| в маршруте `-> int` без `\| 404` `return 404` отвечал 200 с телом `404`; `return x ?? 0` — ошибка «status 0 is not declared» | число 100–599 после `return` или `??` — статус: необъявленный — ошибка, `(404)` — число; `?? 0` — число |
| `T { ...old, ...patch }`: поле `T?` заплатки со значением `none` стирало старое | `none` заплатки пропускается всегда; стереть поле — явно: `note: patch.note`; распаковка того же типа копирует все поля |
| `type`, `in`, `match`, `test`, `call` — только ключевые слова | имена полей (кроме `type` у варианта); `type` и `test` — ключевые слова только в начале объявления верхнего уровня, иначе это имена: параметр `?type=`, локальная |
| тело `call` с типом писало поля `none` как `null` | поля `none` не отправляются; явное `поле: none` в теле — ошибка; `null` — телом-строкой; литерал без имени типа при пути-литерале получает тип тела маршрута |
| `const N = 2 + 3` молча давал 2; `const RATE = 1.5` — ошибка | константа — один литерал int, float, str или bool (и отрицательное число); выражение — ошибка с подсказкой написать функцию |
| `xs.slice(0, 2)`, `xs.sort_int()`, `n.to_f64_bits()` — внутренние функции библиотеки вызывались как методы | методы списков, int, float и bool — только описанные; остальное — ошибка (у списка — с перечнем его методов) |
| `[1, 2].join(",")` компилировалось и падало при запуске (SIGSEGV) | ошибка «.join() works on [str]», подсказка `xs.map(x => x.to_str()).join(", ")` |
| цепочка `xs.map(f).filter(g)...` — каждый метод по всему списку | цепочка поэлементная, если лямбды без побочных действий: `any`, `all`, `find` останавливаются на решающем элементе, паника — от первого по порядку элемента; `[1, 0].map(x => 6 / x).find(y => y == 6)` даёт 6, а не панику |
| `s.len()`, `s[i]`, срезы, `find`, `for c in s` — байты (`"мир".len()` — 6, `s[i]` — int) | символы (`"мир".len()` — 3, `s[i]` — str из одного символа); байты — `byte_len()`, `byte(i)`, `byte_slice(a, b)` |
| `'a'` — int (байт) | строка из одного символа, а где ждут int — код символа (`'я'` — 1103) |
| `fn trim(s: str)` молча проигрывала встроенному `s.trim()` | своя функция с именем метода str и первым параметром str — ошибка в объявлении |
| неправильный UTF-8 в JSON-теле и параметрах принимался | ответ 400 с причиной («invalid JSON body: name: invalid UTF-8») |
| `THREADS=5000` запускал 5000 потоков | не больше 4000: больше — отказ при запуске |

## Замеры

Метод v2 для памяти и задержек: одна и та же постоянная частота запросов для
всех языков (`wrk2 -R`), прогрев 60 с, замер 60 с, RSS каждые 100 мс.

- **Память** ([точка отсчёта](../../bench/results/2026-10-26-memory-baseline.md),
  [10 минут](../../bench/results/2026-10-26-memory-long.md),
  [часть 2](../../bench/results/2026-10-26-memory-part2.md),
  [часть 3](../../bench/results/2026-10-28-memory-part3.md)): patch под
  постоянными обновлениями — пик 4,3 МБ (0.12 — 232, Go — 14,5); пиковая память
  ниже Go во всех 13 сценариях eval (0,14–0,82 от Go); 10 минут при одинаковой
  частоте — 0,26–0,46 от Go; смена фазы — 0,62 от Go; живые данные на запись —
  0,76–1,26 от Go; молчащее соединение — 0,2 КБ (Go — 22).
- **Паузы сборщика** ([проект](../design/v0.13-store-gc.md), шаг 6b): при 134 МБ
  живого начало сборки — 4–6 мкс, самый долгий кусок разметки — 229–253 мкс
  процессора, конец разметки — 2–3 мкс.

  [часть 2](../../bench/results/2026-10-28-speed-part2.md)): catalog — 16 789

  запрос против 135,5; bookings — 14 257 против 8 924 (до этапа — 7 990), 114 мкс

  [Промежуточный замер](../../bench/results/2026-10-25-v0.13-interim.md) до этапов
  памяти и скорости: запросов в секунду больше, чем у Go, во всех 13 сценариях, и

- **Токены** ([часть 1](../../bench/results/2026-10-28-tokens-part1.md),

- **Строки**: `lower()` 180 байт кириллицы — 107 нс (было 913), 100 тыс.
  случайных `s[i]` по строке 1 МБ — 9,4 мс (было 20).

## Известные ограничения

- Сопрограммы не вытесняются: долгий обработчик, занятый процессором (большой
  JSON), держит остальные соединения своего потока.
- В маршруте без базы нельзя отличить поле, присланное как `null`, от не
  присланного (это умеет только `SET {patch}` в `sql`): JSON Merge Patch со
  стиранием через `null` в памяти не написать.
- `sql`: необязательное значение в `BETWEEN` и в аргументе функции молча ничего
  не находит; в сравнении и `LIKE` — ошибка компиляции (у `ch` — везде).
- Удаление большей части записей вразнобой оставляет страницы занятыми: сборщик
  без перемещения не возвращает спаны, где остались живые объекты (у Go — так же).
- Снимок KHRIP_DATA — JSON всего `store` под исключительной блокировкой.
- Цели скорости строк не взяты: случайный `s[i]` — 9,4 мс (цель 8), `len()` 20
  байт — 12 нс (цель 5–8), срез 16 байт — 35 нс (цель 15–25).
- Генерация кода: регистры для переменных циклов, лёгкие кадры и устойчивая
  раскладка кода — на будущее (раскладка двигает patch на ±4–5 %).
- Драйверы MongoDB и ClickHouse — первая реализация: одно прямое подключение к
  MongoDB (без SRV, сессий, транзакций и повторов), пароль SCRAM — печатный ASCII,
  TLS — только 1.3, без сжатия протокола; MongoDB-часть API в языке (коллекции,
  как `table`) — после 0.13.0. Полный перечень — [DATABASES.md](../DATABASES.md).
- Слепой проверки на моделях других поставщиков ещё нет: протокол готов
  (`eval/blind.py`), нужен доступ к их API.
- `url_encode` и `json_error` — из библиотеки API: в программе без маршрутов,
  тестов, `store`, `every`, `fetch`, баз и JSON их нет («unknown function»), и
  подсказка к `s.url_encode()` там предлагает такую же недоступную
  `url_encode(x)`.
- `bench/simd/simd.kh` не компилируется (давняя ошибка вызова `__arena_init`).

## Переход с 0.12

Пересоберите программы: `khc -o app app.kh`. На код, который компилятор теперь
не принимает, он укажет ошибкой (почти всегда — с подсказкой, как написать);
молча меняется только то, что ниже отмечено «тихо».

- **Строки (тихо).** `len()`, индексы, срезы и `find` теперь в символах. Где
  нужны байты (протоколы, размеры буферов), пишите `byte_len()`, `byte(i)`,
  `byte_slice(a, b)`, `byte_find(x)`. `s[i]` — строка: сравнения `s[i] == 'a'`
  работают как раньше, а арифметика `s[i] - '0'` — ошибка: `s[i].to_int() ?? 0`
  или `s.byte(i) - '0'`. `for c in s` даёт строки, а не числа.
- **Словари с ключом из переменной:** `{k: v}` → `{(k): v}`.
- **Блоки в `match`:** `=> { name }` → `=> name`.
- **Заплатки (тихо).** `T { ...old, ...patch }` больше не стирает поле, если в
  заплатке `none`; чтобы стереть, напишите поле явно: `note: patch.note`.
- **Статусы:** `return 409 "текст"` → объявите `| 409 str`; в маршруте `-> int`
  `return 404` для числа → `(404)`, для статуса → объявите `| 404`.
- **Константы:** выражение в `const` → литерал или функция.
- **Внутренние методы:** `xs.slice(a, b)` → `xs[a..b]`, `xs.sort_int()` →
  `xs.sort()`; `[1, 2].join(",")` → `xs.map(x => x.to_str()).join(",")`.
- **Тесты с `call` (тихо).** Поле `none` в типизированном теле больше не уходит
  как `null`, и маршрут берёт значение по умолчанию; явный `null` — телом-строкой:
  `` call PATCH "/x" `{"note": null}` ``.
- **Цепочки (тихо).** В цепочке чистых лямбд элементы проходят все методы по
  одному: если лямбда паникует на каком-то элементе, паника может прийти из другого
  места или не случиться вовсе (`find` остановился раньше).
- **Свои функции с именами методов str** (`fn trim(s: str)`, `fn find(s: str,
  ...)`) переименуйте.
- **`THREADS`** — не больше 4000.
- **KHRIP_DATA** от 0.12 загружается: неправильные байты и одинокие суррогаты
  в строках становятся U+FFFD, об этом — строка в журнале.
- **Память `store`** освобождается сама; если важнее процессор, чем память,
  увеличьте `KHRIP_GC` (100 — цель вдвое больше живого).
